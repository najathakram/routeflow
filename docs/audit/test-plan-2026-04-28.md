## 1. Scope

The user reports many broken or missing controls and wants to find **every** broken/wrongful button and every broken flow. This plan covers:

- **Operator** surfaces (`apps/mobile/app/(operator)/*`)
- **Driver** surfaces (`apps/mobile/app/(driver)/*`)
- Cross-role flows between them
- Numerical correctness (order totals, payments)
- Cross-cutting concerns (loading, errors, permissions, network, console)
- **Optional Phase 2:** Buyer portal (`apps/web/app/buyer/*` — different deployment, may be skipped this round)

**Out of scope (this plan):** native iOS/Android-only behaviors, performance benchmarks, security testing, accessibility audit beyond keyboard/screen-reader basics.

---

## 2. Test heuristics (apply on every screen)

For every screen we visit we sweep:

| Heuristic | What we check |
|---|---|
| **Inventory of controls** | List every visible button, link, menu item, swipe action, drag target. |
| **Primary action works** | Click each — does it trigger the expected mutation/navigation? |
| **Wrongful behavior** | Does the click do the right thing? Wrong endpoint, wrong state, wrong toast? |
| **Disabled vs enabled** | When should it be disabled (e.g. saving) — is it? |
| **Loading state** | Spinner shown? Button disabled mid-request? |
| **Optimistic UI** | Does UI update before server confirms? Does it rollback on failure? |
| **Error toast** | When mutation fails, is a user-readable error shown? |
| **Empty state** | List with 0 rows — is there a useful empty state? |
| **Refresh / pull-to-refresh** | Does state stay in sync after another actor changes data? |
| **Console errors** | Any JS errors / warnings / failed asset loads? |
| **Network errors** | Any 4xx/5xx — including silent ones (UI ignores). |
| **Validation** | Empty form submit, partial form, max-length, special chars (`'`, `"`, `<`, `&`), leading/trailing whitespace. |
| **Numeric inputs** | Try 0, negative, float, very large (1e9), non-numeric, paste-with-commas. |
| **Date inputs** | Past date, today, future, invalid date. |
| **Permission boundary** | Try operator-only action while in driver view; try driver-only action as operator. |
| **Refresh during edit** | Reload mid-edit — is data lost or restored? |
| **Multi-tab** | Open same record in two tabs, edit in tab A, save in tab B — is conflict handled? |
| **Back button** | Native browser back works, in-app back button works, both go to expected place. |
| **Deep linking** | Direct URL to detail page works without going through list first. |
| **Mobile widths** | Resize to ~390px width; layout still usable; no horizontal scroll on body. |

Every bug found is logged with: screen, control, steps, expected, actual, severity (S0–S3), screenshot, console line, network line.

## 9. Edge cases / variations to derive from each task

For every test we derive these branches as time allows:

- **Empty / null:** no items, no customer, no driver, no date.
- **Boundary numerics:** 0, 1, very-large, negative, decimals.
- **String edge cases:** unicode, RTL, emoji, very-long, leading/trailing whitespace, embedded newlines, embedded HTML.
- **Concurrency:** two tabs, two roles editing same record at once.
- **Stale data:** open detail page, modify elsewhere, refresh — does it pick up the change?
- **Slow network:** Throttle to 3G; verify no double-submit, no premature success toast.
- **Repeat-clicks:** mash the button while it's "loading" — only one network call?
- **Permissions abuse:** as driver, hit operator-only endpoints via URL — should 403.
- **Status illegal transitions:** force a transition that should be blocked — server rejects.
