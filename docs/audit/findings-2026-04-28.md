## Root Cause: `Alert.alert()` is a no-op on Expo Web

**Affects F-01, F-02, F-03, F-05, F-06, F-07.**

React Native's `Alert.alert()` is only supported on iOS/Android. On the Expo web build it is completely silent — no dialog appears, no callbacks fire. Approximately 36 operator screens and several driver screens wrap destructive or confirmable actions in `Alert.alert(...)` before calling the mutation. On web those buttons appear to do nothing.

**Fix pattern (apply uniformly across all 36 affected files):**

```tsx
// ❌ Broken on web
Alert.alert("Delete order?", "This permanently removes the order.", [
  { text: "Keep it", style: "cancel" },
  { text: "Delete", style: "destructive", onPress: () => deleteMut.mutate(order.id) },
]);

// ✅ Web-safe replacement
if (Platform.OS === "web") {
  if (window.confirm("Delete order? This permanently removes the order.")) {
    deleteMut.mutate(order.id);
  }
} else {
  Alert.alert("Delete order?", "...", [
    { text: "Keep it", style: "cancel" },
    { text: "Delete", style: "destructive", onPress: () => deleteMut.mutate(order.id) },
  ]);
}
```

Or introduce a thin `confirmAction(title, message, onConfirm)` helper that branches on `Platform.OS`.

**Known affected files (grep for `Alert.alert` in `(operator)` and `(driver)`):**

- `app/(operator)/(tabs)/orders/[id].tsx` — cancel, delete, back-to-pending, quick-deliver
- `app/(operator)/routes/[id].tsx` — delete stop, delete route
- `app/(operator)/invoices/[id].tsx` — void invoice
- `app/(operator)/vendor-bills/[id].tsx` — void vendor bill
- `app/(operator)/returns/index.tsx` — reject return
- `app/(driver)/route/stop/[stopId]/payment.tsx` — "Continue in Google Maps?" post-completion navigation
- 30+ additional operator screens (products, customers, vendors, purchase orders, expenses, settings, …)

### F-07 · S1 · Driver

**Driver stuck on payment screen after completing a stop**

**Reproduction:**

1. Log in as `ux_driver_a`. Open a stop, tap **Complete & collect →**.
2. On the payment screen, choose a payment method and amount.

### F-08 · S2 · Operator Finance — Vendor Bills

**New vendor bill form cannot be submitted via keyboard input**

**Reproduction:**

1. Navigate to Finance → Vendor Bills → **New**.
2. Type dates, description, and unit cost using the keyboard.
3. Tap **Create bill** → nothing happens (no API call, no navigation).

**Root cause:** React Native `TextInput` (rendered as `<input>` on web) uses `onChangeText` which maps to the native `input` event, not the standard `change` event. Keyboard input updates the DOM value but does not trigger the React state updater, so the component's `items` state array still has an empty description. On submit, the validation guard (`if (filtered.length === 0) { Alert.alert("Items required …"); return; }`) fires but the `Alert.alert` call is itself a no-op, leaving the form silently non-submittable.

**Workaround (user):** Select the supplier from the dropdown and use the supplier dropdown to trigger a state update, then try again. (Partial — same root cause applies to date and line-item fields.)

**Fix:** Ensure all `TextInput` onChangeText handlers are triggered correctly on web, OR use the standard React controlled-input pattern with `onChange` instead of `onChangeText` for web.

**File:** `apps/mobile/app/(operator)/vendor-bills/new.tsx`

### F-10 · S2 · Operator Finance — Vendor Bills

**Vendor bill line-item total always shows $0.00**

**Reproduction:**

1. Open any vendor bill (e.g. BILL-2026-0001 with "Fuel – April delivery run, 1 × $120.50").

**Fix (choose one):**

- Add a computed `lineTotal` to the API response DTO (`qty × unitCost`).
- Fix the mobile component to compute inline: `formatCurrency(Number(item.qty) * Number(item.unitCost))`.

**Files:**

- `apps/mobile/app/(operator)/vendor-bills/[id].tsx` (line ~139)

### F-15 · S1 · Cross-cutting (umbrella)

**`showToast()` falls through to `Alert.alert` on iOS/web → every success toast invisible**

**Reproduction:**

1. Trigger any successful save (e.g. customer add-address, settings save, catalog override save, driver POD save). Code path calls `showToast("Saved")`.
2. On Android the message appears as a Toast. On iOS native it shows an Alert. **On web, the Alert no-ops** → user sees nothing and cannot tell whether the save actually succeeded.

**Root cause:**

```ts
// apps/mobile/lib/toast.ts
if (Platform.OS === "android") { ToastAndroid.show(...) }
else { Alert.alert("", message, [{text:"OK"}], { cancelable: true }); }
```

On web `Platform.OS === "web"` → falls into the iOS branch → `Alert.alert` is a no-op (same root cause as F-01..F-07).

**Affected (~40 files):** every operator/driver/buyer mutation that calls `showToast(...)` on success, including but not limited to: customer add/edit/delete, address CRUD, catalog tier override CRUD, settings save, driver POD save, driver complete-stop, driver complete-route, vendor bill receive, returns approve/reject/cancel, invoice send, invoice record-payment, expense create/update, PO send/close/receive, route assign/edit/optimize, product create/update, supplier create/update, driver create/update, standing-order pause/resume/reorder.

**Fix:** Replace the iOS/web branch with a real toast component (e.g. an in-app `<Toast>` portal that auto-dismisses, or a no-op on web combined with an inline success banner per surface). Easiest: use `react-native-toast-message` or implement a lightweight `Toaster` in `lib/toast.ts`.

**File:** `apps/mobile/lib/toast.ts` (root cause), all `showToast(` callers

### F-18 · S2 · Operator — Purchase Orders

**"Items received 000 / 053" — string concatenation instead of summing qty integers**

**Reproduction:**

1. Create a PO with two line items: qty 5 and qty 3 (total ordered = 8).
2. Open PO detail. Header reads **"Items received 000 / 053"**.

**Expected:** `"0 / 8"` (received 0 of 8 total ordered).

**Actual:** Each integer is being padded/concatenated as a string:

- received: `"" + 0 + 0 = "00"` (two received-zeros), then prefixed with `"0"` → `"000"`
- total: `"" + 0 + 5 + 3 = "053"` (initial empty + each item's qty as string)

**Fix:** Use numeric `.reduce((s, i) => s + Number(i.qtyOrdered), 0)` for the denominator and `… i.qtyReceived` for the numerator. Likely an `acc + i.qty` where `acc` was initialized as `""` instead of `0`.

**File:** `apps/mobile/app/(operator)/purchase-orders/[id].tsx` (header progress display)

### F-30 · S1 · Driver — Signature (data integrity)

**Signature pad never captures pixel data — server-side proof-of-delivery is meaningless**

### F-35 · S1 · Buyer Portal — All screens (umbrella)

**Buyer portal crashes on load — Prisma Decimal fields serialized as strings**

**Reproduction:**

1. Log in as buyer2 (`ux_buyer2_1777265477001@ux-audit.test`). App navigates to `/orders`.
2. Page renders completely blank (white screen).
3. Console: `TypeError: (b ?? 0).toFixed is not a function`

**Root cause:** Prisma returns `Decimal` fields (unitPrice, qty, total, amountDue) as strings in JSON. **API verification:**

```json
// GET /buyer/orders → order.total = "51.91" (string), lineItem.qty = "4" (string), lineItem.unitPrice = "5.49" (string)
```

**Affected files (all fixed in this branch):**
| File | Crash site |
|------|-----------|
| `app/(customer)/(tabs)/orders.tsx` | `formatCurrency(total)`, `totalItems` accumulator |
| `app/(customer)/orders/[id].tsx` | `total.toFixed(2)`, `item.unitPrice.toFixed(2)`, `item.qty * item.unitPrice` |
| `app/(customer)/(tabs)/catalog.tsx` | `formatCurrency(cartTotal)`, `product.price.toFixed(2)`, `add({unitPrice: product.price})` |
| `app/(customer)/(tabs)/invoices.tsx` | `invoice.total.toFixed(2)`, `amountDue.toFixed(2)` |
| `app/(customer)/invoices/[id].tsx` | `invoice.total.toFixed(2)`, `amountDue.toFixed(2)`, `invoice.amountPaid.toFixed(2)` |

**Fix applied:** Wrap all numeric reads from API data in `Number(x)` before calling `.toFixed()` or arithmetic. For the cart `add()` call, cast `product.price` to `Number` before storing.
