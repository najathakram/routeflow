## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** The camera gate dedupes per-frame refires so one presented item adds once, whatever symbology the decoder picks each frame.

**Actually does.** The gate held ONE slot keyed on the raw last code. A carton carrying two genuinely different codes (an ITF-14 case code does not normalize to its inner EAN-13) flipped A&rarr;B&rarr;A across frames, resetting the slot on every flip — each frame counted as a new scan and the line quantity ran away.

**The gap.** Dedupe compared raw codes in a single slot; real cartons present as a SET of candidate codes and need per-code clocks.

**Evidence.** Evidence · apps/mobile/lib/scan-loop.ts (gateScan) — fixed shape: 4-slot LRU, slots match on intersecting normalizeScanCode candidate sets
