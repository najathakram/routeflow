# B858 · Product CSV import reads only name, price, description, unit and SKU — pack size, tier prices, barcode, category, cost and tobacco-flag columns are silently ignored

**Location** `apps/api/src/import/import.service.ts importProducts (~1660-1710) · settings/import 'Products (Items)' card` · **Severity** medium · **State** uncampaigned

## Summary

_Not yet analysed._

## What this feature is for

Bulk-load a new wholesaler's catalog (often 300-1,000+ SKUs) from their spreadsheet or old system so the workspace is sellable on day one. The onboarding playbook (docs/runbooks/wholesaler-onboarding.md) relies on it for stage 5.

## Root cause

_Not yet analysed._

## User impact

Every onboarding with a real catalog: pack sizes (unitsPerBox — drives boxed proration and case pricing), tier prices, barcodes (scanning), categories, costs (margins, AVCO) and tobacco flags (regulated reporting) must be keyed by hand per product, which turns a days-long load into weeks for a large catalog and invites typos in money fields. Route with the import-module work; likely fix = read the extra columns (and wire the dead JSON path or the migration page) with a preview.

_Not yet analysed._

## Test plan

_Not yet analysed._

## Reported evidence

Only Item Name/Name, Rate/Sales Rate/Price, Description, Unit/Usage Unit and SKU are read; unitsPerBox, priceTier2-5, barcode, category, standardCost/averageCost, isTobacco, msrp and reorder columns are dropped with no warning, and re-import matches by name and skips existing rows so it can't fill them later. A richer JSON path (POST /products/import: barcode, category, opening stock, averageCost) exists but its hook useImportProducts has no call site; the Move-to-RouteFlow page forwards only name/sku/price/unit/category. White-glove onboarding must hand-enter pack sizes and tiers per product.
