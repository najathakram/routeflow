## Root cause

Enabling a priced add-on twice creates two Stripe subscription items and keeps only one pointer

Symptom / evidence: Two overlapping enables both pass the read-then-act active check and both create a subscription item; the upsert keeps only the second id, so the orphan charge can never be disabled from the product.

Files implicated: apps/api/src/billing/addon.service.ts, apps/api/src/platform-admin/platform-admin.controller.ts.
