## Root cause

SA-113(i) follow-up (fleet lead + SA, 2026-09-23). Verified on #1274 head 130099aad1f55cac825614911fa21f488516c1c9: CreateInvoiceItemDto accepts @IsOptional() @IsUUID() orderItemId (create-invoice.dto.ts:28), but the web edit page's PATCH builder (items.map at :518, productId at :524) and mobile invoiceLineDto (invoice-totals.ts:137-160) never emit it. Every client edit therefore rebuilds lines with a null orderItemId: #1274's recompute falls back to product matching (safe — an ambiguous match skips and warns, so no wrong money), and the inline-return sourceOrderItemId provenance is dropped by the same rebuild. Fix: carry orderItemId from the loaded line through both editors' wire DTOs (web + mobile in one item); pin it with a spec per client. Lands AFTER #1274 merges. Owner: R-ui, after B790/B784/B788.
