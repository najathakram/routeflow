## Reported evidence

The pin classifies every file that reads a raw request path with READS = /\b(?:req|request)\??\.(?:originalUrl|url|path)\b|\boriginalUrl\b(?!\??\s*:)/. A new log or audit sink that does const http = ctx.switchToHttp().getRequest() and reads http.url or http.path (or any other identifier name) is not flagged, so a route carrying a token in its path could be written raw. Review-b mutant M15 on #4231 at de46d6af5d survived (14 of 15 mutants caught); shipped in 5f84cd0789. Today every reader is inventoried. Fix: in the pin, also match .url and .path on any identifier assigned from getRequest( in the same file (a small AST pass, or the regex const (\w+)[^=]*=\s*[^;]*getRequest\( followed by \b\1\??\.(?:url|path)\b), with a self-test fixture that uses another name. Cf. L-364 (a static pin reads every shape the repo writes). Source: #4231 review-b note 1, bookkeeping 2026-11-07.
