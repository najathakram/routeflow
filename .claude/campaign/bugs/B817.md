## Root cause

Verified at #1318's head 59623d67 (2026-09-23); from #1318's Opus review (PASS WITH NOTES; old code). The 'worktree' step (step 2) runs trySh('git', ['-C', repoRoot, 'worktree', 'remove', '--force', a.target]) and only THEN safeRemoveTree(a.target) as a 'Windows file-lock leftover' cleanup. git worktree remove --force deletes recursively and follows node_modules junctions/symlinks into their targets, which is exactly how 2026-09-21's wipe happened (L-180). The header (:30-38) and runbook (:76-79) claim the junction-safe unlink runs first. Fix: unlink junctions and symlinks (the safe path) BEFORE any git worktree remove, then git worktree remove, then prune; pin it with a fixture worktree whose node_modules links outside it. Owner: MacBook landing, stacked with B815/B816 after #1318 (its new containment guard may already cover parts; it verifies).
