## Reported evidence

Hit live on B420: a T1 row was correctly proven, but its proof cited evidence in a shape campaign-check.mjs cannot verify (a standalone node self-test run by npm run verify, never a jest suite -- tier T1's discharge path scans jest report titles only). The correct target state is already-fixed (its EVIDENCE_ONLY_STATES path in campaign-check.mjs checks only that evidence is non-empty, matching this evidence's real shape), but no command reaches it from proven: already-fixed refuses any state other than queued/in-flight, and the only command that clears a proven row's proof (reopen) forces state to regressed and REQUIRES citing an actual failing REG-token or regression run -- writing that citation for a bug that did NOT regress (it is correctly fixed, just mistiered) would be a fabricated claim. Fixed this one instance via a direct, lock-checked, single-field edit to its ledger row (owner-approved, out of band) -- a manual escape hatch that should not need repeating. Fix: add a lawful transition (e.g. a 'reclassify <B###> already-fixed --pr <n> --why <text>' command, or extend already-fixed to accept a proven row when explicitly told the tier/evidence-shape was wrong, distinct from reopen's regression semantics) so this never again requires a direct ledger edit.
