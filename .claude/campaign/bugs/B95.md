## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** A tenant admin opens a dedicated org-level dashboard (Today/Dispatch/Billing/Settings/More) distinct from the operator warehouse-dispatch UI.

**Actually does.** ActiveRole is typed as "driver" | "operator" | null with no third value; defaultRoleForUser folds TENANT_ADMIN into "operator"; every setActiveRole call site passes only driver or operator (the role picker offers only those two cards, and its own comment says it has no in-app entry point); the root layout redirects any operator-role session to /(operator)/home whenever the segment isn't (operator), with no (tenant) branch — so even manual navigation bounces back.

**The gap.** A fully built, hook-backed tenant-admin dashboard sits in the tree, unreachable by any state, control or redirect, for any role including TENANT_ADMIN.

**Evidence.** Evidence · apps/mobile/lib/auth-store.ts:14, :34-39; apps/mobile/app/_layout.tsx:167-173 (no (tenant) case in the role-routing effect); apps/mobile/app/(auth)/role-picker.tsx:13-16, :78-127; setActiveRole call sites more.tsx:283, home.tsx:491/541, driver-menu.tsx:73, role-picker.tsx:27/43/47; apps/mobile/app/(tenant)/today.tsx (516 lines) and (tenant)/_layout.tsx (69 lines); .claude/code-map/mobile.md:228-230 documents it as an intended area.

**Suggested fix (register).** Either wire a real entry point (extend ActiveRole with "tenant", route TENANT_ADMIN there by default or via the role picker, add a (tenant) branch to the root redirect) or delete the tree if it's superseded.

> suggested fix for every one of the four bugs while confirming every diagnosis.
