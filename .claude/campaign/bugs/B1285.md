## Reported evidence

Dark-phase observability gap, read from the code at 266095419c, not run. record() lets one stack capture through per kind|model|op key per second (CAPTURE_GAP_MS), then dedupes the log per call-site fingerprint. A hot call site that hits a key more often than once a second wins the capture slot almost every second, so a different, rarer call site with the same kind, model and op is rarely or never logged: the counter is true, but the log that PR-2 is meant to read its conversion list from shows only the loud site. Also: the capture itself (new Error().stack with stackTraceLimit 40) runs before the per-site dedupe, once per key per second, so a hot path that alternates many models pays it per model per second. Fix direction: gate the capture per call site (a cheap site key) instead of per key, or capture a short stack and dedupe on it, and add a spec with two sites under one key. Matters before the 72-hour dark review. Found in review of #4225 (lead's note).
