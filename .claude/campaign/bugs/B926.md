## Reported evidence

With no tenant context (anonymous route, cron, lost ALS, or SUPER_ADMIN where null means both) forTenant() returns the UNSCOPED client, so a tenant-owned query reads across tenants. Proven harm: #2872 staff-email recipients would include every tenant admins. Security, cross-tenant read. Fix is fail-closed: add a context kind (TENANT, SUPER_ADMIN, ANONYMOUS, SYSTEM); forTenant() throws on ANONYMOUS or no context and on a SUPER_ADMIN tenant-owned create with no tenantId; add an explicit forSystem(reason) door with an allow-list spec. Roll out DARK (warn TENANT_CONTEXT_MISSING with a stack) for 7 days, then enforce in a separate diff. Source: SA-619 (#2554 5919576056), full plan and caller audit there.
