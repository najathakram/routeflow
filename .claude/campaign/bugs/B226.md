## Reported evidence

F12 (PR #652) added OptimizeResult.windowViolations/startTime on the API and wired both web dispatch modals to warn + require acknowledge before a late-stop dispatch; mobile's optimize callers (apps/mobile/lib/api/routes.ts useOptimize*, apps/mobile/app/(driver)/route/index.tsx, apps/mobile/app/(operator)/trips/new.tsx, apps/mobile/app/(operator)/routes/[id].tsx, apps/mobile/app/(operator)/route-runs/[id].tsx) call the same optimize endpoints but never read windowViolations or render a late-stop warning, so a driver can dispatch a known-infeasible route from the app with no signal at all.
