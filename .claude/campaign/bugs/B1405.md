# B1405 · The old invoice importer accepts a QuickBooks-shaped sales file and would post every historical invoice as an open (SENT) balance

**Location** `apps/api/src/import/import.service.ts (importInvoices, :1244 onward; endpoint import.controller.ts:54)` · **Severity** high · **Batch** F65 · **State** queued

## Summary

_Not yet analysed._

## What this feature is for

_Not yet analysed._

## Root cause

importInvoices has no header check that proves the file is the Zoho shape.

## User impact

_Not yet analysed._

## Fix approach and UX

Cheapest guard: importInvoices refuses a file with neither 'Invoice Status' nor a balance column, with a message pointing to Settings > Move to RouteFlow (the SA-1295 import); a header check before any write. The SA-1295 module is the real path; this closes the wrong door.

## Test plan

T1 red first on a synthetic QuickBooks-shaped CSV (acme placeholders): today N invoices import as SENT; after the fix 400 with 0 writes. A Zoho-shaped file still imports unchanged.

## Reported evidence

Observed by code read, not executed: a QuickBooks Desktop sales-detail file shares the Zoho importer's column names but has no 'Invoice Status' and no 'Balance Due' column. mapInvoiceStatus(undefined) returns SENT (:349), so years of paid history would land as open receivables and overdue invoices. The line amount falls back to qty x price (:1521), a blank quantity becomes 1 (:1515), the customer matches by businessName contains (:1355), and a source number equal to an existing invoice number updates that invoice (:1593-1621).
