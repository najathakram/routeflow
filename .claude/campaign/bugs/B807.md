## Root cause

Fleet lead relay, 2026-09-23. Verified on origin/master f9556ed2. email.service.ts has escapeHtml (:198) and uses it in the shared shell (:264, :299, :303, :319), but the invoice/reminder HTML body interpolates raw: ${it.description} (:1525, the line item cell), 'Dear ${params.customerName},' (:1618), ${params.invoiceNumber} (:1627), and ${params.paymentTermsLabel} (:1641). Any tenant-entered text containing markup (a product or line description, a customer name) renders as HTML in the buyer's mail client: HTML injection (links, forms, hidden content) under the seller's name. SIBLING SWEEP (the same file): the account-merge emails interpolate ${params.primaryEmail} and ${params.secondaryEmail} raw (:1746, :1819, :1845). These are validated email addresses, so the risk is lower, but escape them for uniformity. Dates (:1560 dueDate, :1631 issueDate) are server-formatted. :297 params.headerHtml is intentionally HTML (built from escaped parts at :264). SAFE: the plaintext bodies (:1682-1702, :2080) and the subject (:1077-1078) aren't HTML. The PDF templates (invoice-pdf-template.tsx, statement-pdf-template.tsx) use @react-pdf/renderer <Text>, not HTML, so there's no injection there. Fix: escapeHtml at every tenant or user-text interpolation in the HTML templates, with an XSS pin per field (e.g. a '<img src=x onerror=…>' description renders escaped), plus ideally a repo-truth guard that no raw ${params.*} or ${it.*} appears inside an HTML template literal without escapeHtml or an explicit allow-list. Owner: R-ui (it owns #1280/#1275 in this file), right after #1275.
