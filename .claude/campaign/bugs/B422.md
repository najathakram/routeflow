## Reported evidence

Seen on the F27 stack gate: npm run local:e2e exited 0 while Playwright itself reported 7 failed / 4 skipped / 14 passed for the run. local-env.mjs's own spawnSync call does 'process.exit(res.status ?? 1)', which should propagate the child's real exit status -- the exact masking point within the npm --prefix / nested npm run / playwright chain needs confirming by whoever fixes this, since the wrapper's own exit-forwarding line reads correct in isolation. Third wrapper-exit-code incident in this session's lane (same class as L-103 'a piped/wrapped gate command can discard its real exit code' and the SKIP_VERIFY wrapper trap). Fix: propagate the child's real exit status end-to-end through the whole chain; add a self-test that a deliberately-failing project still turns the wrapper's own exit code non-zero.
