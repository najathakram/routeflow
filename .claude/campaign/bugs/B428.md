## Reported evidence

Observed repeatedly this session (self-referential commit backfill lines appearing on B388.md/B389.md/B420.md/B426.md after running node scripts/campaign/bugs.mjs self-test / the verify chain, before any commit) and again on routeflow-33's push of #743 at ~06:25Z. Same class as B420: a fixture/self-test process writing into the REAL repo state instead of a properly isolated scratch copy. Unlike B420's GIT_DIR leak (a full repo hijack), this specific instance is bugs.mjs's own sync-on-verify step touching real .md files as a side effect of its own commit-scan -- appears to be sync's intended behavior (Gate 4 of stop.mjs runs sync every turn) rather than a leak, but the pre-push verify chain running it mid-verify, before commit, means a push can pick up working-tree changes nobody explicitly authored in that turn. Needs investigation: is this sync's documented idempotent behavior working as intended, or a self-test fixture writing outside its scratch dir the way B420's stamp self-test did.
