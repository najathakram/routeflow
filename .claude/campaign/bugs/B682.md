## Reported evidence

buildLine, computeLineSubtotalStrict and AmbiguousLineError in packages/pricing exist specifically to refuse the shape "unitsPerBox > 1 with neither boxes nor pieces given" (the B644 shape). A repo-wide search across apps/api, apps/web and apps/mobile returns zero callers for any of them (confirmed via grep on 2026-09-22); build-line.ts's own doc comment concedes no API caller exists yet. Every real call site uses the lenient computeLineSubtotal, which has no ambiguity check and silently falls back to unitPrice * qty. The only live guard on this shape is regulatedUnitBasis, which only emits a logger.warn and only fires on the regulated-ledger path at write time. This is the root shape behind B644, B645, B655, B659, B661, B671 and B681 -- it is resolved by a different convention at each call site with nothing refusing it. Wiring the strict guard everywhere is the structural fix for the whole family; regulatedUnitBasis's own comment already anticipates being turned from a warn into a throw once buildLine is wired everywhere. Fast-follow, not release-blocking -- filed per the fleet lead's request during Release 1.
