# B349 · Google OAuth link state is unsigned, so anyone can attach their Google identity to any user account

**Location** `Auth · API /auth/google (+/link) and the unguarded callback, platform twin included` · **Severity** critical · **Batch** F47 · **State** proven

## Summary

Google OAuth link state is unsigned, so anyone can attach their Google identity to any user account

## What this feature is for

Context: Auth · API /auth/google (+/link) and the unguarded callback, platform twin included. This is part of the F47 batch ("Google OAuth link state is unsigned, so anyone can attach th…") — see the batch theme in the hunt digest for the surrounding feature's purpose.

## Root cause

Google OAuth link state is unsigned, so anyone can attach their Google identity to any user account

Symptom / evidence: An unauthenticated caller mints a valid nonce, rewrites linkUserId in the base64 state, completes consent with their own Google account, and then signs in as that user — cross-tenant and SUPER_ADMIN capable for any never-linked account.

Files implicated: apps/api/src/auth/google-oauth.service.ts, apps/api/src/auth/auth.controller.ts, apps/api/src/auth/platform-google-auth.controller.ts.

## User impact

Severity: critical. Critical — money, tenancy or security correctness is silently wrong; no user-visible error signals the defect.

Symptom: An unauthenticated caller mints a valid nonce, rewrites linkUserId in the base64 state, completes consent with their own Google account, and then signs in as that user — cross-tenant and SUPER_ADMIN capable for any never-linked account.

## Fix approach and UX

Owner ruling 2026-09-12: sign the OAuth link state with a key HKDF-derived from JWT_SECRET (same isolation pattern as STORAGE_URL_SIGNING_SECRET); no new secret. Design may start.

## Test plan

Tier T1. Test name: REG-B349 an OAuth callback whose state was tampered with is rejected, and linkUserId is bound to the nonce issued for it
