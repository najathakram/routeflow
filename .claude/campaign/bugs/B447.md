# B447 · plane-doctor T2-doctor/T-concurrent-writer self-test intermittently doesn't see appendRun's runs.jsonl line land, worse under host load

The backfill lane ran scripts/campaign/plane-learning.self-test.mjs's T2-doctor/T-concurrent-writer cases in 3 isolated runs and saw 1 fail: appendRun's runs.jsonl line was missing after plane-doctor.mjs --offline exited, worse under host load. ## Root cause

Relayed as 'unawaited async write racing process exit in plane-doctor.mjs' -- verified against master 9508a748 and that mechanism does not exist: appendRun() (plane-client.mjs:299) is a plain synchronous function using appendFileSync, not async. plane-doctor.mjs's main() IS called unawaited at EOF (if (import.meta.url === ...) { main(); }), but with no process.exit() call anywhere in the file, Node's implicit exit waits for the event loop to empty (including this call's own pending work), and the synchronous appendFileSync inside the finally block completes before that promise settles regardless. The self-test (plane-learning.self-test.mjs T2-doctor/T-concurrent-writer) spawns plane-doctor.mjs as a CHILD PROCESS via async spawn() and awaits its exit/close event before reading runs.jsonl -- if there's a real race, it more plausibly sits at the OS/filesystem level (the child's exit event firing before its write is visible to the parent's read under host I/O contention) rather than an unawaited-promise bug inside plane-doctor.mjs itself. Evidence for the SYMPTOM stands (backfill lane: 1 fail in 3 isolated runs; owner-authorized audited SKIP_VERIFY on #769) -- only the suspected mechanism is corrected here.
