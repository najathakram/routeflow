## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** When a mutation fails the user sees why, so they can fix the input or decide whether to retry — on every platform the app ships to.

**Actually does.** toast.ts handles Android and web; the iOS path is an empty fallthrough. 380 showToast calls across 99 files are the sole failure feedback, and no inline error component exists in the mobile app at all.

**The gap.** On iOS a failed mutation is visually identical to a tap that never registered — the spinner clears and nothing else changes.

**Evidence.** Evidence · apps/mobile/lib/toast.ts:4,6,34 (android and web branches only; the iOS line is a comment saying to use in-screen feedback instead); apps/mobile/app/(driver)/route/stop/[stopId]/payment.tsx:299-303 (catch → setClosing(false) + showToast and nothing else), :323, :329-335 (success DOES fire a native Alert for the maps hand-off, so success is visible on iOS while failure is not); counts run during verification: grep -rn "showToast(" apps/mobile excluding lib/toast.ts = 380 hits across 99 files, and grep -rln "InlineError" apps/mobile packages/ui/src/mobile = zero files; apps/mobile/app.json:16-17 confirms iOS is a real build target.

**Suggested fix (register).** Replace the iOS no-op with a real in-app toast/banner host rendered in the root layout, reusing the existing showToast signature so all 380 call sites become visible; separately add an inline error row to the driver payment, adjust and return screens.

> ⚠️ Treat this as a hypothesis, not a plan. On F11 the adversarial pass refuted the
> suggested fix for every one of the four bugs while confirming every diagnosis.

**Verifier's note.** Half of the original claim was refuted and is excluded: the idempotency-key argument is wrong and was already cleared in this register — the per-attempt key is deliberate (it is copied into the offline queue's replay headers so a replay dedupes while a fresh tap is a genuinely new attempt), and the server rejects a second completion before idempotency matters. Corrections in the claim's favour: the call-site count is 380 across 99 files, and the alternative the toast module's own comment prescribes ("in-screen feedback") does not exist anywhere in the mobile app.
