# B800 · janitor treats a freshly created branch (tip == origin/master, zero commits) as merged and would remove an actively used lane worktree

**Location** `scripts/janitor.mjs:83-89 (verdict), :205-212 (isMerged via merge-base --is-ancestor)` · **Severity** low · **State** uncampaigned

## Summary

Registry reconcile 2026-09-24 (Mac Lead, owner ask via the fleet lead): verified FIXED on origin/master by #1318. fix(tooling): a fresh zero-commit branch is not "merged" (B800) (#1318) — edits scripts/janitor.mjs plus a new self-test case matching the bug's fix approach.

## Root cause

Found by the Mac Lead, 2026-09-23 (a report-only run, nothing applied). Verified on origin/master 5ae97db7. isMerged proves 'merged' with git merge-base --is-ancestor <tip> origin/master (:205-212). A branch that a lane JUST created off origin/master (no commits yet) passes that test trivially. Live case: R-ui had moved worktree rf-lane-R-ui-b653 onto the new fix/b795-adjust-double-add-item at 5ae97db7, minutes old, clean, and janitor planned '[1] clear node_modules' plus '[2] remove whole worktree … (merged, clean, pushed)' for it. janitor:apply would have deleted an active lane's worktree mid-task (recoverable only because it had no commits yet; any uncommitted edits would be lost). Fix: treat 'merged' as requiring EVIDENCE of a landing, not mere ancestry. Exclude a branch whose tip EQUALS origin/master (or any master ancestor that has no own commits and no upstream), and/or require the branch's reflog to show a commit that later became an ancestor; plus a janitor.self-test case for a zero-commit fresh branch. Workaround until fixed: run janitor report-only, and never --apply while lanes are active without reading the plan.
