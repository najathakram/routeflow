# B827 · reopenStop after an on-account close resets deliveredQty and sets the order CONFIRMED but doesn't rebuild the DRAFT, which stays at the delivered basis, so a later send or re-delivery under-bills

## Root cause

Fleet lead relay, 2026-09-23 (LOW-MED, money; filed MED). Verified on origin/master ef9183c6: reopenStop (:2939) resets each line to status PENDING with deliveredQty 0 and sets the order CONFIRMED, but makes NO reconcileOrderDraftInvoice call, so the order's DRAFT invoice stays at the DELIVERED basis from the on-account close (e.g. 7 of 10 delivered, invoicedQty 7). If the office then SENDS that draft, or the order is fully delivered on another run, reconcileDeliveredOrdersInTx finds a SENT invoice (it pays it, never restating it) and 3 units are under-billed. Fix: reopen rebuilds the DRAFT on basis 'order' inside the same transaction, so the draft returns to the ordered quantity. Red-first DB pin: close on-account at 7/10 → reopen → the draft is at 10; send → invoiced 10. Owner: Lane F (PC), folded into B785.
