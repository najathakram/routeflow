## Root cause

Verified at #1320's head 927d514e (2026-09-23), fleet lead relay. The Google OAuth callback base is `${this.webUrl}/auth/google/callback` for every browser (non-native) flow; only profile.mobile / GOOGLE_MOBILE_SCHEME (routeflow://) goes elsewhere. Before #1320, www proxied phone user agents to the Expo mobile-web build, so a driver's browser sign-in from the Expo web app returned through www and was proxied back into Expo's own callback. After #1320, www serves the Next callback page (callback/page.tsx:79 POSTs /auth/google/exchange, consuming the one-time code) and lands the driver on the WEB dashboard, whose DRIVER banner points back to the driver app → a loop. Password login is unaffected. Fix: carry the INITIATING origin as an allow-listed returnTo (www or the mobile-web origin from config) in the OAuth state, and have the callback redirect to that origin's /auth/google/callback. Update the stale comments at apps/mobile/lib/auth.ts:193 and apps/mobile/app/(auth)/auth/google/callback.tsx:12. Red-first pin on the redirect target for both origins and a rejected non-allow-listed returnTo. Owner: the unit-picker lane, alongside phase 1a. (The lead proposed this as B824; that id was already used for the publish-and-repin flake, so it's B825.)
