# B816 · janitor run from inside a worktree treats the real main checkout as an ordinary worktree (mainCheckoutPath = --show-toplevel of the cwd)

**Location** `scripts/janitor.mjs:377-398 (repoRoot = rev-parse --show-toplevel; buildPlan(repoRoot, repoRoot, …)), :252 (isMainCheckout)` · **Severity** low · **State** uncampaigned

## Summary

Registry flip 2026-09-24 (Mac Lead, fleet-lead list, verified against the merged PR bodies): FIXED by #1326. PR body: janitor takes the main checkout from `git worktree list`.

_Not yet analysed._

## Root cause

From the #1318 (B800) review, fleet lead relay 2026-09-23. Verified on origin/master 361e46eb (2026-09-23). repoRoot = git rev-parse --show-toplevel ?? cwd (:377), then buildPlan(repoRoot, repoRoot, worktreesRoot) (:398) passes the SAME path as mainCheckoutPath, and isMainCheckout = resolve(wt.path) === resolve(mainCheckoutPath) (:252). Run from inside a worktree, --show-toplevel is that WORKTREE, so the real main checkout is classified as an ordinary worktree (eligible for node_modules clearing or removal if it looks merged). Fix: derive the main checkout from 'git rev-parse --git-common-dir' (its parent) or the first 'git worktree list --porcelain' entry, with a pin run from a worktree cwd. Owner: MacBook landing, stacked after #1318.
