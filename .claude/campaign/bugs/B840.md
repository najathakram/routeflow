## Root cause

Found 2026-09-24 during the registry reconcile (Mac Lead). `note <B###> "<text>" --section <S>` overwrites section S's whole body. Two reconciles (2026-09-22, 2026-09-24) and about 32 earlier analysis notes silently replaced Summary, Root cause and Fix-approach text across about 150 records. Caught only because a note run's diff had insertions == deletions; repaired from git history on the registry branch (686adee6, 0 paragraphs lost across every historical version). A verb named 'note' reads as append, so the replace is a silent-loss class. Fix (fleet lead ruling): note appends to the section (placeholder '_Not yet analysed._' replaced), and a deliberate overwrite requires --replace. Pin in the bugs self-test: a note on a non-empty section keeps the old text, and without --replace the section only grows. Lesson written (the silent-loss class of append-named verbs).
