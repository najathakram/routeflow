## Reported evidence

A fresh subscribe() to a plan key that is not in the published catalog (a catalog-publishing error, not a client bug) falls through planKeyToEnum's else branch and writes Tenant.plan / TenantSubscription.currentPlan as STARTER -- silently misrepresenting the tenant's plan on every screen that reads the enum shadow -- instead of refusing the write. planChangePreview's ACTIVE-tenant path and downgrade() already refuse an unranked/off-catalog key; the fresh-subscribe path does not (F18 sibling-sweep finding, not fixed).
