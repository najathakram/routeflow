# B277 · Estimate create() has no P2002-to-409 catch on the number mint - a collision with an imported number surfaces as a 500

**Location** `Finance - estimates (create mint)` · **Severity** low · **Batch** F31 · **State** refuted

## Summary

Refuted as filed. estimates.service.ts:139 is the only writer of estimateNumber anywhere in the repo (no importer, no seed, no backfill), and the mint is already monotonic and collision-guarded, so the stated collision-with-an-imported-number trigger cannot occur.

## What this feature is for

Estimate create() mints the customer-visible estimate number via the already-guarded NumberingService path.

## Root cause

None reachable - kept only because create() has no P2002-to-409 catch around the estimate.create write, unlike the four equivalent invoice sites and convertToInvoice in the same file, which do.

## User impact

None observed or reproducible. Landed as a zero-risk defense-in-depth consistency fix matching sibling sites, not a repro.

## Fix approach and UX

refuted as a repro (single monotonic writer); kept as a P2002-to-409 pin (no REG token) - landed with #678

## Test plan

Unit-only pin in estimates.service.spec.ts, mirroring the file's existing P2002-mock shape: prisma.estimate.create rejected with code P2002 expects ConflictException, not the raw error. No REG token - not a live repro.

## Reported evidence

F16b/B100 cause refutation + engine final pass, 2026-09-08: nextEstNumber (estimates.service.ts:15-24) is the same findFirst+orderBy-desc+parseInt generator B100 diagnosed (siblings verified in B100's own evidence: "estimates.service.ts:16-25 tenant-scoped but same pad-4 string-sort wall"). Unlike invoices.service.ts's create path, which B100's evidence explicitly notes has a P2002-to-409 "please retry" catch (:2700-2701), create() here (estimates.service.ts:26 onward) has no equivalent try/catch around the estimate.create write: a collision - most plausibly an imported estimate number, since imported documents keep their original numbers per numbering.service.ts's own doc comment - throws Prisma's raw unique-constraint P2002 straight out of the handler as an unhandled 500 instead of the same 409-retry UX invoices already get.
