## Root cause

Ruled by SA-102 (2026-09-23, from its #1292/B663 read); verified on origin/master 2ed80789: the controller still exposes @Post(':id/stops/:stopId/complete') → completeStop (routes.controller.ts:186-189; service :2227). Inside its transaction it records the mutations and then tx.order.updateMany({ data: { status: DELIVERED } }) (~:2344) — no deliveredQty stamp and no delivered-basis reconcile, unlike completeWithPayment after #1292. No web or mobile caller found today (git grep), but the endpoint is live, so any client/script/API user closing a stop this way bills the FULL ordered qty for a short or refused delivery — the same money shape B663 fixes on the payment path — and also skips deliveredAt (see B778). FIX (SA-102): either route completeStop through the same single reconcile step after stamping deliveredQty (inside the completion transaction), or refuse/retire the endpoint. Units-gate adjacent: B663's reconcile must be the ONLY close path.
