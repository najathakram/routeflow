## Reported evidence

Verified against master 97fdb372: shareCsv() (line 464) destructures only { uri } from FileSystem.downloadAsync(url, target), discarding status entirely. The sibling call site at line 244-245 (sharePdf, fixed by #756) destructures { uri, status } and checks isDownloadOk(status) immediately after, failing loudly on a non-2xx download. shareCsv silently proceeds to share/write a failed download's response body (an error page, an empty file) as if it were the real CSV. Fix: apply the same isDownloadOk(status) check to shareCsv's downloadAsync call that sharePdf already has.
