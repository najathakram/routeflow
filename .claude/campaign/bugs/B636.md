## Reported evidence

raisePoBlocker is unit-tested (apps/web/lib/raise-po.test.ts) but the composition in the ScanInvoiceModal submit — raisesPo = inv.raisePo && !raisePoBlocker(inv.supplierId, billItems), sent as createPurchaseOrder: raisesPo ? true : undefined — has no test. That composition is the exact 'switch ON with an unmatched line is IGNORED, not refused' behaviour that stops a bill silently claiming a PO was raised. Fix: extract shouldRaisePo(inv, billItems) into apps/web/lib/raise-po.ts beside raisePoBlocker, call it at the submit site, and add four jest cases: ON + unmatched line -> false; ON + no supplier -> false; ON + all matched -> true; OFF -> false. Owner: U-po lane; test-coverage; priority medium; follow-up PR after #1045 lands (a head change would void Mac Train A).
