# B1387 · Three read-only cells print the piece count beside a box price (36 x $18.00 for 3 boxes)

**Location** `apps/mobile/app/(operator)/estimates/[id].tsx; apps/web/app/(dashboard)/estimates/[id]/page.tsx; apps/web/app/buyer/portal/[seller]/orders/[id]/page.tsx` · **Severity** medium · **Batch** F65 · **State** already-fixed

_Not yet analysed._

## What this feature is for

## Root cause

Three screens built their own qty text instead of the shared invoiceLineQtyText; the buyer Delivered and Remaining cells counted pieces because deliveredQty is written against qty.

## User impact

_Not yet analysed._

## Fix approach and UX

SA-1286: route the cells through invoiceLineQtyText (estimateLineQtyPriceText on mobile, splitProgressText on the buyer page, re-denominated at the line's own stored pack), plus a count-pinned, shrink-only no-raw-qty-beside-price.pin.spec.ts. Labels only. Fixed by #4514.

## Test plan

T2. estimate-line-qty-price.test.ts, page.qty-cell.test.tsx, page.qty-cells.test.tsx, no-raw-qty-beside-price.pin.spec.ts; red by run against the base page in the R-166 follow-up.

## Reported evidence

A boxed line stores qty in pieces and unitPrice as the box price. The mobile staff estimate printed '36 x $18.00', the web staff estimate Qty cell printed '36', and the web buyer order read view printed Qty '36' with Delivered '12' and Remaining '24'. Every total was already right ($54.00 for 3 boxes at $18.00).
