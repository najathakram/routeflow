# B314 · Revert to Draft is blocked by VOID (bounced) payments because the guard counts every InvoicePayment row

**Location** `Invoices · API revertInvoiceToDraft + revertLinkedInvoicesForOrderEdit (web Revert to Draft, order edit)` · **Severity** medium · **Batch** F39 · **State** proven

## Summary

Revert to Draft is blocked by VOID (bounced) payments because the guard counts every InvoicePayment row

## What this feature is for

Context: Invoices · API revertInvoiceToDraft + revertLinkedInvoicesForOrderEdit (web Revert to Draft, order edit). This is part of the F39 batch ("Revert to Draft is blocked by VOID (bounced) payments becaus…") — see the batch theme in the hunt digest for the surrounding feature's purpose.

## Root cause

Revert to Draft is blocked by VOID (bounced) payments because the guard counts every InvoicePayment row

Symptom / evidence: An invoice whose only payment bounced is refused with "this invoice has payments recorded. Void it instead.", and the same count blocks editing its source order.

Files implicated: apps/api/src/invoices/invoices.service.ts, apps/api/src/invoices/payment-predicates.ts.
