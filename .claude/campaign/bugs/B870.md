## Reported evidence

checkIdempotencyKey() returns Promise<unknown>, and both methods do 'if (cached) return cached;'. The truthy-narrowed unknown is {}, which widens each method's inferred return type to {}, so every caller loses the typed response. routes.service.spec.ts:2000 reads response.paymentIds and fails to type-check (TS2339 'paymentIds' does not exist on type {}); it is the one error left in #1315's check-types.spec baseline for that file. Runtime is unaffected: the replay returns the saved response object. Fix shape: type the cache read (checkIdempotencyKey<T>, or cast the replay to the method's own response type) and annotate the return type, so a replay and a fresh call share one declared shape.
