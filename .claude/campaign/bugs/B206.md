## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** A buyer tapping Reorder on a past order gets the same goods at the same denomination: a line that was 2 boxes reorders as 2 boxes and bills 2 x the box price.

**Actually does.** A buyer's bare {productId, qty} counts SELLING UNITS on every path — create() stores it box-unaware and bills it x the BOX price, and F06's merge normalizers are built on that premise. But updateOrderItems' buyer branch re-splits a bare qty as loose PIECES whenever the product is new to the order (isBuyerEdit && !existingProductIds.has(productId)). So reordering a box-unaware line of a upb-12 product into an active order that does not already carry it stores 2 pieces where the buyer asked for 2 boxes, and bills 1/12 of the price.

**The gap.** The pre-F06 clause exists for the opposite mis-read (a bare qty being stored as a BOX count and over-charging by unitsPerBox), so both readings are defensible and the two cannot be satisfied at once while the payload is ambiguous. F06 fixed the STORED side of the denomination reconciliation and left this one deliberately, naming it in merge-items.ts's SCOPE comment rather than guessing.

**Evidence.** Evidence · apps/api/src/orders/orders.service.ts shouldSplit (the !existingProductIds.has clause); apps/api/src/orders/merge-items.ts normalizeBareIncomingSellingUnits (handles the stored-box-split pair only) and its SCOPE comment, gap 1; apps/mobile/lib/order-tracking-logic.ts buildReorderItems (emits the bare shape); apps/api/src/common/pricing.ts header (unitPrice IS the box price for a boxed product). Found by F06's Fable final pass, 2026-09-01.

**Suggested fix (register).** Settle the client contract rather than patching a branch: either have every buyer client send an explicit boxes/pieces split (the web cart already does), or carry an explicit denomination flag on the DTO so the server never has to infer it. Whichever is chosen, the same rule must hold on create(), the merge and the edit — today they disagree.

> suggested fix for every one of the four bugs while confirming every diagnosis.
