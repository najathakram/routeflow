## Reported evidence

app/(marketing)/contact/page.tsx's DemoForm (spec.md R8, must) builds a mailto:hello@routeflow.info draft client-side (contact/page.tsx:67) with no POST to any API -- RouteFlow itself never receives or stores the submission, and delivery depends entirely on the visitor's device having a configured mail client. R8's own copy states this outright ('prepares an email and stores nothing'), so this is a deliberate v1 scope cut, not an oversight -- filed so a lead-capture endpoint (store the submission + notify the team, matching the app's own notifications/email modules) is a visible, prioritizable follow-up rather than a silent gap.
