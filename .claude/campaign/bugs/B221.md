## Reported evidence

The findAll endpoint's @Roles list is (OPERATOR, DRIVER, CUSTOMER), but findAllForUser only special-cases user.role === 'CUSTOMER' (scoping to that customer's own returns); every other role, DRIVER included, falls through to the unscoped this.findAll(options) -- the full tenant-wide list. F08's B75 fix now enriches every row of that list with refundEstimate (billed refund money) and, on a resolved return, effectively refund/credit amounts -- so a DRIVER account can already see other customers' billed return values across the whole tenant. This is a pre-existing role/scoping gap (not introduced by F08) that F08's B75 change makes materially worse by adding money to the payload every DRIVER request now receives. Needs a tenancy carve-out: DRIVER should get either a 403 or its own return-relevant scoping, mirroring the CUSTOMER branch.
