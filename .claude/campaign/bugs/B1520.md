## Reported evidence

SA-1324 (a), 7218330197, confirmed from the code: each payload entry is matched against the PO items read before the loop, so [{A,8},{A,8}] against 10 outstanding passes the check twice, qtyReceived is overwritten with stale+8 and postPoReceipt posts twice: stock +16, qtyReceived 8. An id plus the productId fallback on one item hits the same path. Fix: refuse a repeated resolved item with a 400 before any write and write qtyReceived by increment; first PR of W-1482 (pack 7218235231).
