Independent Opus review of #898 (B343 fix, merged as acbc1037): #898 added a new creditNote.voided socket event mirroring creditNote.created, emitted to the customer's own room -- it now reaches the buyer side and is silently dropped there. Neither useBuyerNotifications.ts (web) nor useBuyerSocket.ts (mobile) has a creditNote.voided handler at all; creditNote.created only toasts/partially invalidates on either. A buyer's own statement/available-credit view goes stale on a void exactly like B343's original bug, and continues to on create the same way it always did. Newly reachable/customer-facing as of #898's merge -- highest priority of the three B343 follow-ups.
