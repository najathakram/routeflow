## Reported evidence

F08's B75 fix prices refundEstimate per row via priceReturn, which needs each return's order's non-VOID/non-WRITTEN_OFF invoice items plus order.lineItems -- selected and joined on every findAll call, then stripped back off the wire per row, purely to derive one number. The web returns page already requests limit: 500 for its KPI/summary fetch (apps/web/app/(dashboard)/returns/page.tsx), and returns.controller.ts's @Query('limit') is parsed with +limit and passed straight through with no Math.min clamp -- so a large or malicious limit multiplies an already-expensive per-row join with no ceiling. Per the repo's limit=0 fetch-all sentinel trap (reference_limit0_fetchall_sentinel_trap.md), any tightening here must first grep every limit:0 / limit:500 caller of this endpoint so a clamp does not silently truncate an existing fetch-all/summary caller.
