## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** Office staff should be able to open a completed stop/order on the web dashboard and view the captured proof-of-delivery photos and customer signature.

**Actually does.** podPhotoUrls/signatureUrl are captured on stop completion (apps/api/src/routes/dto/complete-stop.dto.ts, written in routes.service.ts) and stored in Prisma (schema.prisma:1235-1236), but apps/web has zero references to either field name anywhere — no fetch, no type, no render.

**The gap.** No web screen (deliveries, routes, order detail) surfaces POD photos or signature; only text mentions of the word "POD" exist (ArrivedStopSheet.tsx comment, deliveries/page.tsx warning copy), not actual images/signature rendering.

**Evidence.** Evidence · Grep 'podPhotoUrls|signatureUrl' over apps/web -> 0 files. Grep over apps/api -> 8 files incl. schema.prisma:1235-1236 and routes.service.ts (capture path). apps/web/lib has no reference to photoUrls either.

**Suggested fix (register).** Add a POD section to the web stop/order/delivery detail view that fetches and renders podPhotoUrls as an image gallery and signatureUrl as an inline image.
