## Reported evidence

Follow-up of B946 (SA-628a, #2554 5927765098). For an order with 2+ creditable invoices the refund keeps a lump-sum credit note, bounded only by the order-wide and latest-invoice headroom, so goods billed on an earlier invoice can be credited past that invoice's line value. Return.creditNoteId is a single link, so full itemisation across invoices needs a schema change (Sitting C). No-migration interim fix: run the same refund-mode line-headroom check (allocateProductQty mode refund, using each invoice's loadLineCredits, oldest first) across ALL creditable invoices; a shortfall is the 409; the mint stays one lump-sum CN. Money, tier-1.
