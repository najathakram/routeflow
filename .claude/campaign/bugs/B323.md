## Summary

## What this feature is for

Context: Orders · API cronSweepPendingOrders / onApplicationBootstrap → mergeAllPendingForCustomer. This is part of the F42 batch ("The hourly and boot pending-order sweep runs with no tenant …") — see the batch theme in the hunt digest for the surrounding feature's purpose.

## Root cause

The hourly and boot pending-order sweep runs with no tenant context: winner tax comes from an arbitrary tenant's rate and merged lines are written with NULL tenantId

Symptom / evidence: A background merge recomputes the winner's tax at whichever tenant's settings.taxRate Postgres returns first (or 0%) and writes OrderItem/invoice-item rows with no tenantId, invisible to every tenant-scoped query.

Files implicated: apps/api/src/orders/orders.service.ts, apps/api/src/prisma/prisma.service.ts, apps/api/src/system-config/system-config.service.ts, apps/api/src/recurring-invoices/recurring-invoices.service.ts.
