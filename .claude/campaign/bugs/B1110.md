## Reported evidence

The proration read window starts 2 s before the call, so a second add-on change within ~2 s picks up the first change's proration lines: observed 147.20 (true 98.13) and 49.06 (true -49.07) in the Stripe sandbox; the BillingEvent prorated payload is wrong too. Stripe charges are correct. Fix in the Option A PR: filter on this call's own subscription_item proration lines created at/after the call start (no backdating) or use the update response's invoice preview; pin two changes 1 s apart. Must be fixed before card go-live.
