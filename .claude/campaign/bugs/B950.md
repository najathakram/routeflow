## Reported evidence

Reported by the documentation alignment review lane via Mac Lead. From #2900/#2905 on master the test fails DETERMINISTICALLY on the MacBook (macOS) and passes on Linux and the Mac mini: some raw-socket POSTs resolve 0 because the client socket errors (EPIPE/ECONNRESET) while it keeps writing 1 MB after the server has already rejected and closed, and the test maps any socket error to 0 and asserts every code is 401. Every MacBook push runs the control suite through the pre-push verify, so it is a false red for every MacBook push; no product impact. Fix plan: tests-only PR off master: a reset after the server's rejection counts as rejected, proven by a server-side spy that every response the server sent was a 401 and none was accepted; keep the memory-bound test; mutation-proven, red-first on a forced EPIPE.
