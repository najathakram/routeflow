# B859 · Customer CSV import never sets payment terms, price tier, credit limit, tax-exempt status, tax ID or tobacco licence — those columns are silently ignored

**Location** `apps/api/src/import/import.service.ts importContacts (~214-533) · settings/import 'Customers (Contacts)' card` · **Severity** medium · **State** uncampaigned

## Summary

_Not yet analysed._

## What this feature is for

Bulk-load a new wholesaler's customer list (50-1,000 retailers) with the commercial terms that govern ordering and invoicing.

## Root cause

_Not yet analysed._

## User impact

Every onboarding: payment terms, price tier, credit limit (hard order block), tax-exempt status and tobacco licence expiry must be set per customer by hand; a missed tax-exempt flag taxes an exempt retailer and a missed licence skips the regulated warning. No geocoding at import means routes need coordinates fixed per address. Route with B858.

## Fix approach and UX

_Not yet analysed._

## Test plan

_Not yet analysed._

## Reported evidence

The contacts importer reads names, phones, email, billing/shipping addresses (+ optional lat/lng) and currency only; defaultPaymentTerms, pricingTier, creditLimit, isTaxExempt, taxId, tobaccoLicenseNo/Expiry, delivery window and consent are never read, so they must be set customer by customer. It also does not geocode: addresses without Latitude/Longitude columns import with no coordinates.
