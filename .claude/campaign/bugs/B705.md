## Reported evidence

returns.service.ts:876-880's cancel claim never reads invoice status. unreverseReturnEntries (regulated-ledger.service.ts:476-479) is a blind deleteMany; the inline path (:600-650) does the same. If the source invoice was voided (e.g. by a separate correction) before the return is cancelled, the deleteMany removes the wrong rows and leaves a positive residue on the filing permanently -- a second void attempt throws, so there is no self-heal path. Fix: unreverse up to the current net, or refuse cancel when the source invoice is VOID. High, fast-follow.
