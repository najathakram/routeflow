## Reported evidence

With flag.units_v1 on, staff can sell an order line by a unit on WEB (CreateOrderModal, #1147). A parked web draft stores the line as unit 'Case', qty 1 (a count of the unit), unitPrice 480, unitLabel 'Case', no unitsPerBox. Mobile's fromOrderDraftPayload maps line fields ONE BY ONE and never carries unitLabel, so the same user resuming that draft on mobile gets a plain catalog line (draftSummary shows $480) that submits { productId, qty: 1 } with no unitLabel and no unitPrice: the server takes the PACK branch and stores 1 pack at the pack tier price ($42). A Case of 288 pieces silently becomes 1 and $480 becomes $42. ZERO exposure while flag.units_v1 is OFF for every tenant. Fix: mobile carries unitLabel through DraftCatalogLine and the submit payload, or REFUSES a draft containing a unit line (never degrades it to a pack line); add a web<->mobile parity test for the draft line shape. HARD GATE: this must be closed before flag.units_v1 is granted to any REAL tenant (it does not block the test-tenant flip); fleet lead ruling 2026-09-21, gates G6-G8. Found by the author-side Opus refute-first pass on #1147; web half (declaring unitLabel/packBase on DraftLineItem) is in the #1147 follow-up commit; mobile lane owns this.
