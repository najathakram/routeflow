## Reported evidence

T1 drives the deploy-triggered E2E freshness guard's own YAML-defined steps under a faked gh CLI and asserts on outputs.run; under full host load (parallel verify runs, an engine session, or a Docker build competing for CPU/IO) the faked gh invocation can be slow enough that outputs.run comes back undefined, failing the assertion, while the same test is reliably green run alone or on an idle machine. This is a timeout/robustness gap in the test's own harness (the YAML-driven runner it shells out to), not in the guard logic itself, which L-058 already covers for correctness.
