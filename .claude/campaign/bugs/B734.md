## Reported evidence

The extraction package carries mintReturnKey — generates a fresh identifier per capture attempt, web's model. Mobile does not use it: an offline-queued submission must reproduce the same identifier on replay, so mobile derives a persisted key in its own module instead. Both platforms already pass the key into the shared code as a plain parameter, so the package never needs to own generation at all. It was kept in the shared package for this PR only because the extraction was a strict pure move (zero insertion/deletion) and deleting the function would have made that move unverifiable. Design point, not a defect: evaluate removing minting from the shared package (receive a key, never produce one), with web's call site moving to its own module the way mobile's already has. No user-visible effect at present. Credited to the review that raised it; the lane was right to keep it as-is for this PR.
