## Reported evidence

Verified against master 27073859: campaign-check only fails loudly with a clear message when ALL FOUR workspace reports (api/mobile/pricing/web) are simultaneously null (:739-750). When only ONE or a FEW are missing, jestIndex is built via mergeIndexes(indexAssertions(jestAssertions(api),...), ...) -- a null workspace contributes zero entries to the merged index, indistinguishable from a report that EXISTS but genuinely has no REG-{id} hit. Any row whose REG token lives specifically in the missing workspace's report then fails at checkProofHits (:939) with the generic 'no test titled with REG-{id} found in the {sourceLabel} report', which reads as 'this test doesn't exist' rather than 'this workspace's report was never generated'. Hit 3 times tonight in fresh worktrees per the report. Fix: when jestIndex is built, track which of the 4 workspaces contributed a null report and, in checkProofHits, if hits.length===0 AND the row's expected workspace's report was null, fail with 'report missing for <workspace>' instead of the generic message.
