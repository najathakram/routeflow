## Root cause

Found by the Senior Architect in SA-085 (#1264-v2 pre-read, c2caf627). #1264's picker creates unit lines and persists unitLabel in both the autosave and the at-door stop-cart snapshot, but resume hydration still runs B638's unitLineRefusal and refuses the WHOLE draft ('Open it on the web dashboard'). A driver's backgrounded/killed-app cart with one Case line is lost. units_v1-only: no production tenant exposed today. Fix (follow-up PR after #1264-v2): hydration restores unitLabel and re-resolves unitBasePrice from the live product at the customer's tier; drop the refusal and its pinning test.

PRECISE MECHANISM (fleet lead, from SA-085e, 2026-09-23) — supersedes this record's 'refused wholesale' framing: the new-order screen's draftCatalogLines never wrote unitLabel, so the B638 refusal never sees one; a parked unit line SILENTLY hydrates as a PACK line with qty = the unit count — e.g. 3 Cases resume as 3 packs at the PACK price and are submitted WITHOUT a unitLabel. A money defect, unreachable today only because flag.units_v1 is off for real tenants. HARD write-side gate condition for units_v1. Fix in progress on fix/b747-resume-unitlabel-pricesource (web unit-line lane).

## User impact

The B747 follow-up is a HARD CONDITION before flag.units_v1 reaches any real tenant.
