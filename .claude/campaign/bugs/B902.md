## Reported evidence

Follow-up to SA-580. A product's default selling level (ProductUnit.isDefaultSelling) is not applied consistently: the picker tap and a barcode scan should both start a new line at that level, but web addLineItem and mobile acceptScannedProduct do not both honour it. web/lib/unit-options.ts exports defaultUnitValue(product, options), which returns the default level's value, yet nothing in the web app calls it (only its own test does), so the default never reaches the line. Fix: route both entry points through one helper that reads isDefaultSelling. Source: SA-580c, board #2554 comment 5893305224.
