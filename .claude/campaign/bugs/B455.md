## Reported evidence

The --id reservation flag (B453) refuses an explicit id when explicitNum <= maxId, but never checks whether that id is actually already taken (catalogue/ledger/record) -- only that it's numerically ahead of this tree's current max. If a lead reserves e.g. B460 for one lane while another lane's tree independently advances its own max past 460 first, the reservation is refused even though B460 was never consumed by anyone. An existence check (does a catalogue/ledger/record row for this id already exist) would be the correct refusal condition, not a bare numeric ceiling.
