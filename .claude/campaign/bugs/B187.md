## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** Picking Español translates the operator experience the way the avatar menu and command palette do.

**Actually does.** 22 translation call sites across 3 files; every dashboard page renders fixed English. The catalog itself documents this as the deliberate Phase-1 foundation set, not a regression.

**The gap.** An incomplete-by-design feature whose user-facing toggle promises more than the staged catalog delivers.

**Evidence.** Evidence · apps/web/lib/i18n/messages.ts:2-11 (the header states coverage grows per phase and names this the Phase-1 foundation set — shell, command palette, undo, re-auth); the only importers are apps/web/app/(dashboard)/layout.tsx:72, apps/web/app/providers.tsx:8, apps/web/components/CommandPalette.tsx:35 and apps/web/components/ReAuthProvider.tsx:11, with 8 + 10 + 4 = 22 call sites; apps/web/app/(dashboard)/layout.tsx:929-944 (the Language menu offering English/Español); for scale, 111 .tsx files under app/(dashboard), 216 under app/, 54 under components/.

**Suggested fix (register).** Either gate the Language menu behind a flag until catalog coverage reaches the main screens, or label it as a preview; otherwise keep expanding the catalog per the documented phase plan, starting with page titles and table headers.

> ⚠️ Treat this as a hypothesis, not a plan. On F11 the adversarial pass refuted the
> suggested fix for every one of the four bugs while confirming every diagnosis.

**Verifier's note.** Two corrections carried from verification: the count is 22 call sites, not 24, and the code explicitly declares the partial coverage intentional — which downgrades this from a broken promise to a shipped control outrunning a staged feature. No database impact. Three adjacent i18n claims (locale-pinned formatters, no server-side locale, no mobile i18n) were refuted outright and are recorded in Investigated & Cleared.
