## Reported evidence

The freshness guard compares each Jest/Playwright report's mtime against the current commit, so every merge commit and every squash invalidates every prior report and forces a full regen -- observed as 3 full Jest runs per bookkeeping landing (api + web, twice: once pre-merge on the fix branch, again on the docs follow-up branch). Proposal: key freshness on a content hash of the workspace's test files + the relevant ledger shards, recorded inside the report itself, so a commit that touches neither invalidates nothing -- only an actual test-file or ledger change would force a regen.
