## Reported evidence

ROTATE_SQL sets "inviteToken" = NULL and "inviteExpiresAt" = NULL and nothing else. Today CustomerLink.inviteTokenHash is all-NULL and nothing reads or writes it (one migration, no backfill), so there is no effect now. If S3 backfills the hash and moves the invite lookup onto it before an owner runs a rotation, a rotated link keeps its hash with a NULL expiry, and NULL counts as live in this codebase (the same predicate the SQL itself uses: "inviteExpiresAt" IS NULL OR > now()), so the old link would work again. Found by review-b (note 4, LOW) on #4232 at ef87ea532f; shipped in 06e41dca24. The script is at the SA-820 size cap (650 non-spec lines), so the fix must stay line-neutral. Fix: add "inviteTokenHash" = NULL to the SET (same line) and assert it in R9; or the SA writes into the S3 plan that rotation runs before the hash backfill (the SA sequencing is the open decision).
