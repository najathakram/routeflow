## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** Disabling an add-on removes both the entitlement and the recurring Stripe charge; if the charge can't be removed, the platform admin must be told so billing can be fixed.

**Actually does.** subscriptionItems.del is wrapped in a log-only catch, then the update unconditionally writes active:false, stripeItemId:null and returns 200. Enable has the mirror flaw: a failed create still activates with stripeItemId null.

**The gap.** On a Stripe failure the tenant is billed for a feature they lost (or gets a paid add-on free), and the only stored si_ id is erased.

**Evidence.** Evidence · apps/api/src/billing/addon.service.ts:178-189 (log-only catch on del), :191-194 (unconditional {active:false, stripeItemId:null}), :123-139 (enable-side catch with "Continue — don't block" comment), :143-157 (upsert writes null/undefined stripeItemId); apps/api/prisma/schema.prisma:562 (TenantAddon.stripeItemId is the sole store — grep shows no reconciliation/webhook reads it anywhere); apps/api/src/platform-admin/platform-admin.controller.ts:336-349 and :321-334 (results returned with no failure signal).

**Suggested fix (register).** Only null stripeItemId after a successful (or already-deleted, resource_missing) Stripe delete; on other failures keep the id, mark the row pending-removal, and surface the error to the admin. Mirror the guard on enable.

> ⚠️ Treat this as a hypothesis, not a plan. On F11 the adversarial pass refuted the
> suggested fix for every one of the four bugs while confirming every diagnosis.

**Verifier's note.** Severity downgraded critical→high: requires a Stripe API failure coincident with the disable call, and recovery is possible (AdminAudit records ADDON_DISABLED with addonKey at platform-admin.controller.ts:345, and Stripe lists the subscription's items by price) though entirely manual. The indefinite-wrong-billing consequence is real; the trigger window is narrow. Not a duplicate of B58 (plan-change subscribe) or any other B## entry.
