## Reported evidence

On an invoice DRAFT edit, a line with a partial box sends boxes:0 and pieces:N. invoices.service.ts:3400 enters its pack branch because 0 is not null; packFromOwnSplit returns null because it requires boxes > 0; unitsPerBox (declared :3389) stays undefined; computeLineSubtotal falls to its non-boxed branch and charges the BOX price per PIECE. Five loose pieces of an $11 twelve-pack save as $55.00 instead of $4.58 -- the multiplier is the pack size, so a 24-pack overcharges twenty-four fold. A notes-only save is enough to trigger it (no line edit required). Worse than the overcharge: the same save at :3457 writes unitsPerBox: boxes != null && unitsPerBox ? unitsPerBox : null, which stores null and destroys the line's pack snapshot -- and update() re-syncs the regulated ledger, so the wrong figure reaches a tax filing. Also affects box-unaware lines, not only partial-box ones. Live regression introduced by #1236 (merged 05782852, tonight), confirmed on origin/master directly by the fleet lead rather than relayed. Do NOT revert #1236 -- it fixed a real defect of its own and a revert reintroduces it. Fix-forward, being written now by the session that found it. CRITICAL, hotfix priority, ahead of everything else in tonight's queue.
