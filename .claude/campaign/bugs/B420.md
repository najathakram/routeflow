## Reported evidence

Under the pre-push hook, git had already exported GIT_DIR/GIT_WORK_TREE (+8 siblings) into the process environment; the self-test's git()/runScript() helpers spawned git for a THROWAWAY scratch repo without scrubbing them, so git honored the inherited GIT_DIR over the scratch cwd -- the fixture's git operations landed on the REAL repo instead. Live incident (22:35Z 2026-09-14): .git/config flipped to core.bare=true/repositoryformatversion=0/[user] self-test@example.invalid, and a live worktree's branch (fix/mobile-scan-lanes) was renamed twice (-> feature/drift -> feature/map-touched) with 3 fixture commits stacked on top of the real head. Already fixed: PR #747 (a3d73ab9) scrubs all 10 GIT_* vars in both helpers, adds a post-init 'git rev-parse --show-toplevel resolves inside scratch' guard, and a REG-B420 victim-repo test proving a second polluting repo's branches/HEAD/config stay byte-unchanged. Lesson L-139 already recorded.
