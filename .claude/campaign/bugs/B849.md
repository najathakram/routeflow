## Reported evidence

Board #2069 (found by the Opus pass on #2061). The remaining-quantity check runs per request item against the stored invoicedQty, so two entries for the same orderItemId in one request are each checked against the same remaining amount. A line with 96 remaining at 10/unit (960) and a request of [X 60, X 60] passes both checks and bills 120 pieces (1200). Fix: refuse duplicate orderItemIds (400) or aggregate before the check, red-first spec.
