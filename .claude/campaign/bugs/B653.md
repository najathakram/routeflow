## Reported evidence

The invoice PDF calls formatQtySplit with no unitLabel/boxLabel, so "3 boxes" prints next to a per-Case price; the invoice email prints raw pieces ("qty 36 @ $40.00 = $120.00"); web order/invoice detail, previews and mobile order/invoice detail all print "3 boxes". Totals are right (stored subtotal): this is a display/document defect. HOW KNOWN: sweeper x3 concordant (three independent sweepers agree); NOT verified by R-ui. ROOT CAUSE (shared with B641/B643/B644/B645/B646): computeLineSubtotal and normalizeBoxesPieces silently fall back to per-piece math when a caller omits the split or the factor, and no client type (web, mobile, @routeflow/types) carries unitLabel, so no client can be unit-aware; the fence (assertNoUnitAwareLines etc.) covers rewrite paths only, not client-typed quantities or documents.
