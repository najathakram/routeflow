## Reported evidence

The mobile api-client queues failed-offline mutations unless the request passes _skipOfflineQueue: true. #2868 opts its three new admin writes out via lib/api/settings-parity.ts, but the General tab business-settings save and the push-notifications preference write on the same Settings screen still enter the queue: the UI shows a "Couldn t save" toast offline, then the change silently applies later when the queue replays. Fix: pass { _skipOfflineQueue: true } on both PATCHes (same pattern as settings-parity.ts) with a mock-apiClient test per call (see apps/mobile/__tests__/settings-parity-api.test.ts). Same class as B923. Found in the Opus self-review of #2868; filed via Lane B.
