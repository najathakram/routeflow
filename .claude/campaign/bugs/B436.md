## Reported evidence

L-148 (2026-09-15) fixed invoices/page.tsx's row Print (TanStack Query v5's useMutation() is a single observer per hook instance -- concurrent .mutate(id, {onSuccess,...}) calls share that state, so an earlier row's callbacks are silently overwritten by whichever row's mutate() fires last, not accumulated) but flagged its own fix as unaudited beyond that one call site. Ran L-148's own suggested sweep against master 97fdb372: grep -rn '\.mutate\([a-zA-Z]._{$' apps/web/app --include=_.tsx returns 80 raw hits. Per L-148's guard note, most are single-instance and safe -- this row is the audit itself: narrow to .map()-rendered LIST rows sharing one hook instance before treating any hit as a real instance of the bug, then fix each confirmed instance the same way (mutateAsync + local try/catch/finally).
