## Reported evidence

Verified against master d69f3094: reconcilePriceLedger (billing.service.ts:447) reads tenantSubscription.basePriceSnapshot, computes oldMonthly vs newMonthly, then writes the new snapshot and emits a PLAN_CHANGED amountDelta -- as three SEPARATE, unserialized operations with no and no lock. updateTenantPriceOverride's backfillBase branch (platform-admin.service.ts:1099-1123) independently reads the SAME basePriceSnapshot field, and when it observes null, books its OWN +price delta (amountDelta: roundMoney(dto.monthly!)) inside its own . Neither path takes a row lock or advisory lock against the other. If an admin re-prices a tenant (updateTenantPriceOverride) while reconcilePriceLedger's backfill is mid-flight for the same tenant, both can observe the pre-backfill null/stale basePriceSnapshot and both book a +price amountDelta for what is really one price change -- double-booking MRR growth. #743 review finding (reviews/743-fix-fable-seam.md, seam B). Fix: serialize both paths through the same lock/CAS discipline the rest of billing.service.ts uses (the tenant-keyed advisory lock, or a conditional updateMany on the prior basePriceSnapshot value).
