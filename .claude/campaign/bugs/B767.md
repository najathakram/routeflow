# B767 · Invoice-to-order backward sync (recomputeOrderFromInvoices) creates an OrderItem mirroring a regulated line's categoryTaxAmount but never sets trackedCategoryId, so the tax has no category attribution

## Root cause

Found by Lane B's B297 guard-(i) callsite sweep (fleet lead relay 2026-09-23); verified on origin/master 2ed80789: in recomputeOrderFromInvoices (:2259), the no-matching-order-line branch calls db.orderItem.create (:2367) with categoryTaxAmount: lineCategoryTax (:2378, 'RF-4: mirror the billed category tax back') but NO trackedCategoryId. A regulated line added directly on an invoice with no matching order line, then synced back, carries real category tax with no category attribution — it escapes excise attribution and B297's zero-NULL trio count gate, which keys on trackedCategoryId. Fix: carry the invoice line's trackedCategoryId (and the B297 rate trio once it exists) onto the created order line. Owner: Lane F, AFTER #1274 merges (this code changes in #1274). B297's guard-(i) allow-list cites B767 for this callsite. Regulated money — carve-out parked.
