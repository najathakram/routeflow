## Root cause

SA-085j filing (fleet lead relay, 2026-09-23). Verified at #1281's head 99a0ecfe (not on master yet): resolvePickTarget finds existingUnitEntry = the first draft entry for the product that has a unitLabel (:503-506), and for input.kind === 'piece' it targets THAT entry whenever one exists (:508-509), even when a pack line for the same product is also on the edit screen. A piece barcode is a pack-axis event, so it should default to the pack line when one exists. Today it lands on the unit line, which after the confirm dialog adds one whole Case. The confirm protects the money (no silent mis-bill), so this is LOW. Fix: for kind 'piece', prefer an existing pack (non-unit) line for the product and fall back to the unit line only when no pack line exists, with a pure pin in edit-items-draft tests. Owner: the unit-picker lane, after #1281 lands.
