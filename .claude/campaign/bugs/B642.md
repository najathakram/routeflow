## Reported evidence

husky sets core.hooksPath=.husky/_ (relative, shared repo config) and its prepare script creates that directory. A worktree made with npm ci --ignore-scripts (or any setup that skips prepare) inherits the setting but has no .husky/_, and git treats a hooksPath at a missing directory as no hooks: silently, exit 0. Every push from such a tree skipped the pre-push verify while looking like a push that passed it; found 2026-09-21 on the Mac lane-B worktree, and a sweep of the PC found 23 more worktrees in the same state (U-po x3, U-bugs, laneC, S-b638, coord-detached), all restored. CI ran on every merge and was the binding gate. Referenced as B637 in the 2026-09-21 session transcript. Companion finding: the force-push/checkout guard.mjs is a per-user PC-only PreToolUse hook (C:\Users\nakram\.claude\hooks), absent on every Mac session, so its absence also looked like success. Fixed by scripts/check-git-hooks.mjs: a fail-closed check wired into npm run verify and a silent-when-healthy SessionStart diagnostic, never into a lifecycle script (Docker builds run prepare with no .git).
