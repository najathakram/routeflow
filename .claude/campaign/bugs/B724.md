## Reported evidence

The per-item order note is absent from the aggregated packing list -- RUN_LINE_ITEMS_SELECT (routes.constants.ts:16-34) does not select it and the aggregation carries no note field; absent from the dispatch page's per-stop manifest, which renders only name and quantity; absent from the driver's delivery checklist ((driver)/route/stop/[stopId]/index.tsx:55-62); and absent from the invoice email body. The field's own placeholder promises it 'prints on invoice' -- it does, and reaches nothing else. Broken promise to the user: a note written to communicate something about an item (a substitution note, a handling instruction) never reaches the warehouse staff packing it, the dispatcher routing it, or the driver delivering it. Arguably the most valuable of a five-bug set from the same trace. Multi-line notes PR fixes this one; the other four are separate ids. Fast-follow.
