# B837 · A delivered order whose only invoice is outside PAYABLE (PAID, VIEWED) gets a fresh DRAFT at delivery: guard should be no non-VOID invoice

## Root cause

Filed by the SA via SA-130b (B663-era), fleet lead relay 2026-09-24. VERIFIED on origin/master b6e6bc7f: delivered-reconcile.ts:51-63 creates a fresh DRAFT (deps.createInvoiceFromOrder) whenever there is no open draft AND no invoice in PAYABLE (DRAFT/SENT/PARTIAL/OVERDUE), so an order whose invoices are all PAID (or VIEWED; see B832) passes the guard, whereas rebuildIssuedDepositMirrorOnDelivery (invoices.service.ts:1690) uses status not VOID. NOT YET VERIFIED, and the real reach depends on it: createInvoiceFromOrder (:553-571) returns the existing invoices without creating one when every line has invoicedQty >= qty, and it bumps invoicedQty itself (:742-746). So a PAID invoice minted by createInvoiceFromOrder does NOT re-invoice; the defect bites when invoicedQty < qty on a prepaid order (a PAID invoice written by a path that doesn't bump invoicedQty, e.g. a deposit mirror or a buyer-checkout invoice, or lines grown after payment). FIRST STEP: a red-first DB spec reproducing a prepaid order re-invoiced at delivery; if none can be built, downgrade. Fix: guard = no non-VOID invoice (the mirror predicate), with the grown-lines remainder case decided by the SA. Money: owner-ready plan first.
