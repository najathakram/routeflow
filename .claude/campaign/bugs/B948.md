# B948 · Inline-return standalone credit notes are not counted in line credit headroom (a second over-credit path)

**Location** `apps/api/src/credit-notes/line-credit-headroom.ts (loadLineCredits is invoice-scoped); apps/api/src/returns/returns.service.ts (inline return pricer)` · **Severity** high · **Batch** F49 · **State** already-fixed

## Summary

CONFIRMED by the F2 probe (#2554 5927794589, master d3875d09). A $100 line: a credit-note item of $60, then an INLINE return of the whole line refunded $100 - both accepted - $160 credited on a $100 line (the reverse order is also $160). Path: inline captureAndIssueInTx -> mintStandaloneInTx (itemless, invoiceId null); the quote/pricing never reads CreditNoteItem; create()'s priorForLine ignores itemless credit notes. Fix shape (SA-628a (c), no migration): loadLineCredits adds an INLINE term (sum of ReturnItem subtotal/qty from sourceInvoiceItemId where the return's credit is not VOID); the inline pricer checks the same helper in refund mode before minting. Severity high, money.

## Reported evidence

Follow-up of B946 (SA-628a, #2554 5927765098). Inline-return standalone credit notes carry no invoiceId, so loadLineCredits never counts them; a credit note on a line plus an inline return of the same goods can credit more than the line value. Inline ReturnItem rows snapshot sourceInvoiceItemId, subtotal and qty, so they are attributable without a migration. Fix: add an inline term to loadLineCredits (sum of ReturnItem credit for sourceInvoiceItemId in the lines whose credit is not VOID) and have the inline pricer check the same helper in refund mode before minting. F2 probes first (a CN on a line plus an inline return of the same goods). Money, tier-1.
