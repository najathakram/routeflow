# B1411 · The far-from-list price warning uses a different reference on the order page and in Create Order

**Location** `apps/web/lib/far-from-list.ts; apps/web/app/(dashboard)/orders/_components/CreateOrderModal.tsx and LineItemRow.tsx; price-edit-row.tsx` · **Severity** low · **Batch** F65 · **State** queued

## Summary

_Not yet analysed._

## What this feature is for

_Not yet analysed._

## Root cause

No single reference function: each screen picks its own price.

## User impact

_Not yet analysed._

## Fix approach and UX

SA-A ruling: one reference, the line's own price for this customer before a manual change, resolved by customerLinePrice; SPECIAL lines compared too; same unit; words name the reference; farFromListText takes { unitPrice, reference, referenceIsList } with one helper beside each surface. Lands right after #4518, S size, web only.

## Test plan

T2 red tests (a) tier at 40% of list untouched: no warning on either surface; (b) SPECIAL 6.00 typed 60: both warn; (c) 12/box line, box reference 18.00, typed 1.50 warns, 17.00 does not; (d) one shared case table runs against both surfaces.

## Reported evidence

Both surfaces call farFromListText but pass different references: the order page uses the line's own resolved price (originalPrice ?? unitPrice), Create Order uses the catalog tier-1 list price and skips SPECIAL lines. A tier customer whose tier price is under half of list sees 'NN% below list' on an untouched line in Create Order and nothing on the order page; a slip on a SPECIAL line warns on the order page and never in Create Order.
