## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** The APK built from #563 installs and opens to the login screen.

**Actually does.** It died before any UI, every launch: NoClassDefFoundError: expo/modules/filesystem/FilePermissionModule. expo-file-system was pinned ~18.1.11 against SDK 55's ~55.0.26, so its native module predates the class expo-modules-core 55 loads while building the module registry. The pin existed to keep the legacy downloadAsync/writeAsStringAsync/cacheDirectory API used by exactly one file — an API SDK 54 moved to expo-file-system/legacy.

**The gap.** Web never links the native module, so the pin was invisible on the only surface anyone ran — it takes a native build to surface, and no native build had ever succeeded. Found by installing the first APK on an emulator and reading logcat.

**Evidence.** Evidence · apps/mobile/package.json (expo-file-system ~18.1.11 vs expo/bundledNativeModules.json ~55.0.26); emulator logcat: FATAL at expo.modules.filesystem.FileSystemPackage.createInternalModules; apps/mobile/lib/share-pdf.ts (the sole importer). npm quirk: a stale nested 18.1.11 under apps/mobile/node_modules that npm ls itself reported invalid kept being restored — removed from tree AND lockfile.

_Found by the first-ever APK run (emulator, Android 14) · verified Aug 31, 2026 · fixed in #565 · master@4046e669_
