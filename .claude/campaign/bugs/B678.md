## Reported evidence

AdminModal's focus-management effect depends on [open, onClose], and 8 of 9 callers pass a fresh inline onClose closure, so every keystroke in a controlled field inside an open modal re-renders the parent, re-creates onClose, re-runs the effect, and moves focus to the modal's close (x) button. In the tenant 'Permanently delete tenant?' confirm (slug input) and the buyer add-link modal, a keyboard user types one character and lands on the close button instead of continuing to type -- a real accessibility/usability defect, worse on a destructive-action confirm. The 4 existing AdminModal specs never re-render the parent while open, so this was never caught. Fix in flight (Lane B PR 2a: onClose moved to a ref, effect deps [open] only, repro-first spec). Related LOW findings from the same audit (dialog has no accessible name, close button is a bare x with no label, 4 error banners lack role=alert, 'Execute Merge' loses focus to body) -- not filed separately, tracked here for the same fix pass.
