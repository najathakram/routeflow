## Reported evidence

Opus W/N on #1324: the STANDARD receive() path calls reverseReturnEntries without the Order row lock the live create/capture/cancel paths and the parked-reversal resolution take (Return -> Order). reverseReturnEntries reads per-line remaining balances then books, so two concurrent receives (or a receive racing an inline capture) on one order can both read the same remaining and over-reverse the regulated ledger. Returns lane, medium.
