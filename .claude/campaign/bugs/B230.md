## Reported evidence

F12's round-4 fix-round-4-result.json recorded two minor new hazards from the seed-once-per-open guard (startTimeRef/seededRef): (1) templates/[id]/page.tsx's guard cannot tell an operator-chosen time from an auto-seeded one, so once any open seeds the tenant defaultStartTime the field stays non-empty for the life of the page -- if the owner later changes the tenant default, this always-mounted modal keeps showing the stale value until a full reload, and a dispatch sends it; (2) routes/page.tsx's comment claims parity with the templates modal ('a time the operator chose survives a reopen, same shape') but that page's reset effect (:126-139) clears startTime/startTimeRef on every open, so a chosen time never actually survives a reopen there -- the code is correct (its real job is stopping a late-arriving defaultStartTime from clobbering a time typed while settings were still loading) but the comment overclaims and could mislead a future edit into weakening the reset effect.
