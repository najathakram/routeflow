## Reported evidence

Mirror-image of updateStatus()'s gap (the reason mrr can disagree with ledgerMrr on the Platform Dashboard, B536) but in the opposite direction: updateStatus can leave a stale +delta in the ledger after a tenant stops paying; activateManualSubscription can make a tenant START paying (status->ACTIVE + planKey set) without ever emitting the matching +delta, so ledgerMrr can UNDER-count relative to live mrr. Contrast with updatePlan() in the same file, which always emits BILLING_EVENTS.PLAN_CHANGED with a correctly-signed amountDelta in the same transaction as its write. Found during a static review (Opus adversarial pass) for the Platform Dashboard MRR P1 investigation, cross-referenced against billing.service.ts's transitionAndEmit()/emitPayingDelta() pattern -- not yet confirmed as the cause of any specific observed drift, that is a separate question the dashboard investigation (report-mrr-ledger-drift.mjs, PR #912) is still running.
