## Reported evidence

On master, assignToVariants runs its transaction at isolationLevel Serializable (timeout 60s) with no retryOnTxConflict wrapper. A concurrent edit to the same product family can abort it with a serialization failure (Postgres 40001 / Prisma P2034), and that raw error reaches the user instead of a retry. Fix: wrap the transaction in retryOnTxConflict. Fixed by #2741 (M2); close this bug when #2741 lands. Source: SA-587e, board #2554 comment 5885586130.
