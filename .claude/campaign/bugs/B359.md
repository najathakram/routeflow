# B359 · Buyer registration reveals whether an email already has an account (F3-005 remainder)

**Location** `Auth · api buyer registration` · **Severity** low · **Batch** F48 · **State** queued

## Summary

_Not yet analysed._

## What this feature is for

## Root cause

Register throws ConflictException with an already-exists message.

## User impact

Pre-auth enumeration of buyer accounts by email for phishing or credential stuffing.

## Fix approach and UX

Uniform response for new and existing emails; existing address receives an account-exists email; keep the rate limit.

## Test plan

T1: existing vs new email produce identical status and body; existing path enqueues the notice; extend buyer-auth.security.spec.ts.

## Reported evidence

Register returns a distinct 409 for an existing email while login is already uniform. Expected: identical response for new and existing emails, with an account-exists notice sent by email.
