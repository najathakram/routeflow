## Root cause

Root cause (traced at b0e0193854): For an order WITH recorded quantities the off-route demote is safe: it is a plain status write (order-ship-state.ts:128-129) that clears only deliveredAt (order-status-claim.ts:24), never deliveredQty or DeliveryMutation rows, so the cancel's under-lock check (order-cancel-tx.ts:72-83) still sees the delivered units and refuses. That is why the demote does not bypass assertNoLiveReturn in the way A-4 guards against (reopenStop reverses the evidence; this path does not). THE GAP is the legacy row: a DELIVERED order whose active lines all read deliveredQty 0 and that has no evidence row (pre-SA-763r office deliveries). (1) assertOrderStatusTransition allows DELIVERED -> CONFIRMED with a reason (order-status-transitions.ts:28,56-66). (2) assertDeliveredDemotionAllowed (delivered-demotion.guard.ts:15-30) checks only a paid walk-in and a COMPLETED stop; it has no return check and no missing-quantity check. (3) The demote to CONFIRMED is a bare CAS write; only the PD demote runs recordPartialDeliveryInTx, which would refuse. (4) Once CONFIRMED, cancelBlockedByMissingQuantities returns false because DELIVERED_STATUSES is only DELIVERED and PARTIALLY_DELIVERED (order-pd-quantities.ts:58-61,75-81), and B56 counts 0 delivered units, so cancelImpact and assertCancelDeliveryStateUnderLock both pass. (5) cancelOrderInTx credits the creation-time decrement for every line (order-cancel-tx.ts:121,135-150). Returns are capped by line qty, not deliveredQty (isReturnable at returns.service.ts:257-260 needs only DELIVERED), so a legacy order can carry a received return that already restocked. Class: a guard keyed on the CURRENT status, which the guarded transition itself changes (the same blind spot B692's own header names for PD -> OUT_FOR_DELIVERY, closed there by leavePartialDeliveryInTx but not for DELIVERED -> CONFIRMED).

## Reported evidence

SA-1101 A-5 (named B1272 in #4208 and its specs; B1272 in the register is a different row). A legacy DELIVERED order of 10 with a received return of 4 (stock 94): Reopen order succeeded and the cancel after it ended at stock 104. Fixed by guardDeliveredDemotion (lock, then count live returns) as the first statement of each demotion write, 409 ORDER_HAS_RETURN, and by counting returns raised on another order through ReturnItem.sourceOrderId (A-6 Part 1). #4208, merge 4242d2b9c1.
