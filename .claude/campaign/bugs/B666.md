## Reported evidence

postBatch rebuilds each bill line as { productId, name, description, qty, unitCost } and DROPS packSize (also sku and lineTotal), although the scan prompt asks for it (vendor-bills.service.ts:1799: 'packSize: units per box/case/pack as a number ONLY when the line explicitly shows one'), the extracted line type carries it (batch-import.service.ts:28), and extractedPayload keeps it (:213, :347). lineInventoryDelta (vendor-bills.service.ts:141-153) converts only when the line's OWN packSize > 1 (pack = item.packSize ?? 0) and never reads Product.unitsPerBox. WORKED EXAMPLE: 12 per box, 5 boxes at $24 printing '12x330ml', on hand 100 pieces at $2 per piece. Correct: +60 pieces, stock 160, averageCost $2.00. As coded: +5 pieces at $24 per piece, stock 105, averageCost $3.05. totalOwed is right; stock and the COGS basis are wrong. SECOND, SMALLER GAP: when the invoice prints no pack size the interactive flow lets the operator choose Boxes; the batch flow gives no way at all. NOT in code #1045 touches (it is web-only interactive-modal code). No import spec pins packSize (batch-import.service.spec.ts has no packSize). PROD DATA QUESTION: batch-imported vendor bills with a boxed product and packSize NULL, and their stock/averageCost deltas. Severity: the lead said MEDIUM-HIGH; the tool has no in-between, so it is filed as medium and can be raised.
