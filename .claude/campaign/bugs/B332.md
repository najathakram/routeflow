# B332 · Monthly tobacco-report and daily standing-order crons have no catch-up window, so a lost tick or FAILED month is never retried

**Location** `Compliance + standing orders · API generateMonthlyReports / generateDailyOrders` · **Severity** medium · **Batch** F43 · **State** queued

## Summary

Monthly tobacco-report and daily standing-order crons have no catch-up window, so a lost tick or FAILED month is never retried

## What this feature is for

Context: Compliance + standing orders · API generateMonthlyReports / generateDailyOrders. This is part of the F43 batch ("Monthly tobacco-report and daily standing-order crons have n…") — see the batch theme in the hunt digest for the surrounding feature's purpose.

## Root cause

Monthly tobacco-report and daily standing-order crons have no catch-up window, so a lost tick or FAILED month is never retried

Symptom / evidence: A restart at 02:00 UTC on the 1st costs a regulatory month with no row at all; a FAILED report row is never re-queued and only a manual POST recovers it.

Files implicated: apps/api/src/tobacco/tobacco-report.service.ts, apps/api/src/order-templates/order-templates.service.ts, apps/api/src/common/cron-lock.ts.
