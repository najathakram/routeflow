## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** Editing a scanned vendor bill should keep the separately-captured sales tax folded into the recomputed total instead of losing it.

**Actually does.** update() explicitly re-folds tax into totalOwed using dto.taxAmount if resent, else falling back to the persisted bill.taxAmount, exactly to prevent dropping it; create() persists taxAmount on the bill row specifically so an edit can recover it. Code comments identify this as an already-fixed prior bug ('G4 tax lost on edit').

**Evidence.** Evidence · apps/api/src/vendor-bills/vendor-bills.service.ts:618-639 (update(), fallback to bill.taxAmount at line 637, comment 625-628 referencing the fixed 'G4' regression) and :257-259 (create() persists taxAmount for exactly this reason); apps/web/app/(dashboard)/vendor-bills/[id]/page.tsx:893-919 (handleSaveEdit sends no taxAmount, relying on server fallback)
