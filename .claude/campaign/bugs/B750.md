## Root cause

Pre-existing. Found by the Order UI lane's extended overflow probe (fleet lead relay 2026-09-23); excluded from its new spec 53 with an inline comment — remove that exclusion when fixed.

## User impact

SEVERITY low -> MEDIUM (2026-09-23, evidence from code at bc7b0ad9, prompted by an independent overflow-fix reviewer): the table sits in `<div className="overflow-hidden rounded-lg ...">` (invoices/page.tsx:696) with NO scroll container, inside the dashboard shell's `overflow-x-hidden` main (layout.tsx:1382). Columns past 390px are therefore CLIPPED AND UNREACHABLE on a phone, not merely drifting. Medium not high: operators have the mobile app's own invoices screen; raise to high if the clipped columns turn out to include Balance/Amount or the row actions (confirm with a 390 capture).

SEVERITY medium -> HIGH on MEASURED evidence (Order UI lane capture, fleet lead relay 2026-09-23; proof on the PC at local-assets/proofs/2026-09-23-mobile-overflow/, the B750 capture): at 390px the Amount, Balance Due AND row-action columns start at x = 414 — off-screen, and the wrapper is overflow-hidden (not auto/scroll), so there is NO scroll mechanism: unreachable, not 'needs scrolling'. A phone-width web operator cannot see an invoice's balance or act on a row. An instance of the B540 defect class (multi-column tables in overflow-hidden clip instead of scrolling). Owner: the Order UI lane, next, as its own small PR — overflow-x-auto on the wrapper, before/after captures at 390.
