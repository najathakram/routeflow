## Root cause

From #1317's Opus delta (fleet lead relay, 2026-09-23), tooling/security hardening with no live instance. Verified at #1317's head 79b5ecc6. (1) The href rule inspects TEMPLATE LITERALS only (:385-392: templateSpans, 'before' text matched by /href\s*=\s*["']?$/i), so string concatenation ('<a href="' + url) and an 'href="' prefix held in a variable get past it. (2) Leading whitespace INSIDE the quote (href=" ${…}", href="&#32;…") doesn't match the regex. (3) isReassigned (:152-176) misses array/object destructuring, for…of, a parenthesized left side and a var redeclaration. (4) Two mutants survive: deleting the isReassigned call in fromSafeLinkHref (:193), and narrowing the regex to href="$. Add tests that kill both. (5) Allow-list keys are 'fn :: expr', so a THIRD identical site in the same function passes silently; count occurrences per key.
