## Reported evidence

middleware.ts's skipMobileRedirect only exempts an exact MARKETING_PATHS/MARKETING_AUTH_PATHS/isMarketingAsset match (marketing-routes.ts: exact-path match only, no prefix matching, by design). A path that is not one of the 10 real marketing routes -- e.g. a typo'd /produkt or a stale link to a retired route -- falls through to the mobile-UA check, and a phone visiting it is proxied to the mobile-web Railway build instead of rendering apps/web's own app/not-found.tsx (the ported 404, covered by e2e/36-marketing-site.spec.ts's Desktop-Chrome-only 'a bogus marketing path 404s with the port's not-found H1' test -- that spec's only project is Desktop Chrome, so this phone-UA path has no coverage). Not a spec deviation (R11 only promises the 10 listed paths stay marketing on a phone) but a real gap: the mobile app has no route for an arbitrary marketing typo either, so the phone visitor likely lands on ITS not-found/blank state, not RouteFlow's.
