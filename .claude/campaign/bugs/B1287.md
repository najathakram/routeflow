## Reported evidence

handleEditPriceSave runs catch { toast("Failed to update price") } and then setEditingPriceId(null) on both the success and the failure path; reopening the editor (handleEditPrice) resets the value to the stored price, so the typed price is lost. The empty-answer branch returns and leaves the box open, which shows the intent. The second toast: useUpdateProduct (apps/web/lib/api/products.ts:100-108) has no meta: { localErrorToast: true }, so handleMutationError (apps/web/lib/mutation-error-toast.ts:18, wired in apps/web/app/providers.tsx:22-24) toasts as well; the sibling useReactivateProduct already opts out. Fix: return in the catch (keep the editor open with the typed value) and either drop the local toast or opt the call out of the global one. Source: bug hunt 2026-11-06, verify-ui C-2 (confirmed, read at 7be372afed).
