## Reported evidence

git exports GIT_DIR to every hook it runs (including pre-push); with GIT_DIR set and no matching GIT_WORK_TREE, running 'git -C <statusDir> rev-parse --show-toplevel' from inside the freshness guard returns statusDir itself instead of the repo root, so path.relative(toplevel, statusDir) yields the empty string and the ledger pathspec used to bound the freshness check collapses to '.' -- the guard then judges freshness against HEAD's own commit time instead of the ledger/test files it should be comparing. Reproduced 2026-09-06 23:1xZ in the rf-ocr worktree: a push issued immediately after a commit was refused by the freshness guard even though nothing it touched was stale. Fix: scrub GIT_DIR/GIT_WORK_TREE/GIT_INDEX_FILE/GIT_PREFIX from the environment of every git/turbo child process this script (and any script it calls) spawns, plus a regression spec that sets GIT_DIR before invoking the guard and asserts it still resolves the real repo root.
