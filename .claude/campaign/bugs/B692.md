## Reported evidence

order-cancel-impact.ts:39-44,89 sums deliveredQty to decide cancel impact, but a manual changeStatus to DELIVERED (orders.service.ts:2634-2635) writes only deliveredAt, never deliveredQty -- only routes.service.ts's route-completion path (:2584, :3085) writes deliveredQty. Consequence: an order marked DELIVERED by staff in the office (not through a completed route stop) still reads deliveredQty=0, so cancelling it restores full stock and voids every invoice as if nothing was ever delivered -- B56's blanket-void gate (deliveredQty>0) never fires because the signal it reads was never written. Fix: manual DELIVERED writes deliveredQty=qty per active line; manual PARTIALLY_DELIVERED requires per-line quantities. Found by MacBook's A2 state-machine verifier (Fable, refute-first), pre-existing on master, not in today's train. Fast-follow.
