## Root cause

From #1322's Opus review (PASS W/ NOTES at 77850a50), fleet lead relay 2026-09-23. Verified: (1) at #1322's head, normalizeOrigin (auth.controller.ts:97-103) returns the raw string when new URL() throws, so a configured MOBILE_WEB_URL with no scheme is KEPT verbatim in the allow-list. Treat it as unset (WEB_URL only) and log the boot warning. (2) rejected return_origin candidates on the UNAUTHENTICATED GET /auth/google are warn-logged every time with no throttle, a log-flood vector; throttle or sample it (for example once per origin per N minutes). (3) PRE-EXISTING on master: configuration.ts:121 'mobileWeb: process.env.MOBILE_WEB_URL ?? <default>', where '??' keeps an EMPTY string, so a blank MOBILE_WEB_URL gives mobile password-reset links an empty base URL. Use '||' plus the same boot warning, and fix the .env.example wording to 'unset or blank'. Pins per item. Owner: the unit-picker lane, after phase 1a.
