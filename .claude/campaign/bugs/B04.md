# B04 · Push-notification toggle registers nothing

**Location** `Settings · mobile` · **Severity** high · **Batch** F20 · **State** done

## Summary

The mobile operator push-notification settings switch is local component state only; toggling it off does not stop the server from sending pushes to that user's device token.

## What this feature is for

_Not yet analysed._

## Root cause

(operator)/settings/index.tsx holds the switch in local state (lines ~41,60-73,115-128); login registers the device token unconditionally (lib/auth.ts:166,252); notifications.service.ts's send path queries deviceToken only (lines 79,101) with no preference check, so the toggle never reaches the send path.

## User impact

_Not yet analysed._

## Fix approach and UX

New per-user UserPreference field pushEnabled (no migration). Send path filters by preference; registerPushToken skips registration when the preference is false; the settings switch reads/writes the preference via /users/me/preferences (same pattern as locale) instead of local state; toggle-off also deletes the current device token.

## Test plan

API unit pins: send path skips users with pushEnabled=false; registerPushToken no-ops when disabled. Mobile pure-logic pins REG-B04-A (switch persists via preference, not local state) and REG-B04-B (login registration gated by preference).

## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** Let the operator control whether this device receives push notifications, with the alert explaining registration will happen the next time the app launches.

**Actually does.** The Switch only sets a local `pushEnabled` state (never sent to the server, never included in the settings save payload) and shows an alertInfo popup; actual push-token registration/deregistration happens automatically and unconditionally on every login/logout via lib/auth.ts, unrelated to this switch.

**The gap.** Turning the switch off does not deregister the device, and turning it on does not register anything on next launch — the alert describes a mechanism that doesn't exist.

**Evidence.** Evidence · apps/mobile/app/(operator)/settings/index.tsx:41 (local state), :107-129 (Switch + alertInfo text), :60-73 (save() payload has no pushEnabled field); real registration in apps/mobile/lib/auth.ts:119-142 (registerPushToken), called unconditionally at :168 and :251, deregisterPushToken at :275.

**Suggested fix (register).** Either persist the preference server-side and gate registerPushToken/deregisterPushToken on it, or replace the switch+misleading alert with an OS-level 'open notification settings' deep link.
