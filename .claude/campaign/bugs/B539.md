## Reported evidence

Owner-requested UX (2026-09-18), feature gap not a defect, filed as two related asks on one entry: (a) changing a tenant's tier gives no before/after preview -- the owner wants to see, before confirming, exactly which features will be ADDED and which will be DROPPED by the change; (b) entitlement configuration must survive a downgrade-then-re-upgrade round trip -- if a tenant had a feature configured a particular way, a downgrade that removes that feature and a later upgrade that restores it should restore it AS IT WAS, not as a fresh default. Flag: (b) intersects the standing ENTITLEMENTS = ONE RULE ruling (preset + grants - denies, owner 2026-09-17, project memory project_entitlements_one_rule_2026-09-17) and may need its own owner ruling on where remembered per-tenant configuration lives -- it is not obviously expressible in preset+grants-denies alone. The lead is raising that intersection with the owner separately; this entry should not be treated as pre-approving a specific storage design.
