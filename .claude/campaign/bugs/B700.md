## Reported evidence

pack-at-sale.ts:19-23 reads the LIVE product.unitsPerBox, on the premise (stated in its own header) that only split lines are snapshotted -- that premise is FALSE: invoices.service.ts:955 snapshots unitsPerBox on EVERY order-derived InvoiceItem (finance.prisma:276-279, explicitly 'carried from the order line, never the live product'). Effect: after a repack (12->24) before delivery, delivered-basis reconcile reverses -60 and re-books +120 -- net +60 phantom pieces on the period's filing -- and a later full inline return reverses only $25 of a $50 line. SA-062 fix: packAtSale = it.unitsPerBox ?? packMap.get(it.productId) ?? null; rewrite the header (it's wrong about the snapshot premise); warn with invoiceItemId + both packs when snapshot and live differ (repack signal). Red-first cases: {qty 5, unitsPerBox 12, boxes null} with product now 24 must book 60 not 120 on BOTH create and resync; {unitsPerBox null, product 12} must still book 60. SA reads the diff before merge. High, own PR, fast-follow -- part of the live-pack-reinterpreting-a-stored-line class (see cross-linked siblings).
