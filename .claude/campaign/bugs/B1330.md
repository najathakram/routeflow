## Reported evidence

Observed 2026-11-15 on a throwaway test tenant (qty 0 re-probe and the qty 3 / boxes+pieces probe): a staff edit {id, qty:3} of a delivered 5-of-5 line on a DELIVERED order resolves with no error; stored qty becomes 3 while deliveredQty stays 5, the line flips to PENDING, stock gets no return movement, and createInvoiceFromOrder bills the reduced qty (total 3 not 5). boxes/pieces on a plain line are silently ignored; on a boxed line they cut the qty the same way. {id, qty:0} is a no-op because the update branch skips qty<=0 for every line (orders.service.ts per-line update branch), so the first probe never reached the floor. entryRemovesLine (delivered-line-lock.ts) covers CANCEL/DELETE/substitute only. Fix per SA-992 D2 as ruled in SA-batch-0751: one pure assertQtyNotBelowDelivered(held, nextQty) in delivered-line-lock.ts, called with the FINAL stored qty at each write of an existing line's qty, 409 LINE_ALREADY_DELIVERED with its own message. Not probed: a unit-aware (selling-unit ladder) line. Rides with F-1; the probe spec is the red test.
