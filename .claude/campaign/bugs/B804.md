# B804 · units_v1: order-edit pack write branches (substitute, UPDATE) never write unitLabel, so a unit line moved back to the pack keeps a stale label and regulatedUnitBasis reads a box count as base pieces (3 instead of 36)

## Root cause

Fleet lead relay; found by the MacBook landing's Opus pre-push review of B802. 2026-09-23. Verified on origin/master b8863d56. The substitute branch's tx.orderItem.update (:4283-4300) writes productId/unitPrice/qty/boxes/pieces/unitsPerBox/promoFreeUnits/subtotal/status, and the UPDATE branch's (:4531-4550) writes qty/boxes/pieces/unitsPerBox/name/unitPrice/subtotal/promoFreeUnits/notes. NEITHER writes unitLabel. When a staff edit via the direct API (substitute with unitLabel:'' or UPDATE with unitLabel:null) moves a units_v1 unit line back to the pack, the line keeps its stale label ('Piece') on a box-count qty with no split and a null snapshot. regulatedUnitBasis branch 1 then reads that qty as BASE pieces: a unit basis of 3 instead of 36 for 3 boxes of 12. That's money/regulated (license and excise basis). Returns and restock are already guarded by B802's unitsPerBox === 1 rule. Web and mobile never send this shape, so it's API-reachable only, units_v1 only (test tenants in prod). Fix: both pack branches write unitLabel: null when the resolved unit is the pack, with red-first pins per branch. It touches orders.service.ts (at its size ceiling), so it rides the held B776/B753 train. Owner: Lane B, with B789.

## Fix approach and UX

WIDENED (fleet lead, 2026-09-23): the LEDGER side also trusts a stale unitLabel on its own: regulatedUnitBasis branch 1 and classifySaleAxis step 4 read the label without cross-checking the pack split and snapshot. So besides the writer fix (both pack branches clear unitLabel on re-denomination to the pack), add a LEDGER-side pin: a line with a stale label on a box-count qty with no split and a null snapshot must not be read as base pieces (or must be refused), so a stale row already in the DB can't mis-state the regulated basis.
