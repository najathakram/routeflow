# B751 · Shared Playwright storageState (e2e/setup/.auth/operator.json) is rewritten by any lane whose global setup uses a different baseURL, so a later run silently lands on another server and reports a false result

## Root cause

Proven 2026-09-23 on the Mac mini (F2's #1121/B597 re-proof): the shared storageState's origin changed from :3003 (freshly minted for the PR's dev server) to :3001 mid-run — another lane's global setup (PLAYWRIGHT_BASE_URL defaults to :3001) rewrote the file. The fresh context then had no :3003 auth and landed on :3001's master build, which lacks #1121, rendering '0 of 51 delivered' — #1121 looked regressed. With a private storageState (origin :3003 only, network log: zero :3001 requests, zero 4xx/5xx) the same order rendered correctly. Remedy shape (fleet lead): a storageState path per lane or per run, and a global setup that REFUSES when the stored origin differs from the target baseURL.
