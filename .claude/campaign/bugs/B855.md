## Reported evidence

createTenant's welcome email embeds the admin's temporary password in the message body (forcePasswordChange applies only when it was auto-generated). The staff path already uses a hashed, expiring set-password link (UsersService.sendSetPasswordInvite); the tenant-admin path should too. The same email uses trial wording, which misreads for sales-led paid customers (documented in the onboarding playbook).
