## Reported evidence

apps/api/tsconfig.json:7 sets isolatedModules: true, which ts-jest inherits, making the Jest transform transpile-only; tsconfig.json:26 additionally excludes **/*.spec.ts and **/*.test.ts from the compile unit entirely. Result: 512 spec files on master are type-checked by NOTHING. A fixture that drifts from the type it models fails only as a wrong runtime value, and only if an assertion happens to touch that specific field -- Lane B hit exactly this during Release 1, a NaN where 4 was expected, because a fixture lacked a newly-required field. On a codebase whose fixtures encode money and regulated-filing quantities, the failure mode is a test that passes while silently asserting the wrong number. Ruled fix shape (Senior Architect, SA-056): a separate apps/api/tsconfig.spec.json extending the base tsconfig with exclude: [] and include: src/**/*.spec.ts, plus a check-types:spec script run alongside check-types in npm run verify; lands as a ratchet with a pinned allowlist of not-yet-passing files that only shrinks (same discipline as size-ratchet.spec.ts); standing rule that a fixture modelling a Prisma row is written with ; and this must NEVER be fixed by deleting tsconfig.json's exclude, because nest build shares that same tsconfig file and specs would land in dist. apps/api/tsconfig.plan-gate-specs.json (six files, nothing runs it) is the existing seed for the pattern. Sixth instance of the same class found in one release night (a control that exists, is believed to be working, and does not run on the thing it protects) -- and by surface area the largest: 512 files. Related to B686 (apps/api/tsconfig.json also excludes scripts/** and prisma/**, same shape, different exclude entry). Fast-follow, not release-blocking. Filed per the fleet lead's request, sourced from the Mac mini via SA-056.
