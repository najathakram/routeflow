## Reported evidence

Verified against master 97fdb372: docker-compose.yml has 6 hard-coded container_name entries (routeflow_postgres, routeflow_redis, routeflow_redis_ui, routeflow_migrate, routeflow_api, routeflow_web) and no top-level name: field. Without an explicit -p <project> flag, the compose project name defaults to the invoking directory's basename -- but the fixed container_name values collide across ANY two worktrees/checkouts that both run local:up, regardless of project name. Already documented as L-103's root cause (2026-09-10); recurs at every lane handoff since nothing has actually changed the compose file. Fix: add a top-level name: routeflow (or require -p routeflow on every local:* script) so at most one stack can hold the fixed container names at a time, with a clear collision error instead of a silent fight.
