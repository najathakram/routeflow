## Root cause

Fleet lead relay (the MacBook's B768 follow-up b01f1ab2), 2026-09-23. Verified on origin/master 5ae97db7 (2026-09-23). Both writers build connectionString = e.DATABASE_URL || <the RAILWAY_TCP_PROXY_* composition> (backfill-supplier-invoice-number.mjs:36-42; backfill-product-aliases.mjs has the same railwayParts pattern after APPLY = argv.includes('--apply')). Under 'railway run --service postgres', DATABASE_URL is the INTERNAL host, so both fail with ENOTFOUND from the PC. They never reach a wrong database; they're just unusable. Fix: resolveDatabaseUrl(env, { requireProxy: true }), the writer rule from B768 (#1297; reports use the default mode). No owner yet.
