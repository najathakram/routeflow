## Reported evidence

Latent, same business only: since #4222 (B1106 PR B) an OPERATOR or TENANT_ADMIN order create proves that dto.routeRunId and dto.routeRunStopId each belong to the caller's business (assertStaffRunStopRefs), but not that the stop is a stop OF that run. The DRIVER branch refuses a mismatch (orders.service.ts:1316, 'Stop does not belong to the supplied route run'); the staff branch does not, and the link write at :2038-2046 stores both ids as given. Repro (not run; read from the merged code): staff create with routeRunId = run A and routeRunStopId = a stop of run B, both in the same business, gives an order whose routeRunId and routeRunStopId point at two different runs. No cross-business exposure (each id is tenant-proven). Filed from review-b's nit on #4222; fix is one same-run comparison in assertStaffRunStopRefs next to the existing proof, plus a row in orders.create-run-stop-refs.spec.ts.
