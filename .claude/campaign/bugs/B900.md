## Reported evidence

The quote service picks the TIER-versus-BASE price label with `tierForProduct > 1`, where tierForProduct = tierByProduct.get(productId) ?? customer.pricingTier (line 371). The shared rule elsewhere is `!== 1`, and the two disagree on a null or 0 tier: `> 1` reads it as BASE, `!== 1` reads it as a special tier. The null/0-tier semantics must be decided (owner/lead call), then the label routed through isSpecialTier from @routeflow/pricing so there is one definition. Until then it is allow-listed in #2751's no-mirrors pin. Source: SA-588c, board #2554 comment 5893065870. Money-adjacent (price label); test tenants only.
