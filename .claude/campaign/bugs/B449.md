## Summary

A Strix (v1.6.2) automated security scan against the OpenAPI-enumerated attack surface (local-assets/security/strix_runs-2026-09-16/openapi_515f/findings.sarif) reported 4 coverage-only findings (level: none, rules strix-coverage/*) where the assigned specialist agent ran out of budget or could not obtain an auth token before dynamic testing began: (1) mass assignment on tenantId/role/isAdmin/creditLimit via POST/PATCH /api/v1/customers, (2) SQL injection on search/filter params across GET /customers, /orders, /products, /invoices, (3) financial-total manipulation (negative amounts, discount abuse) across POST/PATCH invoices, orders, credit-notes, estimates, vendor-bills, (4) mass assignment on totalAmount/subtotal/taxAmount/status/tenantId via POST/PATCH /api/v1/orders. This is a REVIEW task, not a confirmed vulnerability -- no exploit was attempted or demonstrated against any of these surfaces; the row exists to track that these 4 areas still need a real security pass (manual or a re-run scan with budget to complete dynamic testing).
