## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** A failed mutation surfaces the server's specific validation messages legibly, so the user knows what to fix.

**Actually does.** The validation pipe always returns message as a string array; the global error handler passes it unguarded into the toast title, and React renders the array's strings back to back with no separator.

**The gap.** With two or more failing constraints the toast is an unpunctuated wall of text; only single-message 400s read correctly.

**Evidence.** Evidence · apps/api/src/main.ts:180-186 (ValidationPipe with no exceptionFactory, so the default flattener always produces an array); apps/web/app/providers.tsx:37-38 (the message is passed straight into toast({ title }) with no Array.isArray check); packages/ui/src/web/Toast.tsx:106-108 (rendered raw); the same unguarded shape at apps/web/app/(dashboard)/drivers/_components/AddDriverModal.tsx:77-80 and apps/web/components/InlineCreateSupplierModal.tsx:95-101; the correct counter-example is apps/web/app/buyer/portal/[seller]/payments/_components/MakePaymentPanel.tsx:41-45, which joins the array.

**Suggested fix (register).** Normalize once at the boundary with a shared apiErrorMessage(err) helper that joins arrays (or renders them as a list) and call it from the global mutation error handler plus the two component-local copies; optionally have Toast accept a ReactNode and render a list for multi-message errors.

> ⚠️ Treat this as a hypothesis, not a plan. On F11 the adversarial pass refuted the
> suggested fix for every one of the four bugs while confirming every diagnosis.

**Verifier's note.** One sub-claim refuted and excluded: "no field attribution" is wrong — NestJS prepends the property path, so each message names its own field; the defect is purely the missing separator. The single-constraint 400, by far the common case, renders as one clean sentence, and most web forms validate client-side before the request goes out. A cosmetic legibility defect with a one-line fix.
