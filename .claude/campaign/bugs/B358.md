# B358 · Mobile Google OAuth deep-link creates a session from URL params without PKCE or state (F12-005)

**Location** `Auth · mobile (Google OAuth deep-link)` · **Severity** medium · **Batch** F48 · **State** queued

## Summary

_Not yet analysed._

## What this feature is for

_Not yet analysed._

## Root cause

Callback trusts tokens in routeflow:// query params; no state bound to the initiating device, no PKCE.

## User impact

A crafted link or another app registered for the scheme can inject or intercept a session on the device.

## Fix approach and UX

Move mobile OAuth to the exchange-code handoff used on web with PKCE verifier/challenge and a state nonce in SecureStore; callback exchanges the code server-side; any tokens in URL params are ignored. Cross-ref B349.

## Test plan

T1 pure-logic tests in apps/mobile/__tests__: state mismatch rejected, missing verifier rejected, URL-param tokens ignored; API spec: exchange requires the verifier.

## Reported evidence

The routeflow:// callback accepts tokens from query params with no device-bound state nonce and no PKCE. Expected: exchange-code handoff (as web, F8-001) with PKCE + state kept in SecureStore; URL tokens ignored. Cross-ref B349 (unsigned OAuth link state) — adjacent, not duplicate.
