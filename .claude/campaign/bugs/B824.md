## Root cause

Seen by F2 on the mini, 2026-09-23: the full test:db at #1310's 1c615285 was 40/41 suites, with 6 failures all in publish-and-repin.db.spec.ts (D5 'confirmation text did not match' expected, got empty stderr; D6/K3 exit expected 0, got 3; D7/D9 +12 unexpected rows). The same file ALONE at the same sha: 13/13 PASS twice. Mechanism (Mac Lead, from the log plus the script): exit 3 with EMPTY stderr is the --only-test-tenants refusal (~:880-890), which reports via say() on STDOUT and refuses when ANY applicable loss in the WHOLE DB targets a non-test slug. So under --maxWorkers=2 another DB spec's non-test-slug tenant with plan losses was alive at that moment. The spec's docstring claims robustness to other tenants, but this refusal is DB-global. Fix options: scope the spec's --apply to its own tenants (a --tenant filter), have every DB spec create only test-pattern slugs (qa-*/e2e-*) and assert that in a shared helper, or mark this file serial (runInBand / its own jest project). Also consider printing the refusal on stderr. Owner: unassigned; the fleet lead routes it.
