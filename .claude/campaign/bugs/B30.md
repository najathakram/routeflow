## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** A typo'd delivery/dispatch date should be caught and explained so the operator can fix it before sending or dispatching.

**Actually does.** In trips/new.tsx (Deliveries "Send" flow) an invalid date disables the Send button AND shows an inline warning "Use the YYYY-MM-DD format, e.g. …". In routes/[id].tsx (route-run "Dispatch" modal) the date field has no client-side validation at all — the Dispatch button stays enabled regardless of the date, and a bad value is submitted and reported via a toast (onError) from the server's rejection.

**Evidence.** Evidence · apps/mobile/app/(operator)/trips/new.tsx:52,171-178,420-436,472-473 (ISO_DATE_RE gates canSubmit + explicit inline warning); apps/mobile/app/(operator)/routes/[id].tsx:152-166 (handleDispatchConfirm has onError toast, no dateValid check), :465-474 (free-text date field, no validation wired), :491-505 (Dispatch button disabled only by createRunMut.isPending).
