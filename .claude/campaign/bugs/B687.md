## Reported evidence

Both #1221 (return-axis fix) and #1219 (credit-note fix) are independently proven with red-first cases, and S-order's independent review confirmed the merge by content-identity against the true shared ancestors rather than by hunk count. But none of the six new tests across both PRs combines a return reversal and a credit-note reversal on the SAME order line. The reviewer accepted this as non-blocking on a structural argument: the per-order-line remaining aggregation is source-agnostic and additive, so the two reversal kinds net correctly by construction. That argument is sound, but it is verified by reading, not by execution -- the thing that would notice it ceasing to hold (a future refactor of the aggregation, for instance) is a test that does not exist. Fix direction: a DB-lane test (per B685, DB-lane tests are the right home for a real-transaction composition case like this) that books a sale, applies both a partial return AND a partial credit note against the same line, and asserts the aggregated remaining/regulated-filing figures are correct -- converting the accepted structural argument into an executable proof rather than leaving it as prose in a PR review. Filed as non-blocking per the reviewer and the fleet lead -- both #1221 and #1219 ship without it. Fast-follow, not release-blocking. Filed per the fleet lead's request.
