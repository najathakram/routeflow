## Reported evidence

The wedge-scan keydown effect depends on [inputRef, onScan] and calls the onScan prop directly. Every consumer passes a fresh inline arrow, so each keystroke into a controlled input re-renders the parent, tears the listener down and resets the sequence; sequence.length >= 6 can never be reached, so a real wedge scanner never reaches onScan on any of the 12 consumers (inventory, invoices new/edit, products, vendor-bills, StockCountTab, ...). Every scan falls through to the field's manual Enter path instead. Pre-existing on master. The same file's camera path already uses onScanRef for exactly this reason. Becomes money-adjacent in #982, where the manual path consumes the typed Qty. Found by S-order with a deterministic RTL repro; fix PR coming. #982 stays not accepted until B672 lands and #982's wedge test asserts exactly +1.
