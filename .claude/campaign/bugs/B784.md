## Root cause

Filed at the fleet lead's request (found by R-ui during B777), RE-SCOPED on verification against origin/master 2ed80789. The reported premise — editing an invoice silently drops a units_v1 line's unitLabel and its unit axis — is FALSE on master: InvoicesService.update() refuses a payload that requests a unit (:3344) and, whenever items/discount/shippingFee change, calls unitAware.assertInvoiceRewriteAllowed (:3350-3354; orders/unit-aware-guard.ts ~:130), which re-reads the invoice's STORED items and linked order lines and throws 409 UNIT_AWARE_LINE before the delete-and-recreate at :3498 — for any client. No money, excise or label change is possible. The web edit page also fails closed up front (invoices/[id]/edit/page.tsx:593-609, B641 banner via lib/invoice-line-unit.ts). WHAT IS REAL (low, UX): the MOBILE edit screen has no equivalent guard (only DRAFT-status and order-mirror guards, edit.tsx ~:410-426), and invoiceLineDto / BuilderInvoiceLine (invoice-totals.ts:111-159) have no unitLabel field — so a mobile operator can open and edit a units_v1 invoice and only learns on Save, via the 409. Fix: mirror web's B641 fail-closed banner on the mobile edit screen (hasUnitLine / unitLabelsOf). units_v1 is test-only in prod today.
