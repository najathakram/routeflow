## Reported evidence

Independent Opus review of merged PR #913 (bebe66af): the tenant self-serve SubscriptionMutationService.enableAddon path (any OPERATOR) still has no requires check at all, and its invalidate call only clears entitlements, never featureResolver -- same stale-cache class B524 fixed elsewhere. PR #913's own code-map entry already discloses it as 'currently unreachable' (no requires-bearing row has billing.skus yet) -- but that is a property of today's routing/catalog data, not of the code, and will expire silently the moment a requires-bearing row gets a SKU. Needs its own id so it isn't lost.
