# B744 · Delayed scanner refocus (setTimeout focus 0-50ms) steals keystrokes from a line note being typed right after adding or scanning a line

## Root cause

Named by the fleet lead as B742's mechanism on master: the add path schedules `setTimeout(() => productSearchRef.current?.focus(), 50)` to re-arm the barcode wedge; typing a line note within that window loses the remaining keystrokes to the search box. Class sites on master bc7b0ad9: CreateOrderModal.tsx:569, :631, :942; estimates/page.tsx:228, :261; vendor-bills/page.tsx:510, :535; invoices/new/page.tsx:942. Structural fix candidate: refocus only when no text field holds focus.

## User impact

Real-world impact (Lane IR, confirmed by the fleet lead): the stolen focus lands in the product search box; since #1261 Enter is an ordinary keystroke inside a multi-line note, so the next Enter submits the half-typed search as a scanned code and opens a phantom 'create product' modal. Fix shape (lead ruling): ONE shared refocus helper used by all 8 sites, not 8 local edits.
