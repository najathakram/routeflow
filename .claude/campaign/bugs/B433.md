## Reported evidence

Verified against master d69f3094: momAgg = this.prisma.billingEvent.aggregate({ _sum: { amountDelta: true }, where: { createdAt: { gte: monthAgo } } }) sums EVERY billingEvent in the trailing 30 days with no filter distinguishing organic MRR movement (new subs, real price changes, churn) from one-time reconciliation/backfill corrections (e.g. reconcilePriceLedger's PLAN_CHANGED emission, or updateTenantPriceOverride's backfillBase emission -- see the sibling rows filed alongside this one). If a reconciliation backfill runs and emits amountDelta events correcting historically-null basePriceSnapshot values, momDelta reports that one-time correction as real month-over-month growth, inflating the momentum figure shown to whoever reads MRR reporting. Fix: tag reconciliation/backfill-sourced billing events distinctly (a payload field or event subtype) and exclude them from momDelta's window, or report them as a separate 'reconciliation' line rather than folding them into organic growth.
