## Root cause

CONFIRMED ROOT CAUSE (found during #926's push, 2026-09-18) -- resolves the 'open question' above. campaign-check's log shows api.json, pricing.json and web.json each explicitly confirmed fresh ('campaign-check: <name>.json fresh (generated ...)') immediately before the final undischarged-claims gate runs. mobile.json is NEVER confirmed fresh anywhere in the run -- its only appearance in the log is 'mobile.json missing -- turbo will generate it -- continuing' at the very start, and nothing afterward confirms it was actually regenerated/read fresh before the gate checks it. All 30 flagged ids are apps/mobile/** files. Five were spot-checked as having real, correctly-titled tests in source: B34 (apps/mobile/__tests__/skip-stop.test.ts:34), B90 (run-lateness.test.ts:19,37), B203 (expo-file-system-pin.test.ts:17), plus B111 and B128. So the gate is not wrong about the registry -- it cannot see mobile.json's test report at all, and is checking a report that was never confirmed fresh (or possibly never populated) for that workspace. This is a genuine repo-wide registry/test-title mismatch caused by a workspace-freshness gap in campaign-check itself, not branch/environment skew on any one PR's branch. Cost: forced the audited SKIP_VERIFY bypass on four separate pushes today across unrelated branches -- the highest cost-per-day tooling defect on the board today despite looking like registry noise.
