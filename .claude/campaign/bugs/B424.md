## Reported evidence

By design (per the code's own comments and RULINGS.md R1, mobile scan-to-order hunt): the staged-edit snapshot is a KEYSPACE (one key per order, rf.edit-items.v1:<userId|anon>:<orderId>) written directly to AsyncStorage, not through lib/user-scoped-storage.ts's clearUserScopedStorage helper used by the zustand-persisted stores -- because that module imports AsyncStorage at the top level, which edit-items-draft.ts 'may not' (unstated bundling/import-cycle constraint, never verified). Sign-out cleanup is therefore a bespoke getAllKeys() prefix-sweep in session-teardown.ts instead of the standard one-call helper -- a second cleanup mechanism to keep in sync with the standard one, and a second place the B136/B137/B140 class of cross-user leak could reappear if either drifts. Follow-up: migrate to a user-scoped persist store (resolve or route around the stated import-cycle constraint) so this snapshot uses the same one cleanup mechanism as every other persisted store.
