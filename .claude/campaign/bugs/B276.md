## Reported evidence

F16b/B100 cause refutation + engine final pass, 2026-09-08: the list endpoint's validSortFields map (invoices.service.ts:2873-2882) points the user-facing "invoiceNumber" sort straight at the invoiceNumber column, which schema.prisma types as plain text - the same lexicographic ordering B100 diagnosed as the root cause of the 9999 mint wall now also skews the READ side once F16b's fix lets series pass 10000: "INV-2026-10000" sorts before "INV-2026-9999" ("1" < "9" at the first differing character), so an operator sorting the invoice list by number sees newer five-digit invoices interleaved ahead of older four-digit ones instead of in creation order. Needs either a numeric sort key derived from the suffix or a padded/fixed-width invariant enforced at mint time.
