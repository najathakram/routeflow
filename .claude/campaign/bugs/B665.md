## Reported evidence

returns-restock.util.ts (~31-46) adds the RAW ReturnItem.qty to currentStock and to the stockMovement (quantity: qty; stockAfter: currentStock.add(qty)); the Mac Lead read it and the filer re-read it on origin/master. STANDARD returns store what the operator typed, in the order line's OWN unit (pieces for a box-aware line, BOXES for a box-unaware one), and returns-pieces.util.ts claims 'OrderItem.qty is ALWAYS stored as total PIECES', which is false for box-unaware lines (see B647 and B658). So restocking a box-unaware return adds boxes to a stock counted in pieces: 12x too few. UNVERIFIED UPSTREAM PREMISE, stated exactly: that the operator/returns UI types the return in the line's own stored unit for a box-unaware line is R-ui's trace, NOT run; if the UI converts to pieces first this defect does not occur on the standard path. Related: B660 (the ledger side, inline path only). Severity: the lead said MEDIUM-HIGH; the tool has no in-between, so it is filed as medium and can be raised. HOW KNOWN: code-read only; NEVER RUN.
