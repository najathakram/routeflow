## Reported evidence

SA-batch-0751 section 1: the per-line update branch skips a non-positive quantity for every existing line, delivered or not, so { id, qty: 0 } resolves 200 and changes nothing. Money-wise safe, but as UX the save ignores the person. Proposed: a coded 400 that points to Remove. Before any change the builder lists every client that can emit qty 0 on an existing line (web order builder, mobile shell, buyer edit, change-request apply, offline replay): a client that sends 0 for an untouched line would start failing.
