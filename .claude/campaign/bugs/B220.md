## Reported evidence

F08's billed-basis refund (B53) prices every return from the order's creditable invoice items, but a return on an order that was only PARTIALLY delivered and invoiced on the delivered basis has no way to know how much of the billed qty was actually delivered vs still owed -- a correct fix needs a nullable ReturnItem.deliveredQty column (schema migration) persisted in create() and consumed by billedBasisFor: refundQty = deliveredQty != null ? min(returnedQty, max(0, billedQty - deliveredQty)) : min(returnedQty, billedQty). This composition (cause-ruling.md S2 Amendment 2, B53xB128) was dropped from #645 by lead ruling -- no schema change in that wave -- and is owed as its own migration-bearing PR. The 'derive it from OrderItem.deliveredQty instead of a new column' shortcut is REJECTED: OrderItem.deliveredQty is written only by completeStop/completeWithPayment and is not scoped per return, so deriving from it would zero every post-delivery return on a delivered-basis invoice, including ones that never had this bug.
