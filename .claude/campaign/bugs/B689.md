## Reported evidence

On a RECEIVED PO's boxed line (12/box, cost $12/box), editing cost to $11/box, Save, then choosing 'Keep stock as is' on the re-apply-to-inventory prompt closes the modal as if the edit succeeded -- no toast, no error. A PATCH IS sent with the new shape (caseCost:11, cases:5, loosePieces:0), but a DB read-back shows PurchaseOrderItem.unitCost is still 1.0000 and totalCost still 60.00 -- the write silently did not persist. Re-opening the PO shows the stale $12. PO cost feeds inventory valuation, so this is a silent-money bug: the UI and the operator believe the cost was corrected, and nothing downstream is told otherwise. Found by Mac F2 during the Release 1 RC proof, confirmed by direct DB read-back on a test tenant -- symptom-only with DB evidence, cause not traced (F2 did not trace into the surface). Live in production since #1210 merged 10:30Z and deployed 10:32Z. Disposition: fast-follow, not release-blocking -- explicitly not fixed same-day per the lead's ruling (an untraced cause plus a ~90 minute gate is how #1207 got a defect into production this morning; not repeating that shape twice in one release).
