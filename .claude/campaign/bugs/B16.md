## Reported evidence

_Imported verbatim from the bug register — this is the ORIGINAL report, not analysis._

**Meant to do.** The Expired filter/KPI chip should let operators find estimates whose validity date has passed.

**Actually does.** EstimateStatus has no EXPIRED value and nothing sets it; selecting it sends status=EXPIRED straight into an unvalidated Prisma `where.status`.

**The gap.** No estimate can ever be surfaced this way — the option is permanently dead and never returns real results.

**Evidence.** Evidence · apps/api/prisma/schema.prisma:235-241 (enum, no EXPIRED); apps/web/app/(dashboard)/estimates/page.tsx:86,780-789 (option+chip); apps/api/src/estimates/estimates.service.ts:156 (`if (status) where.status = status;`)

**Suggested fix (register).** Remove the EXPIRED option/chip (and the [id]/page.tsx "has expired" branch) until a real EXPIRED status is computed from expiresAt.
