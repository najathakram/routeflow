# B810 · Driver payment screen shows the ORDER total as the amount to collect when the order's earlier invoice is SENT or PARTIAL (no open draft), not the remaining balance

**Location** `apps/mobile/lib/run-money.ts:189-213 (orderAmountDue) · apps/api/src/routes/routes.constants.ts:80-81 (run read projects DRAFT invoices only)` · **Severity** medium · **State** uncampaigned

## Root cause

SA-122 filing (fleet lead relay, 2026-09-23), pre-existing product/UX. Verified on origin/master 22fcee22. The run read projects only invoices with status DRAFT and deliveryBatchId null (routes.constants.ts:80-81). orderAmountDue (run-money.ts:189) sums those drafts' totals and, when there are none, falls back to the order's own subtotal/total (:198-213). For a stop order whose earlier invoice is SENT or PARTIAL there's no open draft, so the door 'amount to collect' shows the ORDER total rather than the REMAINING payable balance. The server applies only the balance and books any surplus as an advance, so the money stays correct, but the driver is told to collect more than is owed. Fix (per the SA): a SERVER projection on the run read giving the per-order remaining payable balance, consumed by orderAmountDue. NEVER a client total-minus-payments computation (the B305 rule). Owner: unowned, pending owner priority.
