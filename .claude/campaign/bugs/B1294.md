## Reported evidence

The scan is /padding[^;{}]*\(100%\s*-[^;{}]*\)\s*\/\s*2/ over public/site/css and public/site/graphics. It misses: "( 100% - 1200px ) / 2" (a space after the opening parenthesis), calc(50% - 600px) (the same half-gap), a custom property holding the half-gap then padding:var(--g), and any stylesheet outside the two folders. A percentage padding resolves against the parent width, so on a wide screen it squeezes a centred card into a narrow strip (the bug #4234 fixed for the founder card and the no-JS hero). Today no site CSS uses any of these spellings (review-b grepped all site CSS and the one inline style in landing.html). Found on #4234 at 39a48689a5 (review-b note 1, LOW); shipped in 7b36e3a630. Fix: normalise whitespace first, match padding[^;{}]*(\(\s*100%\s*-[^)]*\)\s*\/\s*2|50%\s*-\s*\d) and the same for a custom property used in a padding, and walk public/site recursively. Nit with it: the hero and founder rules each restate .w min(1200px,100% - 48px), three copies; a shared custom property would keep them together. Source: #4234 review-b, bookkeeping 2026-11-07.
