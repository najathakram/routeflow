# B745 · Dockerfiles copy packages/* selectively before npm ci; a new workspace (packages/returns, #1262) is missing, so the postinstall build fails and every api/web/mobile deploy fails

**Location** `apps/api/Dockerfile · apps/web/Dockerfile · apps/mobile/Dockerfile` · **Severity** critical · **State** uncampaigned

## Summary

Registry reconcile 2026-09-24 (Mac Lead, owner ask via the fleet lead): verified FIXED on origin/master by #1268. Dockerfiles now copy packages/returns and packages/types before npm ci, directly fixing the postinstall build failure from the missing workspace.

_Not yet analysed._

## Root cause

#1262 (f894d974) added the packages/returns workspace and extended the root postinstall to build @routeflow/returns. apps/{api,web,mobile}/Dockerfile copy packages/* manifests selectively before npm ci and none copies packages/returns, so npm ci fails: 'No workspaces found: --workspace=@routeflow/returns'. Evidence: GitHub deployment for f894d974 'routeflow / production' state=failure at 00:41:09Z; prod stuck at cb88378f (#1261). Reproduced locally: compose web build at bc7b0ad9 fails at npm ci. Class: a hand-maintained COPY allow-list drifts from the workspace list; guard candidate = a repo-truth spec asserting every packages/* dir is copied by each Dockerfile. Fix owner: Lane B (fleet lead assignment 2026-09-23).

## User impact

_Not yet analysed._

## Fix approach and UX

Guard correction (fleet lead, from Lane B's repro): full-copy set = postinstall-built packages (pricing, returns) PLUS the transitive closure of their workspace imports (today: types — returns imports @routeflow/types and its tsc runs at postinstall; a manifest-only copy fails TS2307 'Cannot find module @routeflow/types'). Derive the set from ACTUAL imports, not declared dependencies. Lesson: a hand-maintained copy list drifts the first time a build-time package gains an import; the guard must compute the set, never restate it.
