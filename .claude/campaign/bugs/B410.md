## Reported evidence

suspendOverdueTenants() filters stripeSubId: { not: null }; the self-serve model never sets it, so every self-serve tenant is structurally invisible to the suspension cron. TenantSubscription.failedPaymentCount and .nextChargeAt are DEAD columns -- zero reads/writes for the former, never persisted for the latter. Owner ruling: the first five customers are free pilots, so 'non-payers are never auto-suspended' is current POLICY (see B327), not a defect. Never close this by dropping the filter -- that would suspend tenants who were never charged. The charge loop must CREATE a non-payment signal, not start reading one. Its grace constant is a local PAYMENT_GRACE_DAYS = 3, not the GRACE_DAYS = 7 in plan-catalog.constants.ts, which belongs to an unrelated soft-cap meter.
