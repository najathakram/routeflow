### #781's NEW-1 — recommended pre-merge fix (one line)

`apps/api/src/customers/customers.service.ts`, `deleteCustomer` — the soft-delete branch is **not
idempotent**: calling it twice on the same customer re-appends the `~removed~<id8>` suffix to an
already-tombstoned username (`acme~removed~cust1234~removed~cust1234`), and `restoreCustomer`
only strips one suffix, so the second delete permanently mangles the login identity with no error
and no way to recover it automatically. **Newly reachable from this PR's own UI**: the trash
view's bulk-select bar (`apps/web/app/(dashboard)/customers/page.tsx`, `selectMode` / the bar
around line 487/777) is not gated on `removedFilter`, so an operator can filter to Removed →
select an already-removed customer → hit Delete again. Fix: early-return (or no-op) in
`deleteCustomer` when `customer.deletedAt` is already set. The full review (in the task
notification, not saved to a file — re-run the review agent or ask the lead's session history if
detail beyond this summary is needed) also flags **NEW-2** (Merge is reachable on removed
customers from the same ungated bulk-select bar, and `mergeCustomers` has no `deletedAt` guard —
medium, money-adjacent since it re-points advance-payment wallets) as a same-priority follow-up if
NEW-1 gets fixed inline.
