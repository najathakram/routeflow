# PROOF-REQ — units 5b: "Sell by" unit picker in the create-order modal (draft for the Mac prover)

Post on #938 as `[U-units@pc] PROOF-REQ — <PR> @<sha>` only AFTER the branch is pushed (needs a real sha).

**Surface**: Orders -> "New order" modal (`CreateOrderModal`), staff/operator session on an approved test tenant
(`qa-*` / `e2e-*` / `ux-audit-*`; never a live tenant). Fixture: one product with a pack (e.g. Box of 24, $42) and a
ProductUnit ladder (Case = 288 pcs, explicit $480; Pallet = 5760 pcs, derived; optional tier-2 pack price so a tier-2
customer exists). Customers: one tier 1, one tier 2. Widths: **1440, 768, 390**. Run everything with `flag.units_v1`
**ON**, then the flag-OFF block.

## Flag ON — states (each at 1440 / 768 / 390)

1. **No levels**: a product with no ProductUnit rows shows NO picker; the row is byte-identical to today.
2. **Picker present**: product with levels -> a "Sell <name> by" select under the price block; options read
   `Box · 24 pcs · $42.00` / `Case · 288 pcs · $480.00` / `Pallet · 5760 pcs · $10,080.00` (piece count has no thousands
   separator, money does) / `Piece · $1.75`; default = the pack.
3. **Switch pack -> Case**: row becomes a plain quantity line: qty 1, "$480.00 / Case", NO boxes/pieces inputs and NO
   Case|Unit toggle, line total $480.00; qty stepper +/- moves by 1 Case; total = qty x $480.
4. **Switch Case -> Pallet -> back to Box**: Pallet price = 42 x 5760 / 24 = $10,080.00; choosing Box again restores the
   original case-packed line exactly (1 box, 24 pcs, price, any one-time price you set before switching).
5. **Tier**: pick the tier-2 customer -> a Case line re-prices to the tier ladder price ($240.00 with the fixture) and keeps its
   typed qty; the price shows as a special (tier) price; change customer back -> $480.00.
6. **One-time price on a unit line**: typing a price below $480 marks it discounted, above marks it an upsell (the compare is
   against the Case tier-1 price, not the pack's $42); clearing it returns to the ladder price, never the pack price.
7. **Re-key (productId + unit)**: with a Case line present, scan/add the same product again -> a SEPARATE pack line appears
   (does NOT bump the Case qty); then switch that pack line to Case -> the two fold into ONE Case line with summed qty.
8. **Save as draft / create**: request body line = `{ productId, qty: <count>, unitLabel: "Case" }` — NO boxes, pieces;
   `unitPrice` present ONLY for a typed one-time price. Confirm in the network tab. The saved order shows a Case line at
   the ladder price (server-priced), stock decrement in base pieces (qty x 288) — check the product's stock.
9. **Guards/edges**: the picker never appears on a custom (unlisted) line; changing a line's product resets its unit;
   at 390 the select and price block do not overflow or clip, no horizontal page scroll.

## Flag OFF (tenant without flag.units_v1)

10. No picker on ANY line, no `unitLabel` in any request, and no request to `/products/:id/units` from the modal. A repeat
    add / scan still behaves as before (bumps the same line).

## A PASS must show

Screenshots of states 2, 3, 5, 6, 7 and 10 at each of the 3 widths, the request body of state 8, no console errors,
no layout overflow at 390, and the pack line restored byte-for-byte in state 4.
