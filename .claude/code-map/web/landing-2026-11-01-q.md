## #4065 `55a707eb5a` a plain line follows the customer in the default builder (SA-1076, SA-1068 M27)

Rule: the customer's price applies at once to every line whose price is still the auto-derived tier price, in the default builder as well as with `scan_v2` on. A price a person typed, an upsell, a history-prefilled one-time price, an unlisted line and a unit line (priced by its own picker) stand.

- `app/(dashboard)/orders/_components/CreateOrderModal.tsx`:
  - The re-price effect no longer branches on `scanV2` (it left `scanV2` out of its deps): the two classic-modal early returns are gone, so a line added before the customer was chosen, or priced for another customer, re-prices to the new customer's memory / tier / product-tier row / layer. A line still waits while a resume re-prices (`!fromOtherCustomer && resuming`, SA-1068 M28); a price pre-filled from ANOTHER customer's history still drops to a plain line (B755). The re-priced line no longer rewrites `prefillCustomerId`.
  - `prefillCustomerId` is set only when the line carries a history override (`hasHistOverride`), never for a plain remembered price (M26/M27 linking is removed); the chip-x reset sets it `undefined`.
  - `customerPricesRead = useCustomerPrices(...)` is kept whole (not just `data`) and fed, with `priceLayer` and the picked customer, to `customerPricingGate` (`@/lib/customer-pricing-gate`, re-exported from `@routeflow/pricing`): `resumePricesReady = priceLayer.ready && !pricingGate.pending && !priceHistoryRead.isPending` (A-1: a plan without customer prices is an empty read, not a failure).
  - Resume reprice: a settled history read with no data, or `pricingGate.readFailed`, sets `pricesNotRefreshed` and keeps the lines as parked (A-4). The product read can land after a customer change, so `repriceResumedLines` now prices from `pricingNowRef.current` (`tierForProduct`, `priceLayer`, `rememberedOf`) read inside the `setLineItems` updater, not from the effect's capture.
  - A-2: `historyUnknown` (customer picked, lines present, `priceHistory === undefined`, read not pending) shows the same `data-testid="prices-not-refreshed"` status as `pricesNotRefreshed`, since the server books what that read would have said.
  - W-1092: `onOrderAgain` calls `setLastPick(null)` first, so "Order again" (many lines, no single Undo) takes the last pick's Undo away.
- `packages/types/api/orders.ts`: doc comment only on `CustomerPriceHistory[productId].lastPrice` (see the api note).
- Tests (same folder): `CreateOrderModal.test.tsx` (the "flag OFF: the default builder follows the customer too" case replaces the old does-NOT-re-price one), `CreateOrderModal.price-layer.test.tsx` ("a line follows its customer", T1-T9, T13, T14), `CreateOrderModal.draft-resume.test.tsx` (a line parked at its customer's memory, T46/T47/T49/T55; "a resume on real reads", T18-T22, T27-T34), `CreateOrderModal.pending-unit.test.tsx` (T24), `CreateOrderModal.suggestions.test.tsx` (W-1092, two cases).
