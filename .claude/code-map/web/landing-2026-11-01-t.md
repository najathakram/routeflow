## #4078 `f7b446e0ab` the customers list prints Open balance through the statement button (SA-1078 / W-1096 PR-5)

Rule: the customers list figure is the statement's Open balance and opens the same sheet; a person without access sees the plain figure (the `OpenBalanceButton` rule from train s).

- `lib/api/customers.ts`: `Customer.receivables?` is renamed `openBalance?` (the api list rows carry `openBalance` and no longer `receivables`). The local `Customer` in `app/(dashboard)/customers/page.tsx` follows.
- `app/(dashboard)/customers/page.tsx`: the column keeps `id: "receivables"` and its `SortHeader col="receivables"` (the server still sorts newest first; filed LATER) but the header reads "Open balance". The cell is the module-level component `OpenBalanceCell({ row })` (`flexRender` mounts a cell function as a component, so an inline `cell:` closure rebuilt with `columns` was a new component type each render and remounted the button, dropping the open sheet; L11). It renders `<OpenBalanceButton customerId={row.original.id}>{fmt(balance)}</OpenBalanceButton>` inside a `data-testid="open-balance-cell"` span (was `receivables-cell`; red when balance > 0). Imports `Row` from `@tanstack/react-table`.
- `components/account-statement/AccountStatementSheet.tsx`: on close of a sheet that loaded, it also invalidates every `["customers", <non-string>]` query (the list is keyed `["customers", params]`), so the list shows the fresh figure (L9). The `?statement=<id>` reload and close behaviour (keeps `?page=2`, drops only `statement`) is covered by L11 rows.
- Tests: `app/(dashboard)/customers/page.ux-list.test.tsx` (L6 tap opens the statement not the customer, L7 header, L11 reload stays open / early tap survives re-render / close keeps `?page=2`), `components/account-statement/AccountStatementSheet.test.tsx` (L9: list query read again after a loaded close, a sheet that never loaded refreshes nothing), `lib/open-balance-surfaces.static.test.ts` (adds the customers list surface, pinned inside `OpenBalanceButton`), `e2e/65-customers-list-ux.spec.ts` (fixtures set `openBalance`; test id `open-balance-cell`; header name `/open balance/i`).

## #4086 `5e7c47acc2` buyer portal Outstanding card opens the statement (SA-1078 / W-1096 PR-6)

- `components/account-statement/BuyerOpenBalanceButton.tsx` (new): `BuyerOpenBalanceButton({ children, hint?, className? })`, the buyer twin of `OpenBalanceButton` (`data-testid="open-balance-button"`, `aria-haspopup="dialog"`, min 44 px tap target on small screens). Opens `BuyerStatementSheet` over `GET /buyer/account-statement`; Print is the only action (no Email), invoice numbers are plain text (`linkInvoices={false}`), and nothing touches the staff client. It reads nothing until tapped. On close of a loaded sheet it invalidates the `["buyer","statement"]` family except its own key and drops its own query, so the Outstanding card behind it is fresh and a reopen reads again. No `?statement=` URL param for the buyer.
- `components/account-statement/AccountStatementSheet.tsx`: the frame is split out. New exports `StatementRead { data?, isError, refetch }` and `StatementSheetFrame({ open, onClose, query, linkInvoices, footer })` (back-to-close, focus hand-back, the footer only when there is a statement). `AccountStatementSheet` (staff) now renders the frame with the Email then Print footer; behaviour unchanged. Invoice link class changed to `max-sm:items-start` (tap target kept).
- `components/account-statement/StatementPrintButton.tsx`: new `StatementPrintControl({ getUrl: () => Promise<string>, client: AxiosInstance })`, the shared print logic (desktop downloads the bytes through `client` and prints; touch or shell gets "Print or share" then "Open PDF"). `StatementPrintButton({ customerId })` is now a thin wrapper (staff `fetchAccountStatementPdfUrl` + `apiClient`).
- `lib/api/buyer.ts`: `buyerAccountStatementKey` = `["buyer","statement","account"]` (extends the Outstanding card's `["buyer","statement"]`, so a payment's invalidation reaches it by prefix), `useBuyerAccountStatement(enabled = true)` (`GET /buyer/account-statement`), `fetchBuyerAccountStatementPdfUrl(): Promise<string>` (`GET /buyer/account-statement/pdf`, the `url` of `{ url }`). Imports `AccountStatement` from `@routeflow/types`.
- `app/buyer/portal/[seller]/payments/page.tsx`: the "Outstanding" `StatCard` value is `<BuyerOpenBalanceButton hint="View statement">{fmt(statement?.outstandingAmount ?? 0)}</BuyerOpenBalanceButton>`; the page-local `StatCard.value` type widens to `React.ReactNode`.
- Tests: `components/account-statement/BuyerOpenBalanceButton.test.tsx` (new: BP1 sheet opens with the figure to the cent, no GET while closed, never the staff client, plain invoice numbers, Esc returns focus, failed read says so with Try Again, reopen reads again, close refreshes the card; BP2 Print is the only action and goes through the buyer client, a failed print keeps the sheet), `AccountStatementSheet.test.tsx`, `lib/open-balance-surfaces.static.test.ts` (the buyer Payments page leaves `PLAIN_ON_PURPOSE`; surfaces gain an optional `tag` so its figure must sit inside `BuyerOpenBalanceButton`). Api side: `buyer/buyer-account-statement.authz.spec.ts`.
