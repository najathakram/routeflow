# Web landing, window 37 (master `495ea1cb18`)

Paths under `apps/web/` unless they start with another root; `app/(dashboard)/orders/_components/` is shortened to `OC/`. Api parts are in `api/landing-2026-11-12-w37.md`. Facts below were read on master `495ea1cb18`. #4306 touches no web file.

- **#4302 drag a line into any order in the order builder and at the counter (W-1187 PR-2b, head `15137041c9`; no request, no server change).** The cart is a local list and its array order is the order sent, so a move reorders the array. New `lib/cart-line-order.ts` (`orderByIds`, `moveLine`, `movedTitle`, `focusMoveHandle`), `lib/use-cart-line-order.ts` (`useCartLineOrder`: toast with Undo, one toast at a time, `afterMove`, and a `keyboardUndo` option that registers the Ctrl/Cmd+Z listener; the order builder uses it, the till passes `false`), `components/CartMovableList.tsx` (the list swap) and `components/CartRowMove.tsx` (`useCartRowMove`, the 44 px handle slot). `components/LineItemRow.tsx` takes an optional `moveId`; `OC/CounterLineRow.tsx`, `OC/CounterSaleScreen.tsx` and `OC/CreateOrderModal.tsx` change by wiring only.
  - `components/SortableLines.tsx` (shared with the saved order page and the buyer page) gets the scan-safety rules: Enter no longer picks up or drops (Space only); a printable key on a focused handle is a scan (with a `scanTarget` the code goes to that field; the order builder passes the product search box, the till passes none); during a keyboard move any key that is not Space, an arrow or Escape cancels it, but a modifier alone does not; `restoreFocus: false`, so a cancelled move does not pull focus back to the handle.
  - Round-2 fix: after the hand-over the handle dispatches a `keydown` copy of the first key on the scan field (`components/SortableLines.tsx:243`), so the field's own detector in `components/BarcodeScannerButton.tsx` hears it and the lookup is whole.
  - Tests: `components/SortableLines.scan-safe.test.tsx`, `lib/use-cart-line-order.test.tsx`, `lib/cart-line-order.test.ts`, `lib/counter-park.line-order.test.ts` (a parked sale keeps its dragged order), `OC/CounterSaleScreen.line-order.test.tsx`, `OC/CreateOrderModal.line-order.test.tsx`, and `OC/CreateOrderModal.scan-from-handle.test.tsx` (the real detector, a 13-digit code from handles 1 and 2 and from search; removing the dispatch turns two cells red).
  - Stated limits, open (see the register): at the till a code that starts with lowercase letters or punctuation, typed from a non-text focus, loses those letters (`OC/CounterSaleScreen.tsx:520-526` routes only digits and capitals); a keyboard move whose keys come under 10 ms apart is not kept (dnd-kit attaches its sensor one tick late); in the office, Escape during a keyboard move also closes Create Order (the draft is kept); Alt+Arrow moves one place and then the till refocuses the scan box.
- **#4305 the New sale invoice date is the order-date chip, worded "Sale date" (W-1188, head `0920c81ff4`).** New `lib/order-date-copy.ts`: `ORDER_DATE_COPY: Record<"order" | "sale", OrderDateCopy>` (whole strings per noun: chip name when Today, name while the day is unknown, clear name, dialog title, typed-day refusal). `OC/CounterDateChip.tsx` and `OC/CounterDatePicker.tsx` take an optional `noun` (default `"order"`, so the till and the regular order read as before). `app/(dashboard)/invoices/new/page.tsx`: in sale mode the issue-date input is `CounterDateChip noun="sale" policy="OFFICE"`; the form keeps a concrete day in state, so the chip's empty value maps to the tenant's today, and `handleIssueDateChange` stays the one path (it re-anchors the due date from the terms; a hand-typed due date survives). "Other charge" keeps its native "Issue Date" input. Clearing the chip now resets to today (the old native clear left the field blank).
