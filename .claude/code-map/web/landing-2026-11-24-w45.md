# Web landing, window 45 (master `effbbc8971`, PR #4450)

Paths under `apps/web/` unless they start with another root. Facts read in the merged diff and the files at `effbbc8971`. The shared planner is in `packages/landing-2026-11-24-w45.md`. Trust the code over this note.

- **#4450 create a supplier bill from a purchase order (SA-1207 P2b; `effbbc8971`).** The bill is built in the PO's own units (boxes, one lot, or pieces); money and unit come from `billPlanFromPO` in `@routeflow/pricing`, the web only maps rows.
  - `lib/po-prefill.ts` (new): `prefillBillFromPO(po)` returns `{ poId, poNumber, supplierId, rows, byHand, zeroCount }`; every PO line lands in exactly one of rows, `byHand` (named, never billed as a guess) or `zeroCount`. A line with no stored total is passed as NaN so it goes to hand entry. `billItemFromRow(row)` makes the create-bill payload line and carries `packSize` and `unitLabel`.
  - `app/(dashboard)/purchase-orders/[id]/po-detail-logic.ts`: `createBillAction(po, billsVisible)` returns the link `/vendor-bills?tab=inventory&fromPo=<id>` only for an ordered, not closed PO with no live (non-VOID) bill and where the plan shows bills; the label is "Bill what arrived so far" after a partial receive, else "Create supplier bill". `PurchaseOrderDetail.tsx` shows it as a link and as a "Received." strip after a successful receive (`PurchaseOrdersReceiveModal.tsx` gains an `onReceived` callback).
  - `app/(dashboard)/vendor-bills/page.tsx`: `CreateBillModal` takes `fromPo` (read with `usePurchaseOrder`), fills supplier, linked PO and rows once per open, lists the by-hand lines, and clears a row's `packSize` and `unitLabel` when its product changes. `lib/api/vendor-bills.ts`: `CreateVendorBillItem` gains optional `unitLabel`. No copy claims the bill equals the PO.
  - Tests: `lib/po-prefill.test.ts`, `PurchaseOrderDetail.test.tsx`, `vendor-bills/page.from-po.test.tsx`. API pins: `vendor-bills/po-bill-lines.spec.ts`, `vendor-bills.bill-line-unit.spec.ts` (a labelled 1-piece line PATCHed to a fractional lot gives 400 `LOT_QTY_NOT_WHOLE`).
