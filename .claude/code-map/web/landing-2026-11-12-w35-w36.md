# Web landing, windows 35 and 36 (master `d4abf05d02` after window 35, `a2208ae4f1` after window 36)

Paths under `apps/web/` unless they start with another root; `app/(dashboard)/orders/_components/` is shortened to `OC/`. Api parts are in `api/landing-2026-11-12-w35-w36.md`. Facts below were read on master `a2208ae4f1`. #4300, #4278 and #4299 touch no web file.

## Window 35

- **#4293 the regular order gets the date chip (W-1188 PR-3, head `1553f97674`).** `OC/CreateOrderModal.tsx`: the hidden "Backdate this order" link, the "Order date (optional)" input and "Use today" are replaced by `CounterDateChip` with `policy="OFFICE"`, capped on the tenant's today (`useTenantToday`, not the UTC day); the payload key `orderDate`, draft save and restore and the merge-block rule are unchanged. `OC/CounterDateChip.tsx` and `OC/CounterDatePicker.tsx` gain a `policy` prop (default COUNTER); OFFICE uses `orderDateRange(today, "OFFICE")` (no future days) and shows "A future day? Set the delivery date instead." `OC/ParkedSalesDialog.tsx` shows "Dated Fri, Nov 6" for a dated parked sale (none on a Today sale). `lib/counter-order-date.ts` gains `futureLimitWords` and `dateIfNotToday` (the one "Today means no date" rule); `lib/natural-date.ts` reads a two-digit year as 20xx and leaves the range check to the picker; `lib/counter-sale.ts` gains `COUNTER_ORDER_DATE_ZONE_FAILED_COPY`. `OC/CounterReceiptView.tsx` shows the sale day and entry time on a reprint of a dated sale. `packages/ui/src/web/Modal.tsx` gains the opt-in `onKeyDownCapture` prop (a key anywhere in the dialog, the header X included, seen before the focused control; the date picker uses it to hand a scanner's first key to the till). `OC/useCounterScanFocus.ts` returns a new `refocusAfterDialog` (re-arms the scan box at 0, 120 and 350 ms after a dialog closes, still never taking focus from a field being typed in). Tests: `OC/CreateOrderModal.backdate.test.tsx` (rewritten for the chip), `OC/CounterSaleScreen.date-scan.test.tsx`, `OC/CounterDateChip.test.tsx`, `OC/ParkedSalesDialog.total.test.tsx`, `OC/CounterReceiptView.dated.test.tsx`, `components/Modal.key-capture.test.tsx`, `components/field-id-consumers.test.tsx`; e2e `e2e/08-create-order-escape.spec.ts` and `e2e/56-create-order-dialog-mobile-pan.spec.ts` follow the removed `#order-date`.

## Window 36

- **#4301 date chip follow-ups (W-1188, head `df13ab2e13`).** Enter on any button inside the picker (the header X included) no longer bubbles out of the portal into the order form (`OC/CounterDatePicker.tsx`); a failed business-day read shows a "Try again" button next to the failed copy (`CounterDateReminder` in `OC/CounterDateChip.tsx` takes `onRetry` and `retrying`; the till passes `zoneRead.retry` and `zoneRead.isFetching` from `OC/CounterSaleScreen.tsx`; the button is `aria-disabled`, not `disabled`, while a retry runs; `lib/tenant-timezone.ts` `useTenantTimeZoneQuery` also returns `isFetching`). The chip's earlier "swallow the scan's Enter" guard is withdrawn: a person's Enter on the chip always opens the picker (pinned by C9 in `OC/CounterDateChip.test.tsx`). Stated limit: in the office, a scan right after Escape lands on the chip and its Enter reopens the picker (no date, no line); it goes away when office scans get a destination. Tests: C9, C10 (header X), C11 and `OC/CounterSaleScreen.park.test.tsx` R8, `OC/CounterSaleScreen.date-scan.test.tsx` T12.
- **#4303 a scan that starts while a dialog is closing is no longer lost at the till (head `cc0a8491a5`).** A closing Radix dialog stays mounted with `data-state="closed"` for its 150 ms exit animation and keeps focus in its text box; both guards read a focused text box as "a person is typing", so the keys died with the unmount. `lib/refocus-scanner.ts` gains the one predicate `insideClosingDialog(el)` (`[role="dialog"][data-state="closed"]`), read inside `isTextEntryElement`, which `scheduleScannerRefocus` and the till's `isTextEntryActive()` (the key redirect and the camera frame check) already go through. No timer, no key timing, no new `.focus()` owner. Tests: `lib/refocus-scanner.test.ts`; `OC/CounterSaleScreen.escape-scan.test.tsx` (picker, Change the price and New product cells at 0 to 200 ms after Escape, both line endings; the harness makes jsdom report an exit animation and dispatch `animationend` after 150 ms). Known gaps, open: the inventory pin at `OC/CounterSaleScreen.escape-scan.test.tsx:259` holds a literal backspace byte where `\b` was meant, so its file list is always empty and it cannot fail; and in Change the price a code that starts with lowercase letters stays in the closing field (`OC/CounterLinePriceEdit.tsx:252`).
