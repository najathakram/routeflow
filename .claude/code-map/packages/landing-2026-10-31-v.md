# Packages landing 2026-10-31, train V (merge commit `56b0991a8b`, range `5a75a5e720..56b0991a8b`; train PR #4030)

Paths from the repo root. Covers what train V changed under `packages/*` (and the one mobile test mock that mirrors it). Attributed by each member's own train merge (`git diff <merge>^1 <merge> -- packages`). The train commits (`7a2f43b21b`, `858612f980`) touch no package file.

## #3541 `2ddac02d79` product count units and the adjustment reasons

- New `packages/pricing/src/count-pieces.ts`: `countFactorOf({ kind, factorToBase })` (a pack counts its size when over 1, else one piece; a level and the base unit count their own factor) and `countPieces(parts)` (each quantity x factor, summed, rounded ONCE to 3 places half up after `toPrecision(12)` drops float noise; matches `Decimal.toDecimalPlaces(3)`). Importers: api `inventory/product-count.ts` (`piecesOf`), web `lib/product-count.ts` (the Count / Adjust preview), so the number shown is the number written. Spec: `count-pieces.spec.ts`.
- New `packages/pricing/src/stock-write-off.ts`: `WRITE_OFF_ADJUSTMENT_REASONS` (DAMAGED, EXPIRED, THEFT, SAMPLE), `isWriteOff(movement)` (a NEGATIVE ADJUSTMENT with one of those reasons) and `writeOffValue(movement)` (|qty| x the movement's `avgCostAfter`, rounded to the cent via `roundMoney`; 0 when not a write-off). Derived, never stored; reporting only, not a books source. No importer yet. Spec: `stock-write-off.spec.ts`. Both files re-exported from `packages/pricing/src/index.ts`.
- New `packages/types/api/product-count.ts` (re-exported from `packages/types/index.ts`): `ProductCountQuantity`, `ProductCountRequest` (SET or ADJUST with `parts`, `reason`, `reasonNote`, `effectiveDate`), `ProductCountResult` (`deltaPieces`, `stockBefore`, `stockAfter`, `movementId`), and `ADJUSTMENT_REASON_NOTE_MIN` / `_MAX` (3 and 200).
- `packages/types/api/enums.ts`: new `ADJUSTMENT_REASON_LABELS` (Count correction, Damaged, Expired, Theft or loss, Sample, Other; picker order, shared by web and mobile). `packages/types/api/error-codes.ts`: `COUNT_FRACTIONAL_PACK`, `COUNT_DUPLICATE_UNIT`; `apps/mobile/__tests__/__mocks__/@routeflow/types.js` mirrors both codes.

## #4026 `69f9be15fe` the one remembered-price rule

- `packages/pricing/src/pricing.ts`: new `isStickyUpsell(remembered, listPrice)` (true only for a remembered price ABOVE list; null, below or equal is not; a premium tier above list is the customer's normal price, not an upsell). `effectiveBuyerPrice` now calls it (same results).
- `packages/pricing/src/customer-line-price.ts` `customerLinePrice`: new optional input `remembered`, used ONLY for the pack, ONLY with no layer row (a layer row beats it) and ONLY when `isStickyUpsell`; the result is MANUAL, not special, with the list price as the base, and carries `remembered: true` (new optional field on `CustomerLinePrice`). Omitted, every other caller is unchanged; a unit line (not the pack) never takes it. Importers: api `orders/buyer-merge-pricing.ts`, `customers/customer-unit-prices.service.ts`; web `useCounterReprice.ts`, `counter-sale-reprice.ts`, `counter-sale-scan.ts`. Spec: `customer-line-price.sticky.spec.ts`.
