- **#2747 (#2653 hybrid shell) the webview binary gets its own OTA runtime, `01d2d71f9`:** `apps/mobile/app.json` `expo.version` 1.1.1 -> 1.2.0. `runtimeVersion.policy` is `appVersion`, so every binary with the same `version` shares one OTA runtime; the last binaries without the native `react-native-webview` module shipped as 1.1.1, and an OTA from a webview-importing tree delivered to them would crash. Gotcha: never move `version` back to (or below) 1.1.1, and never replace the policy with a fixed runtime string (it would re-merge the runtimes). Spec: `__tests__/runtime-version.test.ts` (webview dependency present, version differs and is newer than 1.1.1, policy still `appVersion`).
- **#1302 (B795) drop a succeeded ADD_ITEM before a retry re-diffs it, `701c321ce`:** `apps/mobile/lib/at-door-diff.ts` gains `dropSucceededAddedLine(added, entry)` (ADD_ITEM only; SUBTRACTS the sent qty/boxes/pieces from the `added` draft and removes it only when nothing is left, so a re-scan during flight is not lost; no match returns the same array) and `leftoverAddedMessage(added)` (toast text, null when empty). `app/(driver)/route/stop/[stopId]/adjust.tsx` calls the drop after each entry in `processDiff` and on the offline branch when the create already landed; a `batchJustCompletedRef` + effect decides "Order updated"/`router.back()` from the TRUE latest `added` (a leftover shows the toast and stays); `BarcodeFab` is `hidden` while `saving`. `lib/at-stop-cr-outcome.ts` `AtStopResolveOutcome` `already-resolved` now carries optional `status`, so a DECLINED resolution reads "declined by the office". Gotcha: CHANGE_QTY/REMOVE_ITEM need no drop (the diff is built against a refetched order and self-heals). Specs: `at-door-diff.test.ts`, `at-door-add-item-wiring.test.ts`, `at-stop-cr-outcome.test.ts`.
