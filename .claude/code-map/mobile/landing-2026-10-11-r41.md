# Mobile landing 2026-10-11 (Release 4.1, the gap before Release 5)

Release 4.1 = merge #3383 (`train/w23-r41`); range `623c23e..e3afbd162`. Paths are under `apps/mobile/`. Mobile mirrors web: the open-invoice set and the server `isOverdue` flag are the one rule (SA-770 follow-ups, row 318). Tests are not indexed.

- `lib/buyer-home-invoices.ts` (NEW, pure) `buyerHomeInvoiceParams() -> {statuses, limit}` (the shared OPEN set), `buyerHomeOverdueCount(invoices)` (follows the server's `isOverdue`, never the OVERDUE status: the sweep never flips PARTIAL, and a stale OVERDUE can outlive a moved due date). `app/(customer)/(tabs)/home.tsx` uses both.
- `lib/buyer-invoice-filter.ts` (NEW, pure) `BuyerInvoiceFilterId` (`ALL | UNPAID | PAID | OVERDUE`), `BUYER_UNPAID_STATUSES` (= `OPEN_INVOICE_STATUS_VALUES`), `buyerInvoiceQuery(filter) -> BuyerInvoiceQuery` (Unpaid = the whole open set; Overdue = the derived `isOverdue` filter, not a status). `app/(customer)/(tabs)/invoices.tsx` spreads it into the query; a VIEWED invoice reads Unpaid.
- `lib/invoice-reminder-error-copy.ts` (NEW) `REMINDER_ERROR_COPY` (by `response.data.code`), `REMINDER_FALLBACK_COPY`, `reminderErrorCopy(err)`: fixed copy, the server message is never read; no response at all is the shared "couldn't confirm" line. `app/(operator)/(tabs)/invoices/[id].tsx` uses it and passes `balanceDue`.
- `lib/invoices-logic.ts`: `canSendReminder` = an `OPEN_INVOICE_STATUS_VALUES` status AND a finite `balanceDue > 0` (like web's `canSendReminder` and the API's `REMINDER_NOT_ISSUED` and no-balance refusals); the input type +`balanceDue?`. `lib/route-parity-manifest.ts` +row `(dashboard)/orders/new` (web-only redirect target).
