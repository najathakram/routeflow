# Mobile landing 2026-10-12 (Release 5.2)

Release 5.2 = the range `5e231561c..7f9dfb180` (first-parent "chore(train): merge X into R5.2" merges; 165 non-merge commits, about 20 touch `apps/mobile`). Symbols read at `7f9dfb180`. Paths are under `apps/mobile/`. Mobile mirrors web: the invoice display rules are the web page's, and the copy helpers are shared `@routeflow/types` subpath re-exports. Tests are not indexed (12 files: 5 new, 7 changed; notable pins named below).

## R5.2: settlement rows come from the server total (B1008, SA-644)

- `lib/run-settlement.ts` `buildSettlementRows(collected, entries) -> {rows, deviceOnly, serverLoaded}`: CASH and CHECK rows come from the run's `collectedPayments` once loaded, so they sum to `expectedPhysicalCash`; before that they are this device's tally (`SettlementRow.basis` "device"). Card, Zelle, advance and other go to `deviceOnly`.
- Same file, `settlementTotalsReady({serverLoaded, fetchedAfterMount})` (SA-644a): ready only when the payload is present AND this screen's own fetch completed (`isFetchedAfterMount`). A cache hit from an earlier visit never unlocks Close run on its own.
- `app/(driver)/route/settlement.tsx`: rows render from `buildSettlementRows`, a separate "This device only, not part of the cash settlement" card lists `deviceOnly`, and Close run (and `closeRun`) is disabled until `totalsReady`. The caption reads "cash/check payments" with the server count, or a "loading or offline: this device's tally only" line.
- Pins: `run-settlement.test.ts` cases (a) to (g) and `settlementTotalsReady`; `settlement-rows-wiring.test.ts` source-pins the caption and the disabled gate.

## R5.2: one open-invoice-status helper (row 326)

- `lib/invoices-logic.ts` NEW `isOpenInvoiceStatus(status)` (null-safe; reads the shared `OPEN_INVOICE_STATUS_VALUES`: SENT, VIEWED, PARTIAL, OVERDUE). `canWriteOff`, `canRecordPayment` and `invoiceActionFlags.canSendReminder` now call it. `canRevertToDraft` (PARTIAL excluded) is deliberately not it.
- Callers: `app/(operator)/credit-notes/[id].tsx` (apply-invoice picker), `app/(operator)/payments/record.tsx` (open-invoice filter, still client-side), operator invoice detail "Apply advance" gate. Invariant: never hand-type the four statuses; an api-side pin fails on a hand-typed set in web or mobile.

## R5.2: read-only copy and license refusal copy (SA-776, CQ-06)

- `lib/read-only-copy.ts` (NEW, re-export only) of `@routeflow/types/read-only-copy`: `READ_ONLY_SENTENCE`, `readOnlyCopy`, `readOnlyCopyText`, `readOnlyReasonLine`, `readOnlyContactLine`, types `ReadOnlyCopy`, `ReadOnlyCopyInput`. Mobile has no read-only surface yet; the first one must call `readOnlyCopy({...})`, not write its own sentence.
- `jest.config.js` `moduleNameMapper`: `@routeflow/types/read-only-copy` and `@routeflow/types/regulated-auth-copy` resolve to package source (the package root is stubbed in jest). A new shared subpath used by a mobile lib needs the same mapping.
- `lib/authorizations-logic.ts` re-exports `regulatedAuthCopy`, `regulatedAuthErrorCopy(err) -> string | null` (non-null only for a 409 `REGULATED_AUTH_REQUIRED`; names categories only when they pass a plain-text check). `lib/api/authorizations.ts` re-exports it via `export *`.
- Fallback order is now `regulatedAuthErrorCopy(e) ?? server message ?? generic` in: `components/NewOrderScreen.tsx` (save-order alert), operator `orders/[id]/edit-items.tsx` (toast), `lib/at-stop-cr-outcome.ts` `classifyAtStopResolveError` (decline reason). A refusal WITH categories still opens the license guard modal first.
- Pins: `authorizations-logic.test.ts` (expired, empty-list fallback, null for other errors) and `at-stop-cr-outcome.test.ts` (declines with the shared sentence).

## R5.2: levy named apart from tax (rows 398, 401 follow-ups)

- `lib/invoice-tax-lines.ts` (NEW) `invoiceTaxLines(invoice) -> {tax, charges: ChargeLine[]}`: a thin adapter over `invoiceTaxSplit` in `@routeflow/pricing` (the invoice header `taxAmount` holds regular tax PLUS the regulated levy). `TaxSplitItem` is the line shape it reads.
- Operator invoice detail `app/(operator)/(tabs)/invoices/[id].tsx`: totals show "Tax" from `taxLines.tax` and one row per named charge (e.g. a deposit) instead of the raw header. No formula lives in the screen.
- `lib/buyer-invoice-totals.ts` (NEW) `buyerInvoiceTotalsRows(inv) -> TotalsRow[]` (Subtotal; Tax from `regularTaxAmount ?? taxAmount`; one row per `chargeLines`; Discount negative; Shipping) and `totalsRowText(row)` (sign in the text via `formatReceiptMoney`). Empty when `subtotal` is null.
- `lib/api/buyer.ts` `BuyerInvoice`: dropped the phantom `tax`; added `taxAmount`, `regularTaxAmount?`, `chargeLines?` (server-computed, absent on an older server), `discount`, `shippingFee`. Customer `invoices/[id].tsx` renders those rows; the hard-coded "GST (10%)" is gone. No tax name or rate may be hard-coded here.
- Pins: `invoice-tax-lines.test.ts`, `buyer-invoice-totals.test.ts` (levy case, older server, sign text, and a source pin that the screen hard-codes no tax name).

## R5.2: paid-at-sale shows no due date or terms (row 401, CQ-26)

- `lib/invoice-sale-terms.ts` (NEW) `invoiceShowsTerms(inv) -> boolean`: false when the server's `paidAtSale` is true; without the flag it falls back to the shared `isPaidAtSale` rule in `@routeflow/pricing`. Unclear or missing input keeps the terms showing. Display only: stored terms and due dates are untouched.
- `lib/api/admin.ts` `AdminInvoice.paidAtSale?` and `order.counterSale?`; `lib/api/buyer.ts` `BuyerInvoice.paidAtSale?` (the buyer copy carries no order or payment instants, so the server answers once).
- Operator invoice detail: when `!showTerms` the due-date row reads "Edit due date" (the editor stays reachable, no date shown) and the "Terms:" line is hidden. Customer invoice detail hides both the "Due:" and "Terms:" lines. Pin: `invoice-sale-terms.test.ts`, which also source-pins both screens.

## R5.2: buyer items edit names each line (row 352, B297)

- `lib/buyer-edit-items.ts` `BuyerDraftItem.orderItemId?`; NEW `draftKey(item)` (`orderItemId ?? productId`); `hydrateBuyerDraft` keys by the stored line id, so two lines of one product stay two rows. `BuyerSavePlan` replace items are `BuyerOrderItemEdit[]` (`@routeflow/types`), each carrying `orderItemId` when it edits a stored line; a catalog add has none (a new line).
- `lib/api/buyer.ts` `useBuyerUpdateOrderItems` sends `{items, namesLines: true}` to `PATCH /buyer/orders/:id/items`; without `namesLines` the server falls back to its one-release compatibility path. Customer `orders/[id]/edit-items.tsx` uses `draftKey` for keys, `setQty`, and the catalog-add merge into an already held product.
- Pins: `buyer-edit-items.test.ts` ("two lines of one product stay two rows and Save names each") and `buyer-edit-items-custom-lines.test.ts`; the `@routeflow/types` test mock gains `ORDER_REVISION_STALE`.
