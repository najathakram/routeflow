## #4108 `d4bd802d61` a family save asks before it moves variants (W-1119, SA-1082 PR-2)

Rule: a family price change no longer copies itself onto variants. Each save that changes a family price asks which variants at the family's old price move; the answer rides the save.

- `packages/pricing/src/family-move.ts` (new, spec `family-move.spec.ts`): the one comparison, against the family's values before the save through `getTierPrice`, rounded once. Retail must match; a tier moves only if Retail and that tier match; a blank family tier stays blank; a variant with its own order unit is never listed. A price scales by pieces only when the family row holds a pack above 1.

The save carries `moveVariantIds`; the server re-checks each one under the family lock. The response and one audit row (`audit/audit-actions.constant.ts`) give the count. No list, nothing moves. `permission-map.pinned.ts` pins the new route.
- `products/family-price.ts`: `propagateFamilyPrice` now writes recipes only. `products/product-price-write.service.ts`, `product-price-grid.service.ts`, `products.service.ts`: `priceAuthority` returns `own` for a variant in both modes, so the family editor's refusal is gone; clearing a box takes the family's number in the same write; typing an own Retail blanks the tiers at the family's value in the same write.
