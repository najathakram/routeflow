# Api landing 2026-11-12, WP2A.0 extra web origins (#4307, head `76490c7ef`; merge sha recorded at landing)

Paths under `apps/api/src/` unless they start with another root. No schema, no migration. Ships dark: `WEB_ORIGINS` empty = unchanged.

- **`config/web-origins.ts` (NEW): the one web-origin allow-list.**
  - `normalizeOrigin(url)` canonicalises through `new URL(x).origin`.
  - `parseWebOrigins(raw, nodeEnv) -> string[]`: comma list, trimmed, trailing `/` stripped, origin-normalised, blanks skipped, de-duplicated. A non-http(s) entry or (production) a loopback entry THROWS in production and is dropped outside it.
  - `extraWebOrigins(env)`, `pickFromOrigins(candidate, origins, fallback)` and `pickWebOrigin(candidate, fallback, env)`: an exact `===` match, otherwise the fallback.
  - `webReturnBase(candidate, env)` returns the candidate when it is listed, else `webBaseUrl()`.
  - `isOnAllowedWebBase(url, env)`: `u === o || u.startsWith(o + "/")` for `webBaseUrl()` and each listed origin.
  - `config/web-base-url.ts` now exports `isLoopbackHost`.
- **Config.** `config/configuration.ts` `urls.webOrigins = extraWebOrigins()`, so a bad production value fails at boot. `apps/api/.env.example` documents `WEB_ORIGINS=`.
- **Rule.** A flow that starts on a listed origin (the request's `Origin` header) returns there. Out-of-session links (emails, QR, jobs, links made for someone else) stay on `WEB_URL`.
- **Google, tenant.** In `auth/auth.controller.ts`, `resolveReturnOrigin` also accepts `webOrigins`. The new `requestReturnOrigin(origin)` is used when no `return_origin` is sent. `googleAuthUrl` and `linkGoogleUrl` take `@Headers("origin")` as their last param.
- **Google, shared state.** In `auth/google-oauth.service.ts`, `generateLinkUrl(type, userId, returnOrigin?)` and `peekOAuthStateReturnOrigin(state)` are exported and shared.
- **Google, platform.** In `auth/platform-google-auth.controller.ts`, `getAuthUrl` and `getLinkUrl` pass a listed origin into state. `handleCallback` takes its base from the peeked state, then from `profile.returnOrigin`.
- **Mailbox.** In `email/mailbox/mailbox-connection.service.ts`, `startConnect` and `startConnectMicrosoft(tenantId, userId, returnOrigin?)` keep `returnOrigin` in the nonce only when it is listed. The new `peekReturnOrigin(state)` does a plain GET and never throws. `mailbox.controller.ts` callbacks call `callbackBase(state)` FIRST, before discard or exchange consume the nonce.
- **Stripe Connect.** `stripe-connect/stripe-connect.service.ts` adds the state claim `ro` (only when listed) and exports `peekStripeConnectStateOrigin(state)` (an unverified decode). The `stripe-connect.controller.ts` callback base is `pickWebOrigin(peek, WEB_URL)`.
- **Billing.** `billing/settings-billing.controller.ts` checkout and portal, and `payment-due.controller.ts` `pay`, read `@Headers("origin")`. The path is `PaymentDueService.pay(..., returnOrigin?)` → `catchup-checkout.service.ts` `open({ returnOrigin })`, which calls `webReturnBase`. `payment-due.service.ts` `returnUrlsOffBase` uses `isOnAllowedWebBase`, so open sessions on either address are kept.
- **Buyer.** `payment-requests/payment-requests.service.ts` `createCardRequest({ returnOrigin })` calls `pickWebOrigin`, and `buyer-payments.controller.ts` `card` passes the header through.
- **Specs.**
  - New: `config/web-origins.spec.ts`, `auth/platform-google-auth.controller.return-origin.spec.ts`.
  - Extended (T34): `auth/auth.controller.return-origin.spec.ts`, `google-oauth.return-origin.spec.ts`, `payment-due.stale-session.spec.ts`, and the checkout, portal, pay, catch-up, buyer card, Stripe Connect and mailbox specs.
  - The arity and route-argument pins in `settings-billing.controller.spec.ts` and `payment-due.controller.spec.ts` now include the `origin` header slot.
