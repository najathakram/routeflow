## #4225 `6987996413` tenant context kind and dark guard (F05 slice 1 PR A, SA-1105 Q1-Q6, T1, tenancy)

Dark: nothing a customer or an operator sees changes and no query result changes. Before it, `forTenant()` with no tenant returned the unscoped client and `isSuperAdmin()` was `getOrNull() === null`, so a SUPER_ADMIN, an anonymous request and "no context at all" looked the same, and a tenant-owned create through it wrote `tenantId = NULL` silently on the models whose column is nullable.

- `tenant/tenant-context.service.ts`: `kind()` returns `TENANT | SUPER_ADMIN | ANONYMOUS | SYSTEM | NONE` (`NONE` = no store at all, `TenantKind` excludes it). `run(tenantId, fn, tenantless, label)` stores the kind and the `Controller.handler` label; `isSuperAdmin()` is `kind() === "SUPER_ADMIN"`. `tenant/tenant.interceptor.ts` reads the kind from the JWT and records it per request. `SYSTEM` has no request producer: it is meant to exist only inside `forSystem`.
- `prisma/tenant-context-guard.ts` (new, `createTenantContextGuard`): `checkWrite` (create, createMany, createManyAndReturn, upsert, and a nested create one level down under `create` and `upsert.create`) and `checkRead` (a tenantless access; reported for `NONE` and `ANONYMOUS` only, a SUPER_ADMIN reads unscoped by design). A counter per `kind|model|op` on every hit, one stack-carrying log line per call site per second (the stack capture is gated per key, 1 s), a 10-minute `TENANT_CONTEXT_MISSING_SUMMARY` line. `TENANT_CONTEXT_ENFORCEMENT` (`readEnforcementFlag`) is read once at boot and throws `TenantContextMissingError` only on exactly `"on"`; no deploy file sets it, so it is off. The log line holds kind, model, op and the call site: no data values, no ids. A nested create under `update` is out of reach in slice 1 (SA-620's walker).
- `prisma/prisma.service.ts`: `forTenant()` with no tenant returns an observing client (every tenant-owned model, including the nullable-`tenantId` ones) and a tenantless `tenantTransaction` returns an observing proxy on the raw tx (`_observeTx`); the write itself is passed through unchanged, and the database's `*_tenantId_nn` check stays the backstop. `forSystem<T>(reason, fn)` is the one deliberate unscoped door: the reason is a literal of at least 12 characters, it runs `fn` inside `run(null, ..., "SYSTEM", reason)`, and the guard never reports for `SYSTEM`. `common/for-system.allow-list.spec.ts` scans the source for `.forSystem(` and holds the call sites set-equal to its own list (self-tested); the first conversion is `inventory/low-stock-digest.service.ts` (cross-tenant scan). Money paths stay out of slice 1 (PR-2, under the owner's review).
- `email/email.service.ts` (Q6): `writeSendingDomainConfig` writes through `SystemConfigService.set` (one constant key) instead of a direct SystemConfig write; the census (`system-config-callers.census.spec.ts`) and the settings registry spec follow. `email/email.module.ts` and nine email specs gain the extra constructor argument.
- Tests: `prisma/tenant-context-guard.spec.ts`, `tenant-context-guard.models.spec.ts` (every nullable-`tenantId` model covered, pinned against the schema folder), `prisma-tenant-context-kind.spec.ts`, `tenant/tenant.interceptor.kind.spec.ts`, `tenant/is-super-admin.callers.spec.ts`, `prisma/tx-upsert-callers.inventory.spec.ts` (eight groups of tenant-scoped `tx.<model>.upsert` callers, `UNSAFE = 0`), `email/email-sending-domain-write.spec.ts`, and the real-Postgres `prisma/tenant-context-kind.db.spec.ts` (a SUPER_ADMIN create on `Customer` with no tenant logs once and the `Customer_tenantId_nn` check refuses it, 23514).
- Registry: **B926 noted and left open** (enforcement, the `forSystem` conversions and the 1384 `forTenant()` call sites are later slices that wait for the dark log). **B1284 filed** (LOW, F05 T2, a PR-2 requirement): `run()` accepts `"SYSTEM"` from any caller, so `forSystem` is not the only way into the kind; nothing calls it that way today. **B1285 filed** (LOW, F05 T2): the capture gate is per `kind|model|op`, so one hot call site can hide others under the same key in the log (the counter stays true).
