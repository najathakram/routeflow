- **#4341 billing payments API (SA-1146 B-4).** `billing/settings-billing.controller.ts` `GET /billing/payments?cursor=` (`listPayments`, TENANT_ADMIN; tenant id from the JWT only; read-only; pinned `"ADMIN"` in `auth/permissions/permission-map.pinned.ts`). `billing/billing-payments.service.ts` `BillingPaymentsService.list(tenantId, cursor)` merges paid card invoices and RouteFlow invoices, newest first, `PAYMENTS_PAGE_SIZE = 12` a page, an opaque `nextCursor` the service decodes; `stripeMinorToMajor` converts minor units to dollars and returns null for an unknown currency (never a wrong figure). Registered in `billing/billing.module.ts`.
  - `billing/stripe.service.ts` `listPaidCustomerInvoices(customerId, { limit, startingAfter }, request?)`: one page of PAID invoices; the customer id is the tenant row's, never a request value. It throws on a Stripe failure; the service turns that into `stripeUnavailable: true` with the RouteFlow rows only, never an empty list posing as "no payments".
  - Invariants: the receipt link is Stripe's hosted invoice page, read live on every request and never stored; a RouteFlow row has none; `amount` is rounded by the API.
  - Types in `packages/types/api/billing.ts`: `BillingPaymentRow` (`source` "stripe" | "routeflow", `date`, `amount`, `currency`, `paidAt`, `paidDayLabel`, `number`, `receiptUrl`) and `BillingPaymentsPage` (`rows`, `nextCursor`, `stripeUnavailable`). No web caller yet. Pins: `billing/billing-payments.service.spec.ts`, `billing/settings-billing.payments.spec.ts`.
- **#4327 discount tax base threaded, dark (W-989, SA-1141 PR-2).** `common/discount-tax-mode.ts`: `discountModeOf(doc, from = DISCOUNT_PRE_TAX_FROM)`, `newDocumentDiscountMode`, `DISCOUNT_SOURCE_SELECT`, `withNsfFlag`, type `DiscountModeDoc`. The mode is a pure function of the `createdAt` of the document the money derives from (an invoice cut from an order reads the order's, one converted from an estimate reads the estimate's, any other reads its own) against the one cutover constant `DISCOUNT_PRE_TAX_FROM` in `packages/pricing/src/discount-tax-base.ts`, which is `null` here: every document answers LEGACY_POST_TAX and no figure moves. With the cutover set, an order-linked invoice loaded without its order, or an invoice without its estimate, throws `MoneyInvariantError` (a loader bug, never a guessed mode).
  - Required, not defaulted: `orders/order-totals.ts` `orderTotalsOf`, `orderTotalsOfSums` and `editedOrderTotals` take `discountBase` (a new order passes `newDocumentDiscountMode()`, an existing one `discountModeOf(order)`); `common/tax-rate.ts` `effectiveTaxRateFromTotals` takes `{ discount, discountBase }`; `invoices/stored-tax-state.ts` `inferredGoodsRateForCopy` takes the source invoice's `discountBase`. The call sites in `invoices/`, `estimates/estimates.service.ts`, `orders/orders.service.ts` and `order-templates/order-templates.service.ts` pass the mode from the one helper.
  - `invoices/stored-tax-state.ts` `taxStateOf` reads the row's own mode; for PRE_TAX the "does the stored tax reproduce" test is judged with the STORED discount, so a legacy row's verdict is unchanged and a new row is never falsely stale.
  - Wire field: invoice, order and estimate detail responses carry `discountTaxBase` (`"PRE_TAX" | "LEGACY_POST_TAX"`; `discountModeOf` in `invoices/invoices.service.ts`, `orders/orders.service.ts`, `estimates/estimates.service.ts`). Types in `packages/types/api/discount-tax-base.ts` (`DISCOUNT_TAX_BASE_VALUES`, `DiscountTaxBaseValue`, `WithDiscountTaxBase`), pinned equal to the pricing union by `common/discount-tax-base-parity.spec.ts`. `packages/pricing/src/invoice-totals.ts` `InvoiceTotalsLine.isNsf`: the NSF bounce-fee line is not goods, so a PRE_TAX discount is never spread onto it.
  - Scripts: `apps/api/scripts/report-b1043-stale-tax-state.mjs` and `apps/api/scripts/report-standard-refund-tax-shortfall.mjs` now read the mode from `@routeflow/pricing` instead of a local formula (both read-only).
  - Pins: `common/discount-tax-base.pin.spec.ts` (every production totals or rate call names its mode; a string-literal mode appears only in the listed LEGACY-by-definition files with listed counts), `invoices/discount-tax-base.mode-sites.pin.spec.ts` (ordered per-file table of every mode call), `common/discount-tax-mode.spec.ts`. `common/testing/discount-cutover.ts` (`withDiscountCutover`, `underCutover`, `BEFORE`) is the harness that sets the cutover inside a test so a swap of `discountModeOf` for `newDocumentDiscountMode` can go red; site specs run the same call with the cutover null and compare.
