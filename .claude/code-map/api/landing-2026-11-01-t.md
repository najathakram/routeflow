## #4078 `f7b446e0ab` customers list and CSV show the statement's Open balance (SA-1078 / W-1096 PR-5)

Rule: one basis for "what a customer owes". The customers list, its CSV and the account statement all read the same invoice where and select and sum with `statementOutstandingAmount`, so a figure printed anywhere is the sheet's figure. DRAFT, PAID, VOID and WRITTEN_OFF are never receivable.

- `customers/account-statement.ts`: new exports `OPEN_BALANCE_INVOICE_WHERE` (`{ status: { notIn: KPI_SUMMARY_EXCLUDED } }`) and `OPEN_BALANCE_INVOICE_SELECT` (`customerId, total, status, dueDate, payments { amount, status }`). `buildAccountStatement` now spreads the where (same set as before, no behaviour change there).
- `customers/open-balances.ts` (new): `openBalancesByCustomer(prisma, customerIds, now): Promise<Map<string, number>>`. One `tenantTimeZone` read, then the invoice read in chunks of 1000 ids (`forTenant().invoice.findMany`, the two constants above), grouped by customer, summed with `statementOutstandingAmount(group, zone, now)`. A customer with no open invoice has no key (callers default to 0); an empty id list returns an empty map with no query. The caller reads `now` once.
- `customers/customers.service.ts`: `findAll` replaces the invoice read plus `receivableBalance` sum with `openBalancesByCustomer(this.prisma, customerIds, new Date())`. **Wire change: each list row carries `openBalance` (rounded with `roundMoney`) and no longer `receivables`**. `exportCustomers` drops the `invoices` include and reads `openBalancesByCustomer` for all exported ids. `unusedCredits` is unchanged. `sortBy=receivables` was never allow-listed and still falls back to createdAt-desc (comment reworded; the web header keeps its sort button, "filed LATER").

- `invoices/credit-exposure.ts`: **removed exports** `RECEIVABLE_INVOICE_SELECT` and `receivableBalance` (their only callers were the list and the CSV). `isUnbackedDraft`, `loadCreditExposure`, `computeCreditExposure` and the hard block are untouched: the credit-limit block and the statement's exposure block keep the draft-aware basis (D6 / B462). `invoices/invoice-status-sets.ts`: comments only (`CREDIT_EXPOSURE_EXCLUDED` / `CREDIT_NOT_APPLICABLE` are now read by the credit-exposure reader alone).
