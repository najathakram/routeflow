## #3541 `2ddac02d79` product Count / Adjust with adjustment reasons (SA-828, row 657 part 2)

- `inventory/inventory.controller.ts` new `POST /inventory/products/:id/count` (`countProduct`, `@Roles(OPERATOR)`; the class-level CATALOG gate applies, see the train commit below).
- New `inventory/product-count.ts`: `piecesOf(product, ladder, parts)` resolves each part's factor on the server (`resolveLineUnits`, then `countFactorOf` and `countPieces` from `@routeflow/pricing`), refuses a fractional packed unit (`COUNT_FRACTIONAL_PACK`) and a unit named twice (`COUNT_DUPLICATE_UNIT`, judged on the RESOLVED unit), and caps the sum at `MAX_PIECES` (9,999,999.999); `describeParts` writes the movement note ("3 Case (x24) + 4 Box (x12) = 120 pieces"); `lockedLadderOf` takes the tenant-units SHARED lock and reads the ladder inside the transaction (SA-826 order: tenant-units, then product rows).
- New `inventory/dto/product-count.dto.ts` `ProductCountDto` (`mode` SET | ADJUST, `parts` 1 to 10 unique units, `sign` for ADJUST only, `effectiveDate`) and `ProductCountPartDto` (`unit`, `quantity` 0 to 9,999,999, 3 decimals).
- New `inventory/dto/adjustment-reason.dto.ts`: `AdjustmentReasonDto` (reason required) and `OptionalAdjustmentReasonDto` (reason optional), with the `reasonNote` rule (3 to 200 characters after trimming, required when the reason is OTHER, at most 200 otherwise); the reasons come from the Prisma `AdjustmentReason` enum (the API never value-imports `@routeflow/types`), the note bounds are pinned equal to the shared constants by `product-count.dto.spec`. `dto/record-adjustment.dto.ts` `RecordAdjustmentDto` now extends `OptionalAdjustmentReasonDto`.
- `inventory/inventory.service.ts`: new `countProduct(productId, dto, performedById)`: the whole write runs in `retryStockTx`, takes `lockedLadderOf`, then the product lock, reads the stock under the lock, and writes through `applyStockCountItemsInTx` (one ADJUSTMENT movement carrying the reason and note; a SET is the counted total minus the locked stock; a backdated count replays the product's average from that date; no negative-stock refusal; an ADJUST that moves nothing is 400; stock left over the column limit is 400). `applyStockCountItemsInTx` gains an optional `reason` argument (default COUNT_CORRECTION) and returns `lines` (`productId`, `movementId`, signed `delta`, `stockAfter`). `recordAdjustment` stores `reason` and `reasonNote`; an absent reason (installed mobile builds post none) is stored null with a "would refuse" warn that sizes the later enforcement.
- `common/api-error-codes.ts`: `COUNT_FRACTIONAL_PACK`, `COUNT_DUPLICATE_UNIT` (mirrored in `packages/types/api/error-codes.ts`).
- Scripts that post an adjustment now name `reason: "COUNT_CORRECTION"`: `scripts/qa-run.js`, `reports-qa.js`, `ux-audit-seed.js`, and `scripts/feature-smoke.mjs` (repo root).
- Tests: `inventory/inventory.product-count.spec`, `inventory/product-count.spec`, `inventory/dto/product-count.dto.spec`, `dto/record-adjustment.dto.spec`, `inventory/sa828-product-count.db.spec` (DB lane; world in `inventory/testing/sa802-world.ts`), `stock-writers-locked-reads.spec`, `stock-writers-tx-retry.spec`, `stock-writers-coverage.spec`, `inventory.controller.roles.spec` and `roles-matrix.spec`; the product-lock, family-writer and census scan specs list the new site.
