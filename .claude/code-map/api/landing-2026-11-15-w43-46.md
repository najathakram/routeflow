- **#4326 late sale into a locked month (W-965, SA-1137).** `regulated/filing-lock.ts`: pure `routeSaleRowsForLockedPeriods`, `routeSaleRowsIfLocked`, type `RoutedPeriod`. A SALE row with an inherited date whose (category, month) a LOCKED filing covers books into the current month (`soldAt` = now, `periodBucket` = now's, `originalSoldAt` = the row's own date). Decided per row, so on a mixed invoice only the locked category moves. Only LOCKED counts (`isLockedFiling`); a GENERATED month books as before and the FILING_STALE rebuild catches it.
  - Invariant: `routeSaleRowsIfLocked` always reads the covering filings (`lockFilingRowsCovering`, FOR SHARE) on the writer's own transaction, with no `anyLockedFiling` early exit, so a lock cannot land between the decision and the insert.
  - `regulated/regulated-ledger.service.ts` `writeSaleEntries` takes a REQUIRED `lockedPeriod: "REFUSE" | "BOOK_CURRENT"`; BOOK_CURRENT routes first and `assertLedgerRowsNotLocked` stays as the last-line guard. `invoices.service.ts` passes BOOK_CURRENT for the order bill (inherited date) and REFUSE for a date chosen at the request; `estimates.service.ts` and the ledger resync pass REFUSE.
  - Audit: `recordLateSaleRouting` writes one `regulated.sale_booked_late` row per routed group in the same transaction (`AUDIT_ACTIONS.REGULATED_SALE_BOOKED_LATE`).
