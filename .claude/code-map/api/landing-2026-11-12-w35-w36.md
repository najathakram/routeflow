## Window 36

- **#4300 offline staff order create (SA-1124 PR-1a, no migration; schema came with PR-0 #4279).** `POST /orders` gains an `offline` mode for staff. The controller resolves the offline request before any merge logic (`orders/orders.controller.ts`; `OFFLINE_STAFF_ONLY` 403 for CUSTOMER and DRIVER). New folder `orders/offline/`:
  - `offline-create.ts`: the `OfflineCreate` class (built by `offlineCreate(...)`; methods `gate`, `judgeDrift`, `orderData`, `writeFlags`) runs the same three gate calls as online (license, restriction, credit); exactly four codes (`REGULATED_AUTH_REQUIRED`, `SELLING_RESTRICTED`, `RESTRICTION_WARNING`, `CREDIT_LIMIT_EXCEEDED`; the const `OFFLINE_GATE_FINDING_CODES`, count-pinned) become findings and the order saves as DRAFT (no stock decrement) with `RESTRICTED` / `LICENSE_REQUIRED` per line and `CREDIT_BLOCKED`; every other error propagates. It also builds the flag rows (`OPEN_ORDER_EXISTS`, `BACKORDERED_OFFLINE`, price flags) and `writeFlags` (one top-level `orderReviewFlag.createMany` with explicit `tenantId` in the create transaction).
  - `offline-drift.ts`: pure `judgeOfflineDrift`, server price vs the device's `offlineQuote` in integer cents (`roundMoney`); `PRICE_CHANGED_OFFLINE` per line, with `unitChanged: true` when the pack or unit label moved, or one order-level flag for a total-only move.
  - `review-flags.ts`: read, list and resolve rules. `GET /orders/:id` carries `reviewFlags` (staff only), `GET /orders?needsReview=true` (`orders/order-list.ts`, `orders/dto/list-orders.dto.ts`), `POST /orders/:id/review-flags/:flagId/resolve` (OPERATOR and up; gate kinds answer 409 `ORDER_REVIEW_FLAG_NOT_MANUAL`; `orders/dto/resolve-review-flag.dto.ts`).
  - No money offline: `appliedCreditNotes` 400 `OFFLINE_CREDITS_ONLINE_ONLY`, `inlineReturn` 400 `OFFLINE_PAYMENT_ONLINE_ONLY`, no `offlineQuote` 400 `OFFLINE_QUOTE_REQUIRED` (`orders/dto/offline-quote.dto.ts`, `orders/dto/create-order.dto.ts`, `orders/dto/create-order-limits.ts`). An open order is never merged (never `MERGE_CHOICE_REQUIRED`): a second order is created and flagged. Offline with `immediateDelivery` is refused. A draft with an open `CREDIT_BLOCKED` flag re-runs the credit gate at promotion (`assertPromotionCredit`), and a successful promotion resolves the open gate flags in its transaction.
  - Idempotent replay returns the original order and writes no flags; the cart hash (`orders/replay-cart-normalize.ts`) reads only `items` and `status`.
  - Two behaviour-neutral extractions took `orders/orders.service.ts` from 5181 to 5152 lines (`common/size-ratchet.spec.ts`): `orders/driver-run-link.ts` and `orders/own-customer-for-create.ts`. New codes in `common/api-error-codes.ts` and `packages/types/api/error-codes.ts`; wire types in `packages/types/api/orders.ts` (`ORDER_REVIEW_FLAG_KIND_VALUES` from PR-0, not a local copy); `auth/permissions/permission-map.pinned.ts` gains the resolve route.
  - Specs: `orders/offline/offline-create.spec.ts`, `offline-create.db.spec.ts`, `offline-drift.spec.ts`, `review-flags.spec.ts`, `order-list-needs-review.spec.ts`, `orders/orders.controller.offline.spec.ts`, `orders/dto/offline-order.dto.spec.ts`, `orders/own-customer-for-create.spec.ts`, `orders/driver-run-link.spec.ts`.
  - Known gaps, open (see the register): `orders.service.ts:1327` runs `assertCreateOrderDateOpen` before the offline gates, so a replay into a locked period answers `ORDER_DATE_PERIOD_LOCKED` instead of saving a draft; the flag `detail.lineIndex` is the line's position at replay (`orders/offline/offline-create.ts:336-341`, `:363`) and goes stale after a reorder.
