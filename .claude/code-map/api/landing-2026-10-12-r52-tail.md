## R5.2 tail: the automatic-lock pause switch, gate and skip record (row 381)

- `billing/auto-lock-gate.ts` (NEW) `autoLockAllowed(autoLocks, {id, class}, kind) -> Promise<boolean>`: the ONE gate every automatic lock asks BEFORE its first write. Unpaused: allowed. Paused: allowed only for an explicit class TEST, DEMO or INTERNAL; PRODUCTION, null, undefined and any unknown value are held (fail closed, S2). `autoLocks` undefined (a bare unit spec) allows.
- Same file: `AUTO_LOCK_KINDS` / `AutoLockKind` (`trial_expired`, `subscription_cancelled`, `overdue_suspended`, `stripe_cancelled`, `payment_overdue`, `trial_cancelled`), `AUTO_LOCKS_PAUSED_KEY` (`platform.autoLocksPaused`), `AutoLockSwitch` interface, `autoLockKindOfMilestone(milestone) -> AutoLockKind | null`.
- Same file `recordAutoLockSkip(client, {tenantId, kind, key, wouldHaveSet, actorId?}, logger?) -> boolean`: one durable claim per `(tenantId, kind, key)` (`BillingNotificationLog` milestone `AUTO_LOCK_PAUSED:<kind>`, `createMany` with `skipDuplicates`), and one `tenant.auto-lock-skipped` audit row only when the claim is NEW. Never throws; a failed record is retried by the next pass.
- `billing/auto-lock-switch.service.ts` (NEW) `AutoLockSwitchService`: `isPaused()`, `getState() -> {paused, since, reason, by}`, `setPaused(paused, reason, actor)`, `invalidate()`; 30 s per-process cache (`CACHE_TTL_MS`), refreshed on set. A MISSING key reads as PAUSED, and so does a read error (not cached). `parseAutoLockStored(raw)` is paused unless the value says `paused: false` (or a bare false).
- It is a standalone billing service, not a `PlatformConfigService` method: `PlatformAdminModule` already imports `BillingModule`, so a back edge would be a cycle (the `EntitlementsModeService` precedent). Every lock writer takes it as a trailing `@Optional()` dependency; `billing.module-wiring.spec.ts` pins that production injects the real instance into all four services.

## R5.2 tail: what each automatic writer does while paused (row 381)

- Held writers are `expireTrials`, `applyScheduledCancellations`, `suspendOverdueTenants`, `cancelFromStripe`, `dunning-pause.ts` `pauseTenantTx`, and the tenant's own trial cancel. TEST, DEMO and INTERNAL tenants lock as before; a super admin's manual lock (`updateStatus`, `deleteTenant`) is never gated.
- `billing/billing-cron.service.ts` `expireTrials`: a held trial gets no status write and no notice; its write is now a CAS (`updateMany` where `status: TRIAL`, `class`), so a repeat or raced pass writes and announces nothing. `applyScheduledCancellations`: no READ_ONLY, no add-on deactivation, `cancelAtPeriodEnd` stays armed; the skip is recorded after the tx.
- `billing/billing.service.ts` `suspendOverdueTenants`: no SUSPENDED, no notice. `cancelFromStripe` (webhook) reads the tenant first; new private `holdStripeCancel`: records the skip (key = Stripe subscription id), still sets `cancelAtPeriodEnd`, disarms the superseded downgrade and resets the coupon, but writes no CANCELLED and no notice. The webhook is not replayed after unpause; the crons find the tenant again.
- `billing/dunning-pause.ts` `pauseTenantTx` reads `class` under the ledger lock and, when held, writes no subscription CAS and no status (only matters in `enforced` pause mode); skip key = the dunning invoice id. `dunning-core.ts` `DunningDeps` +`autoLocks?`; `dunning.service.ts` threads it.
- `billing/subscription-mutation.service.ts` `cancel(tenantId, actorId?)`: a PRODUCTION TRIAL tenant is not locked at once while paused; the intent is the skip record plus audit row (`trial_cancelled`, key = `trialEndsAt`, `actorId` = the clicking user) and it answers `{ cancelled: "trial_recorded" }`; `trialEndsAt` is untouched, so the ordinary expiry locks it after an unpause.
- Class in the CAS (S3): the class the gate judged is part of the write, so a TEST to PRODUCTION reclassification between scan and write cannot lock: `expireTrials` (`updateMany` where), `suspendOverdueTenants` and `cancelFromStripe` (`transitionAndEmit` `statusWhere` and the SUSPENDED to CANCELLED `updateMany`).

## R5.2 tail: every writer of a tenant lock is classed (row 381)

- `billing/auto-lock-writers.pin.spec.ts` (NEW structural pin, no runtime code): scans every non-spec file in `apps/api/src` by predicate (a function writing `Tenant.status` to anything but ACTIVE or TRIAL, a non-null `readOnlyReason`, or handing such a target to `transitionAndEmit` / `deps.transition`) and requires each to be classed in a table.
- Classes: AUTOMATIC and TENANT_ACTION must call `autoLockAllowed` before their first write (source order inside the function); MANUAL_ADMIN is an allow-list and must NOT be gated; NOT_A_NEW_LOCK (`transitionAndEmit`, `transitionToActiveTx`, `markCancelledWhilePaused`) needs a written reason. Unclassed, stale or late-gated entries fail the build; self-controls inject each case.
- Invariant for a new lock writer: add it to the table AND gate it before its first write, in the same function. The gate is per call site; there is no central choke point.
