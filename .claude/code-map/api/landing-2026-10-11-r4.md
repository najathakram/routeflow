## Digital receipt (SA-751r): ONE receipt money model

- `documents/receipt-model.ts` (NEW, pure): `buildReceiptModel(order, invoices, payments, branding, zone) -> ReceiptModel` (`@routeflow/types` `ReceiptModel`), mirrors the web `receiptModelFromOrder` line for line. Types `ReceiptLineInput`, `ReceiptOrderInput` (`counterCashTendered?`), `ReceiptInvoiceInput`, `ReceiptPaymentInput`, `ReceiptBranding` (+`hideOriginalPrice?`, `configuredTaxPercent`); `isLiveInvoice`, `formatReceiptMoney`, `formatSaleTime(at, tz?)`. Lines price through pricing `receiptLineAmounts`; Tax is the order's tax, Adjustments the remainder, the rate is named only via `explainedTaxRatePercent(storedTaxRatePercent(...))`; change is `servedChange(...)` (counter-sale-readback), never recomputed.
- `documents/render-order-receipt.ts` (NEW, pure) `renderOrderReceipt(order, invoices, payments, branding, zone) -> RenderedReceipt {subject, html, text}`: branded shell from `email/email.service.ts` (`tenantHeaderHtml`, `renderBrandedEmail` now exported); every dynamic string `escapeHtml`; plain text built from the model (`receipt-model.ts` cuts the footer by code points at the one footer cap).
- `documents/receipt.service.ts` (NEW) `ReceiptService.send(orderId, dto, now?) -> SendReceiptResponse`: tenant-scoped read (customer name and `isWalkIn` only, no customer email read, the typed address is never stored), 409 `RECEIPT_NOT_AVAILABLE` for a cancelled order or one with no live invoice, three counted caps (per order, per tenant-day in the tenant's zone via `resolveZone`, per address-day, all statuses), channel send through `RECEIPT_CHANNELS`, 502 `RECEIPT_EMAIL_NOT_SENT` on a provider failure. Also reads `invoice.hideOriginalPrice` and the receipt footer.
- `documents/receipt-limits.ts` (NEW): `RECEIPT_EMAIL_PER_ORDER_KEY` / `_PER_TENANT_PER_DAY_KEY` / `_PER_ADDRESS_PER_DAY_KEY` (`receipts.email.perOrder` ...), defaults 3 / 100 / 5, `resolveReceiptLimit(raw, fallback)` (a positive whole number, else the default; 0 is not "off"). `documents/receipt-channels.ts` (NEW): `RECEIPT_CHANNEL_VALUES` (["email"], parity-pinned to the shared list), `ReceiptChannel`, `ReceiptDelivery`, `ReceiptChannelSender`, `sendEmailReceipt`, `RECEIPT_CHANNELS`. `documents/send-receipt.dto.ts` `SendReceiptDto` (`channel`, `to` trimmed, `IsEmail`). `documents/receipt.controller.ts` `ReceiptController` `POST /orders/:id/receipt` (OPERATOR admits TENANT_ADMIN). `documents/documents.module.ts` NEW module (in `app.module.ts`); `documents/receipt.fixtures.ts` (acme-style test fixtures). `email/email-kinds.ts` +`RECEIPT`. `common/api-error-codes.ts` +`RECEIPT_EMAIL_ORDER_LIMIT` / `_DAY_LIMIT` / `_ADDRESS_LIMIT` (429, final), `RECEIPT_EMAIL_NOT_SENT` (502), `RECEIPT_NOT_AVAILABLE` (409).

## SA-764 reprint and tender; counter pass 2; on-account replay

- `orders/counter-sale/counter-sale-readback.ts`: NEW `isCounterTenderCashRow(p)`, `storedChange(...)` (stored cash tendered less the sale's own original CASH tender rows; null when negative), `servedChange(counterCashTendered, payments, balanceDue)` (THE gate: only a sale whose FIRST stored tender is CASH with nothing left to pay serves a change). The POST and `GET .../by-key/:key` response carry `change`, `cashTendered` (omitted when nothing stored), `tax` (`Order.tax`), `taxRatePercent` (candidate from pricing `storedTaxRatePercent`) and `lines: CounterSaleLinePrice[]` (stored price facts, so the live receipt strikes the same list price as the reprint).
- `orders/counter-sale/counter-sale.service.ts`: the CASH handed over is stored on `Order.counterCashTendered` BEFORE any payment (overwritten until a CASH tender row anchors it, then frozen; a tender that cannot be stored takes no money); the replay serves the STORED tendered for every request method, including ON_ACCOUNT (no tendered stored for a new on-account sale). `isCounterTenderCashRow` anchors the write.
- `orders/counter-sale/counter-sale-today.ts` / `counter-sale-today.service.ts`: Today's sales rows (`toTodaysSaleRow`) now carry `cashTendered`, `change` (same `servedChange`) and `taxRatePercent` (`storedTaxRatePercent` corroborated by `configuredTaxRatePercent`, one read per page). NEW "Hand-overs" fold: `handOverCandidatesWhere(tenantId, w)`, `handOverCandidateSelect`, `HandOverPayment`, `handOverPayments(...)` (v5 group-id filter in code); summary gains `handOvers {count, total}`, included in `moneyIn` and `cashExpectedInDrawer`; the day is now six whole-day queries.
- `orders/counter-sale/pickup-tender-group.ts` (NEW) `PICKUP_TENDER_NS` (fixed namespace, never regenerate), `pickupTenderGroupId(orderId)` (uuidv5 of `orderId:pickup:0`); `common/uuidv5.ts` (NEW) `uuidv5(name, namespace)`. `orders/counter-sale/pickup-complete.service.ts` writes that group id IN the payment create (`invoices/dto/create-invoice.dto.ts` +`RecordPaymentOpts {paymentGroupId?}`, `InvoicesService.recordPayment(id, dto, opts?)`).
- `orders/counter-sale/counter-sale-void.service.ts`: the void returns every unit that was booked out (reads `unevidencedDeliveredFloor` before `clearUnevidencedDelivered`; `orders/order-cancel-tx.ts` takes `bookedFloor`, credit on `max(qty, floor)`).
