## Cash-refund guard: void, delete and cancel refuse after a cash refund (W21b)

Money safety: a counter refund is a Return resolution (`EXTERNAL_REFUND` with `refundedAt`), not a negative payment, so voiding the sale would pay the refunded part twice. Commits: `442770f03`, `5d1630042`, `2347b8f02`, `b6d0595d1`, `f0f48c3f6`.

- `invoices/invoice-cash-refund-guard.ts`: reads-only guards, called ONCE after the row locks and before the first write.
  - `INVOICE_HAS_CASH_REFUND_MESSAGE`, `ORDER_HAS_CASH_REFUND_MESSAGE`: string consts for the two 409 bodies (own wording per surface).
  - `assertNoCashRefundOnInvoice(tx: any, invoiceId: string, orderId: string | null): Promise<void>`: 409 `INVOICE_HAS_CASH_REFUND`. Sources = INLINE returns via `ReturnItem.sourceInvoiceItemId` on the invoice's lines, plus STANDARD returns via `Return.orderId` (conservative on split orders).
  - `assertNoCashRefundOnOrder(tx: any, orderId: string): Promise<void>`: 409 `ORDER_HAS_CASH_REFUND`, same rule over every non-VOID invoice's lines (one `invoiceItem.findMany`).
  - Private: `refuseOnCashRefund`, `inlineSourceFrom`.
- `invoices/invoices.service.ts`: `voidInvoice` calls `assertNoCashRefundOnInvoice(tx, id, inv.orderId)` right after `lockInvoiceRow`; `deleteInvoice` calls it before the recorded-payments check. `voidInvoiceInTx` does NOT repeat it (caller owns the guard; doc comment updated).
- `orders/orders.service.ts`: `changeStatus` cancel path calls `assertNoCashRefundOnOrder(tx, id)` after `lockOrderForCancel`; the order hard-delete transaction (the loop that deletes invoices without `deleteInvoice`) calls it before `assertNoUnspentSourcedCredits`.
- `returns/inline-return-refund.ts`: new `CASH_REFUNDED_RETURN_WHERE` (Prisma where fragment: `refundMethod: EXTERNAL_REFUND_METHOD`, `refundedAt: { not: null }`, `status: { notIn: DEAD_RETURN_STATUSES }`; mirror of `isRefundPending`); new `sourceLineIdsOfInvoice(db: any, invoiceId: string): Promise<string[]>`. It now imports `DEAD_RETURN_STATUSES` from `orders/counter-sale/counter-sale-today.ts` (a returns -> orders import).
- Error codes (declared in `common/api-error-codes.ts`, outside this slice): `INVOICE_HAS_CASH_REFUND`, `ORDER_HAS_CASH_REFUND` (own code for cancel since `2347b8f02`).
- specs: `invoices/invoice-cash-refund-guard.spec.ts` (void: the two codes and messages, INLINE and STANDARD sources, nothing written, code not swapped), `invoices/delete-cash-refund-guard.spec.ts` (delete refuses 409 before any write, guard asked under both locks, a clean sale still deletes), `orders/order-cancel-cas.spec.ts` (cancel with a cash-refunded return: 409 `ORDER_HAS_CASH_REFUND`, nothing written; CAS control cases kept).

## Bulk delete never orphans variants (B1212, W22a-1)

Commit `c8071e277` (web copy: `b04ea8064`, outside this slice).

- `products/products.service.ts`: new exported `interface BulkDeleteSkip { id: string; code: string; reason: string }`; `clearAll()` and `bulkDelete(ids: string[])` return `{ deleted; softDeleted; skipped: BulkDeleteSkip[] }`. Skip codes: `PRODUCT_HAS_ACTIVE_ORDER_ITEMS` (existing refusal, now coded) and `FAMILY_HAS_ACTIVE_VARIANTS` (a product whose variant stays active outside the batch).
