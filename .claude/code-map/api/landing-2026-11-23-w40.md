# API landing, window 40 (master `e43d589f5f`, PRs #4406, #4414, #4416, #4420, #4445, #4446)

Paths under `apps/api/src/` unless they start with another root. Facts read in the merged diffs and the files at `e43d589f5f`. The web halves are in `web/landing-2026-11-23-w40.md`. #4406 and #4414 merged before the window 39 range end but were not in that note. Trust the code over this note.

- **#4406 read-only receipt group (SA-1208 D1 M1-02, SA-1220, SA-1228 A; `a86f4359f4`).** `invoices/payment-receipt-group.ts` (new): `receiptKeyOf(row)` names the kind (`CREDIT_USE`, `SINGLE`, `PICKUP_TENDERS`, `SPLIT_LEG`, `OFFICE_GROUP`) and the key; `readReceiptGroup` returns `{kind, header, tenders[], applications[], unapplied}`. Membership is `receiptKeyOf(row)` equal to the anchor's kind and key, for the anchor's customer; an empty or null group is a SINGLE. VOID rows stay out of the total and the number; the head is the lowest PAID row, else the lowest live row; the lowest payment number is compared numerically. Unused credit comes from the advance linked by `sourcePaymentId`. Nothing is stored and no writer reads it (void and bounce stay per row). `findPaymentById` (via `invoices/payment-list-query.ts`) returns the payment plus `receipt`. Shared type: `packages/types/api/payment-receipt.ts`. Guards: `payment-receipt-group.pin.spec.ts` (void writers address one row, the two payment routes, no till predicate, the buyer-route exception is dated) and `payment-receipt-group.spec.ts`.
- **#4416 PO line stock on hand (P1b, `18c346e323`).** `inventory/inventory.service.ts` PO detail read now selects `currentStock`, `parentProductId`, `variantName` and the parent name on each item's product, and passes the parent through `tenantSafeParentView` (a parent of another tenant is never followed). Spec: `inventory/inventory.po-detail-parent.spec.ts`.
- **#4420 return line, returned items, one word for credit (SA-1211 A1.1, A1.4, A1.7, SA-1231 fold; `2ae81260fc`).** `orders/counter-sale/counter-return-read.ts` gains `readReturnItems` (own try, shared `DEAD_RETURN_STATUSES`, one batched read; each item carries its return's kind and a snapshot of the sold line so a box prints "24 pcs (1 box)"). `counter-sale.service.ts` adds `returnItems` to the split (`CounterTenderSplitFields` in `packages/types/api/counter-sale.ts`). `common/credit-words.ts` is `CREDIT_WORDS_API`, the api mirror of `packages/types/api/credit-words.ts` (`CREDIT_WORDS`), pinned set-equal by `credit-words.spec.ts`; `credit-words.census.spec.ts` fails on a retired word ("Store credit", "Advance balance") in a renderer string outside its shrinking allow-list. `documents/receipt-model.ts` prints "Credit $x" only when credit is kept and each return dollar once. `packages/pricing/src/counter-tender-split.ts` carries the return line math.
- **#4445 one generated-dirs list (`e4c6b5b571`).** `scripts/lib/generated-dirs.cjs` exports `GENERATED_DIRS` (`node_modules`, `.next`, `dist`, `.expo`, `coverage`, `.turbo`, `.jest-cache`); every cross-workspace source scan spreads it instead of a hand-typed `SKIP_DIRS`. `common/generated-dirs.pin.spec.ts` fails a cross-workspace scan (found by `scripts/lib/cross-workspace-specs.cjs`) that declares its own set without it. Cause: web jest renames temp files in `apps/web/.jest-cache` while other workspaces' scans walk it (ENOENT).
- **#4446 nav layout order and hidden (SA-1228 F-2, `e43d589f5f`).** Types only on this side: `packages/types/api/nav-layout.ts` adds `NAV_GROUP_ID_VALUES` (`orders`, `dispatch`, `warehouse`, `finance`, `reports`, `regulated`) and `NAV_LAYOUT_NEVER_HIDDEN` (`/settings`); `order` and `hidden` are now applied by the web.
