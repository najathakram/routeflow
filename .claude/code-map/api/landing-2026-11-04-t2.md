## #4196 `65512e0103` FG-1 WP1: the entitlement sweep (read-only, measuring tool)

- New `billing/entitlement-sweep.service.ts` and `platform-admin/entitlement-sweep.controller.ts`: `GET /platform-admin/entitlements/sweep?cursor=&limit=` (`JwtAuthGuard` + `SuperAdminGuard`; an operator gets 403; pinned in `auth/permissions/permission-map.pinned.ts`). Per tenant: a hashed id, `TenantClass`, `inputsHash` (also hashes each override's live bit at sweep time) and for every gated registry key the bits `old`, `effective`, `strict`, `clientAddon`, `clientFlag`, `courtesy`; plus one row per distinct multi-key `@RequireAddon` set decided by the real `decideAddonAccess`. Each tenant is computed fresh and nothing is written; no business name, slug or raw id leaves the API. The first page also returns `{ mode, planFlagEnforcement }` and nothing else from env; the mode is read with `entitlements-mode.service.ts` `getModeStrict()` (no cache, no fail-open; a failed read puts `modeReadFailed: true` on page 1), serving paths keep `getMode()`.
- `billing/plan-flag-policy.ts` gains `isCourtesyServed`, the one predicate behind the `courtesy` bit (a dark plan flag on a plan that is not always enforced and lacks the flag; a dark add-on key, equal to `decideAddonAccess`'s "dark" outcome; the credit row while `creditLimitCheckApplies(switch, false)`); WP2's resolver is meant to import the same function. `orders/credit-limit-guard.ts` exports the pure `creditLimitCheckApplies(switchValue, tenantHasFlag)` behind `isCreditLimitCheckEnabled`.
- `scripts/entitlement-sweep.mjs` (+ `scripts/entitlement-sweep.self-test.mjs`, root `package.json` script): `--check <file>` classes each row agree, courtesy gap (exit 0 before WP2), unexplained (exit 2), client drift (listed, never fails); exit 3 = file cannot be trusted (no tenants, mode missing, `modeReadFailed`), exit 4 = WP2-STOP (mode live or switch on); precedence 3, 4, 2. `--compare` refuses across a mode or env change (3), treats a key-set change or a differing `resolve_failed` state as a difference (2), and `--new-keys` excuses keys only added in the second file. `--expect wp2` and `--after-wp2` are refused (3), WP2 carries them. The script refuses any non-local base URL unless the owner flag is passed. Production sweeps run per command on the owner's yes, never by an agent.
- Tests: `billing/entitlement-sweep.service.spec.ts`, `entitlement-sweep.sets.spec.ts`, `entitlements-mode.service.spec.ts`, `plan-flag-policy.courtesy.spec.ts` (class pin of the flag clause over every `DARK_PLAN_FLAGS` entry x switch x plan), `orders/credit-limit-rule.spec.ts`, `platform-admin/entitlement-sweep.controller.db.spec.ts` (real Postgres, 6/6).
