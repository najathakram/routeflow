## units-v2-2 (PR #3501, merged as `c9dedd42b`; `30d9b89c5...177a09061`, plus `5b1be185b`, a db-lane spec fix only): price save and undo, customer unit prices read

- `products/product-price-write.service.ts` (NEW) `ProductPriceWriteService.save(...)` / `.undo(...)`: one tx per call. Lock the Product row, re-read the grid model under the lock, compare the client's `priceRevision` AND the `priceState` token (value compare-and-set; legacy writers do not bump the revision), re-plan patches and keeps with the pricing core (client follower values are never trusted), write the pack columns through `materializePack` plus the unit rows, move customer cells under their own row locks with per-cell compare-and-set, bump `priceRevision` once, write ONE audit row holding the inverse. Any mismatch: 409 `LADDER_REVISION_STALE`, nothing written. Refusals: `PRICE_EDIT_INVALID` (400, body `problems`), `PRICE_UNDO_UNAVAILABLE` (409, not this product's save or already undone). SA-809: stored refs go through `canonicalUnitRef`; `baseBackingUnit` decides whether a "base" write lands on a factor-1 row; `addUnitFirst(label)` is the interim refusal when none backs it.
- `products/product-pricing.controller.ts` gains `POST products/:productId/prices` and `POST products/:productId/prices/undo` (same class-level `flag.units_prices_v2` gate). `products/dto/save-prices.dto.ts` (NEW) `SavePricesDto`, `PriceCellPatchDto`, `PriceCellKeepDto`, `CustomerPriceMoveDto`, `UndoPricesDto`, `UndoSkipCellDto`. `products/price-state.ts` (NEW) `computePriceState(product, units, tierUnits)`: the opaque fingerprint of the price-bearing state (5 pack columns, `packAuto`, each unit's id, factor and prices). `product-price-grid.service.ts` now returns `revision`, `priceState`, `tierAnchors`, `tierRules`, per-row `editable` / `notEditableReason`, and keys unit codes by level ref.
