- **#4441 PO lot lines stay in whole packs (SA-1227, SA-1228, SA-1238; `7107badf1d`).** `vendor-bills/bill-line-identity.ts`: `assertWholeLotQty` judges the RESULTING row (incoming pack and qty, stored or derived label) on create and on every edit row (400 `LOT_QTY_NOT_WHOLE`, one text in `wholeLotQtyMessage`); `assertWholeLotReceive` judges each planned receive pair in whole packs (`RECEIVE_PARTIAL_UNIT`, copy names the add, save, remove path); `editedLinePack` is the pack an edit of a stored PO line writes: a labelled line keeps its STORED pack and label, a product change on it is 409 `SPLIT_LINE_LOCKED`, an unlabelled line takes the incoming pack, and only a changed line is judged by an exact Decimal remainder (an untouched legacy part lot is left to the receive check). A locked bill row changes `unitCost` only (description, sku, `lineTotal` compared); an echoed row is relabelled by `billLineUnit` when its unit factor changes. The duplicate-id check is the shared `assertNoDuplicateLineIds` (`common/duplicate-line-ids.ts`). `inventory/inventory.service.ts` `updatePurchaseOrder` calls `editedLinePack`; `receivePurchaseOrder` calls `assertWholeLotReceive` (a 3-line change to `vendor-bills/vendor-bills.service.ts` makes `update()` select the locked fields). Guards: `vendor-bills/vendor-bills.bill-line-unit.spec.ts`, `inventory/inventory.po-edit-whole-lot.spec.ts` (R-rows), `inventory/inventory.po-receive-whole-lot.spec.ts`.
