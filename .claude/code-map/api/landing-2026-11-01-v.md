## #4102 `829ff05a1f` the Piece row takes a first price and creates its unit (SA-1082 PR-1, W-1119)

Rule: a product with no 1-piece unit has an unbacked Piece level. With `flag.units_v1` on, its first typed price creates the factor-1 `ProductUnit` in the price write's own transaction; with the flag off the row is read-only and the write refuses with the same sentence.

- `products/product-price-grid.service.ts`: `get` is now `async` and reads `pieceSellable()` (the tenant's `flag.units_v1` through `entitlements.hasFlag`; a failed read counts as off). An unbacked Piece row is editable with Auto figures and `unbacked: true` when sellable; otherwise read-only with `PIECE_NOT_SOLD` ("Follows the pack price. Selling by the piece isn't on for this business."). New export `PIECE_NOT_SOLD`. `packages/types/api/products.ts` gains `unbacked?: boolean` on the grid cell and a reworded comment.
- `products/product-price-write.service.ts`: `save` runs in `locked(productId, ...)`, which now takes `lockProductPack` first (SA-1045 house order: tenant units lock shared, the product's lock, then the row) and passes `pieceSellable`. A first price, a follower Keep, or a customer price on the unbacked Piece calls `createBaseUnit` (the unit service's `createInTransaction`) inside the same transaction; any later refusal rolls the unit back. With the flag off a price on that level is refused before planning; a blank box has nothing to do. The undo removes the unit the save created through `removeCreatedUnitIfUnused`, unless a price, default or order unit, child, customer price or unit, barcode or any document or template line now rests on it (`anyLineCarriesLabel`); then the price goes blank and the row stays.
- `products/product-units.service.ts`: `create` is split into the locked wrapper and `createInTransaction(tx, productId, dto, actorId)` (the caller holds `lockProductPack`); new `removeCreatedUnitIfUnused(tx, productId, unitId)`.
- Behaviour to know: a `PRICING`-only operator can now create the Piece row through a first price (price routes need `PRICING`, unit routes `CATALOG`); a unit rename can make a price save wait up to 3 s, then 409 `UNITS_RENAME_IN_PROGRESS`; an older line labelled Piece at another size gives 409 `UNIT_SIZE_IN_USE`; a first price may set `packAuto` bits for tier columns already at 0 (the five stored columns and pack figures are unchanged, and undo does not reset the bits). No `priceAuthority` change.
