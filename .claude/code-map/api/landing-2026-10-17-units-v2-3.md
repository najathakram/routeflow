## S19 / S19b customer price layer (all behind `flag.units_prices_v2`; flag off = master's chain byte for byte)

- `orders/units-prices-v2.ts` (NEW) the ONE billing reader of the layer. `customerPricing(svc, customerId, productIds, customer, cpRows, db?) -> CustomerPricing {defaultTier, cpMap, layered, layer(product, label?)}`: flag off returns master's `customer.pricingTier ?? 1` and the raw `cp.pricingTier` map; flag on goes through `customerTierFor` plus the customer's typed `CustomerUnitPrice` rows and `CustomerPrice.orderUnitRef`, resolved by `customerLayerPrice` (@routeflow/pricing). `layer` returns null when the unit is not in the layer.
- Same file: `loadUnitsPricesV2(deps, customerId, productIds, rawTiers)` (asks the entitlement only when a typed row or an odd tier exists; a failed read prices as master), `ladderOptionsOf(product, tierOrderUnits?)`, `loadTierOrderUnits(db, tenantId, productIds)`, `omitCustomerLayerHistory(svc, customerId, history)` (drops last-given prices for packs in the layer: the pre-fill is the resolver's price), `UNITS_PRICES_V2_FLAG`, types `LayerProduct`, `CustomerPricing`.
- `customers/customer-price-layer.ts` (NEW) `buildCustomerPriceLayer(svc, customerId) -> CustomerPriceLayerResponse`: per product with a typed row, one row per sellable unit from `pc.layer` (`ref`, `label`, `price`, `listPrice`, `source`, `aboveList`); `PRICE_LAYER_TYPED_ROWS_CAP` (5000, `complete: false` past it); customer outside the tenant is a 404. `customers/customer-price-layer.controller.ts` (NEW) `GET customers/:customerId/price-layer` (`@Roles(OPERATOR)`, class-level `flag.units_prices_v2`); registered in `customer-unit-prices.module.ts`; `CustomerUnitPricesService.priceLayer(customerId)` delegates.
- `customers/customer-unit-prices.service.ts` takes optional `EntitlementsService`; the K6 view builds `buildLadderView` with the product's own anchor options (`orderUnitRef`, `packAuto`, tier units); the pack row shows source "history" only when the resolved source is tier or list (a typed or layer price beats the sticky price). `customers/customer-price-history.service.ts` takes optional `EntitlementsService`: `references.tierPrice` is the layer price of the newest sale's unit when it is in the layer; keys by `unitNameKey`.
- Staff pricing. `orders/staff-override.ts` `decideTierOverride(product, tier, price, reason, layer?)`: layer price is the baseline, `isSpecialPrice` decides SPECIAL; an echoed above-list layer price is MANUAL with `overridden: false` (R2, no attribution). `orders/staff-line-price.ts` `StaffPricedLine.layerManual`, `aboveList?` on the decide* inputs, `isOverride` ignores `layerManual`. `orders/unit-line-build.ts` `buildUnitLine({..., customerLayer?})` uses the layer's price and list, `layerManual` makes the line MANUAL without a staff stamp. `orders/unit-line-edit.ts` `loadOperatorTiers(tx, customerId, productIds, svc)` now also returns `operatorPc`; `UnitWriteContext.layerOf`.
- Buyer pricing. `orders/buyer-merge-pricing.ts` `resolveBuyerLinePrice(..., layer?)`: layer replaces tier base and beats the sticky price; above-list is MANUAL with no promo; `isSpecialPrice` replaces `isSpecialTier`. `orders/buyer-replace-keep.ts` `priceReplacedLine({layer?})`; `orders/replace-all-line-build.ts` `ReplaceAllLineBuildCtx.layerOf`; `orders/buyer-cart-price-check.ts` `assertBuyerCartPricesCurrent({layerOf?})`: the layer price is the current price, above sticky history.
- `orders/orders.service.ts` create, `updateOrderItems` (buyer edit, add, substitute, edit, replace-all) and change-request add read tiers through `customerPricing`; `getCustomerPriceHistory` returns `omitCustomerLayerHistory(...)`; the POS price-edit gate on a unit line keys on `unitLine.overriddenBy`, so a ladder-priced layer-MANUAL line is never refused for a missing right. `orders/replay-merge-reconcile.ts` (NEW) `replayMergeReconcile(deps, orderId, customerId, appliedCreditNotes)`: the method body lifted verbatim out of the service (size ratchet); the service keeps a delegator. `invoices/paid-window-bounds.ts` (NEW) `tenantCalendarDayStart(dateStr, tz)`, `tenantCalendarDayEnd(dateStr, tz)` lifted verbatim out of `InvoicesService` (now imported functions).
- Invoices / estimates / templates. `invoices/invoice-line-override.ts` `loadOverride(prisma, dto, ladders, actorId, entitlements?)` builds `tierOf` and `layerOf` from `customerPricing`; `LineOverrideCtx.layerOf`; the unit and pack decisions use the layer's list and price, a layer-MANUAL echo is `overridden: false`. `invoices/invoice-edit-plan.ts` `loadEditCatalog` and `invoices/manual-invoice-context.ts` select `packLabel`/`baseUnitLabel`/`orderUnitRef`/`packAuto`; `derivedBaseAsPackItems(..., layerPackPrice?)` stamps an old client's Piece line at the layer pack price; `products/line-units.ts` `normalizeDerivedBaseLine` opts gain `packPrice`. `estimates/estimates.service.ts`, `order-templates/order-templates.service.ts` use `customerPricing` (layer price and list; above-list is MANUAL on estimates; templates pass the layer as the 8th `resolveBuyerLinePrice` argument only when present).
- Other readers. `orders/counter-sale/counter-sale-tier-price.ts` `resolveTierPrices(db, customerId, productIds, svc?)` baseline is the layer price (audit row for a counter-sale edit; `counter-sale.service.ts` passes `svc`). `buyer/buyer-catalog.service.ts` (tile, detail, variants, favorites) and `buyer/buyer-dashboard.service.ts` (`tilePricing`, tiles keep no sticky price) price from `pc.layer(p)?.price` first; `buyer.module.ts` imports `EntitlementsModule`. `returns/inline-returns-quote.service.ts` takes optional `EntitlementsService`: an unreferenced return is credited at the layer price (source CUSTOMER_PRICE). `orders/unit-label-norm.ts` `norm = unitNameKey` (@routeflow/pricing).

## U-1 tenant units settings (`flag.units_settings_v1`)

- `units/units.module.ts` (NEW) `UnitsModule` (imports `EntitlementsModule`, exports `UnitsService`), registered in `app.module.ts`. `units/units.controller.ts` (NEW) `UnitsController`, `@Controller("units")`, class-level `@RequirePlanFlag("flag.units_settings_v1")`, `@Roles(OPERATOR)`: `GET /units` (active array) or `?archived=1&cursor=` (page of 100), `POST /units`, `PATCH /units/:id` (send `name` OR `archived`). - `units/units.service.ts` (NEW) `UnitsService`: `list()`, `listArchived(cursor?) -> {items, nextCursor}` (cursor = base64url of [db lower(name), id]), `create({name}, user)` (idempotent by `nameKey`; an archived match is restored with its id; unique-index race ends as one row), `update(id, dto, user) -> {unit, productsUpdated}`. Rename takes the tenant units lock EXCLUSIVE in one 60 s tx, refuses the whole rename on a product collision (409 `UNIT_RENAME_COLLISION`, `UNIT_NAME_TAKEN`), relabels linked levels and base/pack/unit text in chunks of 5000, writes the `tenant_unit.renamed` audit row inside the tx.
