## #3801 fix(api): stamped pickup cash refund takes the till lock (W-829)
- `returns/counter-close-lock.ts`: new `tillRegisterOfSale(order)` (register a REFUND is counted on: `registerKeyOfOrder`, else the stamped `registerKey` of a `FulfillPath.PICKUP` order) and `tillRegisterStampedUnderLock(tx, orderId, lockedRegister)` (re-reads the stamp after the Order row lock; true means a hand-over stamped it while the refund waited, so the caller stops).
- `returns/returns.service.ts` (external refund) and `returns/inline-returns.service.ts`: `registerKeyOfOrder` -> `tillRegisterOfSale` (selects widen to `fulfillPath`); when the stamp appears under the Order lock they throw `refundBusy()` (retryable 409) so the retry takes the close lock first. A stamped pickup cash refund now leaves the same drawer, takes the same close lock and is refused in a closed window.
- `orders/counter-sale/counter-sale-today.ts`: the today-sales order filter becomes `counterSale: true` OR (`counterSale: false`, `fulfillPath: PICKUP`, `registerKey` not null), the same definition the hand-over candidates use.
