# Api landing, window 48 (master `e30d385326`; members merged as PRs in order, no train branch)

Paths under `apps/api/src/` unless they start with another root. Window 48: #4336 `797e535c74` (web only), #4340 `573f754868` (web only), #4343 `6881bdea16`, #4344 `c7c41e9d4a`, #4325 `e30d385326`. The web parts are in the web landing note of the same date.

- **#4344 one home for billing return addresses (SA-1146 B-1).** `billing/billing-return-paths.ts`: `API_BILLING_RETURN_PATHS` (`plan`, `pay`, `cardAdd`), `API_BILLING_PORTAL_RETURN_PATH`, `API_BILLING_CANCEL_PATH`, `billingReturnUrl(base, path)` (one slash between them) and `assertBillingReturnUrl(kind, url, base?, tenantId?)`, kinds `success`, `cancel`, `embedded_return`, `portal`. Compiled API code cannot value-import `@routeflow/types`, so the constants are a local copy pinned equal to the shared `BILLING_RETURN_PATHS`, `BILLING_CANCEL_PATH` and `BILLING_PORTAL_RETURN_PATH` (`packages/types/api/billing.ts`).
  - Invariant: the check is exact string equality against the addresses built from the web base, at the two boundaries where an address reaches Stripe: `billing/checkout-session-params.ts` `withCheckoutPolicy` (a present `return_url` is judged by presence, in both modes; the embedded address is checked after conversion) and the portal wrapper in `billing/stripe.service.ts` (optional `tenantId`, passed by `billing.service.ts`). A mismatch logs one `BILLING_RETURN_URL_MISMATCH` line (kind, received with a concrete `session_id` redacted, allowed list, tenant) and throws a plain 500 with no address in it.
  - The dto override of the return address is gone (`billing/dto/create-checkout.dto.ts`); `catchup-checkout.service.ts`, `payment-due.service.ts`, `settings-billing.controller.ts`, `billing-notification.templates.ts` and `platform-admin/platform-admin.service.ts` read the home constants.
  - Pins: `billing/billing-return-paths.spec.ts` (unit table, log-line fields, a source scan for any other billing page literal with one named, count-pinned exclusion, a walk row naming edge files), `billing/billing.checkout-anchor.spec.ts`.
- **#4343 a draft cannot be delivered on the spot (SA-1158).** `orders/orders.service.ts` `create`: `status: "DRAFT"` with `immediateDelivery` is refused with a 400 `ORDER_DRAFT_CANNOT_DELIVER_NOW` before any read or write; the two delivery writes also read `!isDraft`. The code is in `common/api-error-codes.ts` and mirrored in `packages/types/api/error-codes.ts`. Pins: `orders/orders.create-run-stop-refs.spec.ts`, `orders/offline/order-status-writers.pin.spec.ts`.
- **#4325 price edits are enforced whatever the permissions mode (W-870).** `auth/permissions/price-edit.ts` `mayEditPrice` no longer reads the global mode: the deny list is read live at every site, a failed read throws (fails closed), and an OPERATOR the deny list or a missing row refuses logs one line (group, site, tenant; no name, no price). A role that never edits prices (buyer, driver) asks the answer on every request and logs nothing. `auth/permissions/operator-permissions.service.ts` `priceEditAllowed` is `priceEditReported(role, groups, ALL_PERMISSION_GROUPS)`, with no mode argument; `GET /users/me/permissions` still reports mode `shadow` (the guard only logs). Callers in `orders/orders.service.ts` and `orders/counter-sale/counter-sale.service.ts`; test helpers `common/testing/no-rights-actor.ts` and `operator-with-rights.ts` carry the new shape. Pins: `auth/permissions/price-edit.spec.ts`, `price-edit-answer.spec.ts`, `orders/price-edit-sites.pin.spec.ts`, `orders/price-edit-capability.db.spec.ts`.
