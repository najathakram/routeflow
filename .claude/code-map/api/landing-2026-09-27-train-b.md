- **#1271:** yes — a test named for a serialization property ("retries ONE AT A TIME, no duplicate rows") can pass while only checking a mock's call count instead of the actual rendered/committed state; when a fix depends on real commit-vs-read ordering (e.g. `flushSync`), the regression test must assert on genuine state (a stateful harness / rendered DOM), not a proxy for it, or it will stay green whether or not the fix under test is present.
- **#2264:** yes — after adding a server-side session-ending disconnect (e.g. on token expiry), always audit client reconnect behavior explicitly: socket.io (and similar libraries) never auto-reconnects after an intentional `"io server disconnect"`, so a security/session change on the server can silently kill a client feature (live tracking/notifications) with no error surfaced to the user.
- **#2259:** yes — a product's configured "unit" field is its SELLING/box unit, not automatically the correct noun for a raw piece count; any call site that formats a bare piece/remainder quantity must use a fixed "pcs" fallback (or the shared formatter's default), never the product's own `unit` string, or boxed products render nonsense like "6 box" for a piece remainder.
- **#2261:** yes — when adding a new role to a dashboard/layout (e.g. DRIVER), audit every existing data-fetching hook on that page/layout for its role gate; hooks are commonly OPERATOR/CUSTOMER-scoped on the backend, and a UI hook with no matching `enabled` gate will fire on mount for every role, producing silent background 403s and broken error cards for the ungated role.
