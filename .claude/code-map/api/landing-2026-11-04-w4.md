## #4204 `05ca937643` SA-1101 refused order (Batch 3): REFUSED is a status

- **One stop-outcome step.** `routes/stop-outcome.ts` `applyStopOutcomes(tx, stopOrders, closedAt)` runs after the `deliveredQty` recompute and reads every candidate order's lines once; `orderOutcomeAfterStop` (`packages/pricing/src/delivery-plan.ts`) says REFUSED only when every line is at 0, else DELIVERED. DELIVERED writes `deliveredAt = closedAt` (B778), REFUSED writes `deliveredAt = null`. `notifyStopOutcomes` sends one notice per flipped order of its own kind (`ORDER_REFUSED` carries no total). `completeStop` and `completeWithPayment` both call it; the blind `status: DELIVERED` write is gone (a pin spec counts the two call sites). `routes.service.ts` size baseline 3103 -> 3071 (the step moved out).
- **B785 (high, money).** `routes/complete-payment-reconcile.ts` `assertEveryOpenLineCovered`: a close with no `deliveries` entry for a line that still has something left (read through `lineRemaining`; the re-visit shape the clients send is accepted) is `400 STOP_DELIVERY_LINES_MISSING`, nothing written. **B782:** `updateRunStatus` stamps `startedAt` on IN_PROGRESS or COMPLETED when unset, not on a cancel. **B778:** `reopenStop` clears `deliveredAt` and also reverses a REFUSED order. All three closed in the registry with this note (ledger F64).
- **Terminal lists by name.** `common/terminal-order-statuses.ts` (`TERMINAL_ORDER_STATUSES` = DELIVERED, REFUSED, CANCELLED; `POST_DELIVERY_ORDER_STATUSES` = DELIVERED, REFUSED; `isTerminalOrderStatus`, `isPostDeliveryOrderStatus`). The api keeps its own copy, not an import of `@routeflow/types` (api source never imports that package as a runtime value); `common/terminal-order-status-lists.spec.ts` pins both copies set-equal to `packages/types/api/enums.ts` and fails any new array that names DELIVERED and CANCELLED without REFUSED or a shared name. REFUSED joined `invoices/pending-mirror.ts` (otherwise the $0 draft is re-mirrored at the full amount on the next edit), `invoices/credit-exposure.ts` (non-backing), the carrier/fulfil-path locks, `invoices/order-edit-revert-set.ts`, `products/product-delete-classify.ts`, `routes/routes.constants.ts`, `routes/route-realtime.ts` and the order status transition table (`orders/order-status-transitions.ts`).
- **Deliver again.** `orders/deliver-again.ts` `deliverAgainInTx`, called from `updateStatusWithShipMarker` (0 lines added to `orders.service.ts`): REFUSED -> CONFIRMED only, under the Order row lock a return create also takes. It refuses `409 ORDER_HAS_RETURN` while any return is not REJECTED or CANCELLED, and clears `routeRunId` + `routeRunStopId` when the linked stop is COMPLETED (or a bare link to a COMPLETED or CANCELLED run) with one compare-and-set; anything else is `409 ORDER_RUN_LINK_CHANGED`, nothing written. `returns.service.ts` `create` re-reads the order status after its `FOR UPDATE`, and returns of REFUSED orders are accepted (`returns/returns.service.ts`).
- **Undo the stop with a live return.** `returns/live-return-guard.ts`: `assertNoLiveReturn(tx, orderIds, message)` (REJECTED and CANCELLED are dead, everything else live) and `lockThenAssertNoLiveReturn` (locks the stop's Order rows with `lockOrderRows`, then counts). Exactly two callers, pinned by the census `live-return-guard.structure.spec.ts`: `deliverAgainInTx` and `RoutesService.reopenStop`, whose first statement in its transaction is the lock-first helper; `409 ORDER_HAS_RETURN` with `UNDO_STOP_RETURN_MESSAGE`. Without it, undoing a refusing stop on an order with a received return deleted the mutation rows and left the return's stock credit standing. **Open follow-up (not built):** the office DELIVERED -> CONFIRMED / PARTIALLY_DELIVERED demotion of an off-route order with a live return needs the same guard as a third caller, added to the census on purpose.
- **Delivered line stays.** `orders/delivered-line-lock.ts`: removing a delivered line (CANCEL, DELETE, substitute) is `409 LINE_ALREADY_DELIVERED` on any status ("record a return"); the full change lock stays pending-delivery only. Supersedes SA-961 R10 row 307 (the old strike-off); `orders.edit-live-lines.spec.ts` row 307 now pins the 409.
- **Buyer notice.** `messaging/notification-triggers.ts` and `messaging/messaging-config.service.ts`: `ORDER_REFUSED` ("your order {{orderNumber}} was refused at delivery"), EMAIL + PORTAL on by default, covered by the buyer opt-out; missing rule rows are seeded lazily, copying DELIVERED's enabled flag (`seed-enabled-from.spec.ts`).
- **Codes** (`common/api-error-codes.ts` and `packages/types/api/error-codes.ts`, parity spec): new `STOP_DELIVERY_LINES_MISSING` and `ORDER_HAS_RETURN`; `ORDER_RUN_LINK_CHANGED` and `LINE_ALREADY_DELIVERED` already existed.
- Behaviour changes for live businesses: a wholly refused stop is now REFUSED (its invoice is the delivered-basis $0 and the buyer gets the refusal note); a stop close with a line missing is a 400; a delivered route or counter line can no longer be deleted or cancelled in an order edit.
