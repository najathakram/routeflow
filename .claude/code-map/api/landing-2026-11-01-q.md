## #4066 `c06c9ef48c` customer account statement: one read, two routes (W-1096, SA-1078 PR-1)

Rule: one function answers "what does this customer owe, on which invoices, what was paid and what was not". Every figure is the server's, in dollars rounded to the cent; the screens never add, net or clamp. The open balance is the sum of each open invoice's CLAMPED balance, so rows add up to the total and an overpaid invoice adds 0.

- `customers/account-statement.ts` (new): `buildAccountStatement(prisma, customer: { id, businessName, email? }, opts: { staff: boolean; now?: Date }): Promise<AccountStatement>`; `daysLateOn(tenantDay, dueDate)` (whole calendar days past due on the tenant's calendar, 0 when due today / not yet due / no due date; same count as web's `daysPastDue`); consts `STATEMENT_RECENT_DAYS = 30` (day 30 in, day 31 out; window start is the tenant's local midnight 30 days back, so it holds across a clock change) and `STATEMENT_RECENT_PAYMENTS = 50`.
  - One clock per statement (`opts.now ?? new Date()`): `asOf`, `daysLate`, overdue, open balance and the window all read it. Zone from `tenantTimeZone(prisma)`.
  - Reads (parallel, `prisma.forTenant()`): invoices of the customer with `status notIn KPI_SUMMARY_EXCLUDED` (so DRAFT, PAID, VOID, WRITTEN_OFF are never receivable), credit notes `status != VOID`, advances with `balance > 0` (the advance `notes` field is never selected), and `CONFIRMED_PAYMENT` invoice payments dated `settledAt ?? paidAt` inside the window. Newest-first order and the 50 cap are applied in code.
  - Open rows: only `OPEN_INVOICE_STATUSES` with `classifyInvoiceBalance(...).balanceDue > 0`; `unpaid` is that clamped balance, `paid` = `splitConfirmed().cash`, `credit` = credit-note applied + advance applied. `waitingToClear` = sum of PENDING payment amounts on the customer's invoices. Staff adds `emailOnFile` and each row's `toCollect` (`toCollectState`); the buyer view leaves both keys out.
  - Credits: a credit note with `remaining = amount - amountUsed > 0.001` and not expired (`expiresAt <= now` drops), plus advances with a balance. `afterCredit = max(0, openBalance - creditAvailable)`. `recentPayments[].kind` is `CREDIT` for `CREDIT_NOTE_METHOD` / `ADVANCE_METHOD`, else `PAYMENT`; `recentPaymentsTruncated` is true when more than 50 fell in the window. Dates are tenant-zone `YYYY-MM-DD` strings.
- `customers/customer-statement.ts`: new exported `statementOutstandingAmount(open, timeZone, now = new Date())` (= `summarizeOpenInvoices(open, overdueCutoff(now, zone)).unpaidTotal`); `statementOverdueAmount` is now exported and takes an optional `now`. `buildMyStatement` and `buildOperatorStatement` both set `outstanding = statementOutstandingAmount(...)` with ONE `tenantTimeZone` lookup per statement. Behaviour change on the older statements: `outstandingAmount` was the signed net (`sum(total - paid)`, an overpaid invoice netted the others down, row 326) and is now the clamped sum, so it can no longer read below the overdue figure.
- `customers/customers.service.ts`: `getAccountStatement(customerId, opts: { staff: boolean })` resolves the customer with `findCustomerOrThrow` (404 on another tenant's id) then calls `buildAccountStatement`.
- Routes: `GET /customers/:id/account-statement` (`customers.controller.ts`, `@Roles(OPERATOR)`, `@RequirePermission("FINANCE", "CUSTOMERS")`, staff view) and `GET /buyer/account-statement` (`buyer/buyer.controller.ts`, `BuyerSellerContextGuard` + `BuyerTenantInterceptor`, `X-Tenant-Slug` header, calls `getAccountStatement(ctx.customerId, { staff: false })`).
- `auth/permissions/permission-map.pinned.ts`: two new pins, `BuyerController.getAccountStatement` = `UNGUARDED`, `CustomersController.getAccountStatement` = `FINANCE|CUSTOMERS`.
- `packages/types/api/statement.ts` (new, re-exported from `packages/types/index.ts`): `AccountStatement`, `AccountStatementInvoice`, `AccountStatementPayment`, `AccountStatementCredit` (the api imports them type-only).
- Tests: `customers/account-statement.spec.ts` (S10 daysLate, A-3 tenant days, S13/S14 recent payments, S17 buyer's view), `customers/account-statement.db.spec.ts` (Postgres, `describeDb`), `customers/customer-statement.clamped-total.spec.ts` (S1-S3), `buyer/statement.service.closing-guard.spec.ts` (S20: the monthly PDF closing equals the open balance on a plain fixture), `invoices/overdue-readers-inventory.spec.ts` (note and pattern for `customers/account-statement.ts`; the overpaid case now expects 0 and 50; S21 pins that both builders take the total from `summarizeOpenInvoices`).

## #4074 `d8fc5aa9fe` one-job self-hosted runner for Verify on train heads (CI tooling, no api source)

Routine and threat model: `docs/runbooks/self-hosted-runner.md` (new). No `tools/` area file exists, so the signatures are here.

- `tools/ci-runner/launch-once.mjs` (`--branch <train/name> [--cpus 0-3] [--memory 16g] [--max-minutes 60]`) and `tools/ci-runner/check-no-runner.mjs` are thin entry files that hold NO entry guard (a guard can read false through a link and skip the work with exit 0): `process.exit(await launch(parseFlags(argv)))` and `process.exit(checkNoRunner())`. Both call into `tools/ci-runner/runner-lib.mjs`.
- `runner-lib.mjs` exports: consts `REPO`, `EXIT_NOT_PRIVATE = 3`, `EXIT_FOREIGN_QUEUED = 4`, `EXIT_LIVE_RUNNER = 1`, `EXIT_UNREADABLE = 2`, `GH_TIMEOUT_MS = 20_000`, `UNSAFE_AFTER_MS = 45_000`, `JOB_STARTED = /: Running job: /`; `parseFlags`, `gh(args, input, exec)` (20 s deadline), `foreignQueuedRuns(ghFn)` (runs in queued/waiting/requested/pending/in_progress whose head repo is not `REPO`), `jobOrigin(runnerName, branch, ghFn)` (`"ours"` only for a same-repo `workflow_dispatch` on the branch, else `"foreign"`, `null` until GitHub shows it), `deleteRunner(id, ghFn)` (`"gone"` also on 404, else `"refused"`), `dockerArgs(name, flags)`, `pollOnce(state, io)` (`wait` / `stop` / `stop job` / `remove`), `noteRunnerLine`, `runContainer`, `launch(flags, deps)`, `checkNoRunner(ghFn, error)`.
- `launch` refuses (exit 2) without `--branch`, with a branch that is not `train/<name>`, or with `--max-minutes` outside 1..80. Then, inside a heavy-slot seat (`withHeavySlot`, label `ci-runner-verify`, exit 5 with no seat token): exit 4 if any non-`REPO` run is active, exit 3 if the repo is not PRIVATE, else mint a one-job JIT runner (`rf-ephemeral-<ts>`, labels `self-hosted Linux X64 routeflow-ephemeral`) and run the container. Outside the seat it deletes the runner, retrying up to 60 times 15 s apart (a killed job's runner stays busy until its run closes).
- Guard loop (every 15 s): past the deadline = stop; an idle runner with a visibility reading other than PRIVATE, or no PRIVATE reading for 45 s, is removed (fail closed); once the runner prints "Running job" the job must be ours within 120 s or the container is stopped. Image `routeflow-ci-runner:2.338.2-r2`, docker network `routeflow-ci-runner`.
- `dockerArgs`: `--cap-drop ALL` then only NET_ADMIN, SETUID, SETGID, SETPCAP (for `entrypoint.sh`'s root phase), `no-new-privileges`, IPv6 off, `--cpuset-cpus`, `--memory` = `--memory-swap`, `--pids-limit 8192`, `--rm --init`; no socket, volumes, secrets or host env.
- `check-no-runner` (the flip check): exit 0 only when `GET repos/<repo>/actions/runners` reads `total_count` 0; exit 1 when a runner is registered (names listed); exit 2 when the read fails or the count is not a non-negative integer. A public repo lets a fork PR reach a self-hosted runner, so every public flip is `node tools/ci-runner/check-no-runner.mjs && gh repo edit ... --visibility public ...`. Same line in `docs/runbooks/deploy-visibility-flip.md` (step 1), `docs/runbooks/claude-md-details.md`, `.claude/skills/rebuild/SKILL.md`.
- `tools/ci-runner/Dockerfile` (ubuntu 24.04, runner 2.338.2 pinned by sha256, user uid 10001, no credential) and `entrypoint.sh` (reads the one JIT config from stdin; iptables allow only loopback, established, tcp 80/443 and udp 53, reject private ranges; `setpriv` drops to uid 10001 with every capability cleared; the container ends with the first of runner exit, stdin close (launcher died) or a 5400 s sleep).
- `.github/workflows/ci.yml`: `workflow_dispatch` gains input `runner` (choice `hosted` | `self-hosted`, default `hosted`). The `verify` job gets `permissions: contents: read`, `runs-on` = the `self-hosted` + `routeflow-ephemeral` labels when `inputs.runner == 'self-hosted'` else `ubuntu-latest` (inputs is empty on every event but dispatch, so a PR always runs hosted), and checkout `persist-credentials: ${{ inputs.runner != 'self-hosted' }}`. The `e2e-gate` job's `if` excludes a `workflow_dispatch` with `runner == 'self-hosted'`, so a self-hosted dispatch runs Verify alone. Header rule 1 now allows that one exception.
- Root `package.json` `verify` script runs `node tools/ci-runner/launch-once.self-test.mjs` (after `verify-gate.self-test.mjs`).
- Tests: `tools/ci-runner/launch-once.self-test.mjs` (plain node, fakes for gh, docker and the seat; covers flags, refusals and exit codes, `pollOnce`, `jobOrigin`, `dockerArgs`, `checkNoRunner`, and that both entry files still run through a linked folder); `apps/api/src/common/ci-freshness-guard-script.spec.ts` (`jobs.verify.permissions` now equals `{ contents: "read" }`).
