## R5.1: an unpaid bank-debit checkout links but never activates (P0 hotfix)

- `billing/billing.service.ts`: `SETTLED_CHECKOUT_PAYMENT_STATUSES = {paid, no_payment_required}`. `onCheckoutCompleted` now links customer, subscription, period and plan for ANY session but writes the APPLIED marker and runs the non-ACTIVE to ACTIVE transition only when `payment_status` is settled; an unpaid (ACH/SEPA) session logs `checkout.awaiting_async_payment` and returns.
- Same file: `alreadyLinked = existingOverride.stripeSubId === subscriptionId` skips the newer-downgrade re-judgement and nulls `planKeyForCheckout`, so settling a linked session only activates. The webhook switch gains `checkout.session.async_payment_succeeded` (re-runs `onCheckoutCompleted` on the now-PAID session) and `checkout.session.async_payment_failed`.
- NEW private `onCheckoutAsyncPaymentFailed(session)`: ONE `recordCheckoutRefusal` audit row (`STRIPE_CHECKOUT_ASYNC_FAILED_ACTION`) plus a platform notice via `writeAdminNotice`; says "ACTIVE and UNPAID" when `hasAppliedMarker` finds a pre-hotfix activation. Nothing is cancelled (SA-774r2 follows).
- `billing/config-snapshot-audit.constants.ts` +`STRIPE_CHECKOUT_ASYNC_FAILED_ACTION` ("STRIPE_CHECKOUT_ASYNC_PAYMENT_FAILED"); `platform-admin/audit-actions.constant.ts` +`AdminAuditAction.STRIPE_ASYNC_PAYMENT_FAILED` and its `ADMIN_AUDIT_ACTION_LABELS` entry.

## R4.2: one classification of till money (rows 374, 342)

- `orders/counter-sale/window-payment-groups.ts` (NEW) `groupWindowPayments(payments) -> {byMethod, notAtTill, handOver: {count, cash}}`, types `WindowPaymentRow`, `WindowPaymentGroups`: PAID only; a CREDIT_NOTE/ADVANCE application is its own method, a counter tender row (`isCounterTenderRow`) is money in, anything else is `notAtTill`. `handOver.count` is DISTINCT orders (a CASH plus CARD row of one order is one hand-over).

- `counter-sale-today.ts`: `salePaymentsWhere` and `handOverCandidatesWhere` use `InvoiceStatus.VOID` only (a written-off invoice keeps its cash in the day; a CANCELLED order's money is not the day's); NEW `salePaymentSelect`; `handOverCandidateSelect` +`paidAt`, `status`, `checkStatus`, order `orderNumber`/`registerKey`/`soldBy.username`/`customer.businessName`; `handOverPayments(rows)` uses `isCounterTenderRow` (a deposited check is foreign, as in the Z).
