- **#2387:** yes, reusable — a "delete-and-rebuild-from-order" pattern will always drop any invoice-only line (fees booked straight onto the invoice with no order-side mirror); the generalizable rule is that any such rebuild must enumerate and explicitly preserve invoice-only line classes via a shared predicate, never assume the order's lines are the complete set.
- **#2398:** yes, reusable, and worth citing directly for B874/#2391 — two call sites (`changeStatus`, `resolve`) had independently invented ownership checks of different strength (one had none, one checked only `order.routeRun.driverId` with no run/stop status); the rule is "one ownership predicate per role check, shared and re-derived under the lock at every write," not a bespoke check per endpoint. This is the same class of bug as B718/SA-388 below — logic duplicated by hand instead of centralized drifts apart.
- **#2220:** yes, reusable — `boxes ?? qty` (then its "fix" to fall back to raw `qty`) silently conflated a unit count with base-unit pieces; the rule is that a value with two possible units (count vs. pieces) needs one named derivation function with an explicit "no safe answer" (LOCKED/null) state, never an inline `??` fallback chain.
