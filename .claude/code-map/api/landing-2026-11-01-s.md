- `returns/inline-returns-quote.service.ts`: constructor gains a last `@Optional() featureConfig?: FeatureConfigService`. `priceInlineReturn(dto, user, db, opts)` opts gain `editingOrderId?: string`; `quote()` passes `dto.editingOrderId`. The excluded invoices are `opts.excludeInvoiceIds ??` (when `editingOrderId`) `quoteExcludedInvoiceIds(...)`, resolved after the buyer and driver checks, so the matching set, the lifetime read and the never-sold read all use the post-revert set. Local `neverSoldToCustomer(productId)`: one cached `invoiceItem.findFirst` per product (qty > 0; this customer, not in the excluded ids, status in `ACCRUAL_REVENUE_STATUSES` or a DRAFT of a delivered order), asked only for a product with an unreferenced chunk; its own read, not `fetchMatchingSet`, so an invoice with no order still counts as a sale. Throws on an empty customer or product id.
- `returns/inline-returns.service.ts`: capture sets `restock: c.neverSold ? false : (dtoItem?.restock ?? restockDefault(reason))`: neither the reason nor a DTO `restock: true` can switch it on.
- `returns/dto/quote-inline-return.dto.ts`: `editingOrderId?` (optional non-empty string): the order being edited, or the merge target.
- `invoices/order-edit-revert-set.ts`: new `quoteExcludedInvoiceIds(db, customerId, orderId, featureConfig): Promise<string[]>`. Reads the order (this customer's; any other is 400 `SOURCE_SALE_INVALID`) and applies the edit's own routing (`carrierEditGuard`, `resyncsInPlace` from `orders/order-carrier-guard`): an order out for delivery, delivered or with the carrier reverts nothing (`[]`); otherwise `selectEditRevertedInvoices`' ids, so the quote prices what the edit's dry run and capture see.
- Shared (api imports): `packages/types/api/inline-returns.ts` gains `QuoteInlineReturnRequest.editingOrderId?` and `InlineReturnQuoteChunk.neverSold?` . `packages/returns/src/inline-return-state.ts`: `buildQuoteRequest(..., sourceOrderId?, editingOrderId?)` (last positional arg; the field rides only when set) and `LineQuoteFacts.neverSold` (`chunks.some(c => c.neverSold === true)`).

## #3976 `aea8e9f452` regulated credit reversal room (SA-1042 A-4, with SA-1054 A-1..A-5 follow-ups)

Rule: a typed credit row on a REGULATED line (tracked category) must fit what the ledger can still reverse on its ORDER line, or the item stores a levy the filing never books. One predicate serves the booking and the create-time bind.

- `regulated/credit-reversal-room.ts` (new; MOVED out of `reverseCreditNoteEntries`). Exports `ROOM_EPS = 0.005`, `LineBag { net; qty; unitBasis; tax; items }` (`items` = ledger rows folded in), `emptyBag`, `CreditReversalRoom` (`saleByLine`, `revByLine`, `lineRows`, ...), `ItemRoom` (`lineKey`, `already`, `remNet`, `remQty`, `remUnitBasis`, `remTax`). `loadCreditReversalRoom(db, items, { excludeCreditNoteId?, onUnmatched? }): Promise<CreditReversalRoom | null>` (null when no item names an invoice item; `excludeCreditNoteId` leaves a reissue's note out). `creditItemRoom(room, item): ItemRoom | null` (null = no live SALE or the line sold nothing: no naked reversal). `creditRoomRefusal(db, rows: CreditRowInput[], { excludeCreditNoteId?, derivedQtyItemIds? }): Promise<CreditRoomRefusal | null>`: first typed row whose amount or qty passes the remaining by more than 0.005; folds accepted rows into a local bag so a second row on a line sees the reduced room. A row that takes ALL the qty left may pass the money by `creditDriftTol(left.already.items)`. A row with no typed qty (`derivedQtyItemIds`, the web form) is held to the money left, not its derived qty. Rows without a tracked category (non-regulated, SA-628 return-refund) and lines that never booked a SALE are not bound. Reads only.
- `regulated/regulated-ledger.service.ts`: `reverseCreditNoteEntries` calls `loadCreditReversalRoom` (`onUnmatched` -> `reportUnmatchedCredits`) and `creditItemRoom` per item, then books as before (its `revByLine` bag now counts `items`).
- `credit-notes/credit-notes.service.ts`: before the items total check, `creditRoomRefusal(db, cnItemsData, { excludeCreditNoteId: opts.excludeCreditNoteId, derivedQtyItemIds })` (derived = merged lines with `qty == null`); a refusal throws 400 `CREDIT_NOTE_OVER_HEADROOM` (existing code).
- `credit-notes/line-credit-headroom.ts`: new `creditDriftTol(priorItems: number): number` = a cent plus half a cent per prior item, capped at 5 cents; `planProductRefund`, `lineTakeRefusal`, `pooledTakeRefusal` use it (same figures).
- `regulated/credit-reversal-census.ts` (new, read only): `censusOldTypedCredits(db, { tenantId? }): Promise<CreditReversalCensus>` (`typedItems`, `itemsWithLiveSale`, `itemsWithoutLiveSale`, `notesBookedLessTaxThanStored`, `sample`, `denominators`) and `loadDenominators(db, { tenantId? })` (counts only). A return or credit REVERSAL does not unbook a SALE, so "live" ignores them.
- `scripts/report-a4-credit-reversal-census.mjs` (new, `apps/api/scripts/`): owner-run runner. Flags `--target-host=<host>`, `--self-test` only (any other flag, a write flag too, is refused).
