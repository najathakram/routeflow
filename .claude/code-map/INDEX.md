## Stack & shape

Multi-tenant delivery / route-management SaaS. **npm workspaces + Turbo** monorepo.

- **API** — [`apps/api`](api.md): NestJS 11, Prisma 7 + PostgreSQL, Redis (Socket.io), JWT auth.
  Everything tenant-scoped. Jest specs.
- **Web** — [`apps/web`](web.md): Next.js 14 App Router. The **golden reference** for flows/DTOs.
  Radix + Tailwind, TanStack Query, RHF + zod. Playwright e2e **+ Jest/RTL unit tests (wave D,
  2026-09-03 — 19 spec files; was E2E-only before)**.
- **Mobile** — [`apps/mobile`](mobile.md): Expo 55 / RN 0.83, expo-router, multi-role. Mirrors
  web's API/DTOs/flows; only UI differs. Jest (pure-logic).
- **Packages** — [`packages`](packages.md): `types`, `ui`, `config`, `eslint-config`,
  `typescript-config`.
- **Deploy**: Railway via per-app Docker. `CMD = node dist/main.js` only — never auto-migrate.

## Entry points

- **api** → `apps/api/src/main.ts` — boots Nest on `:3000`, global prefix `/api/v1`, health
  `GET /api/v1/health`. Runs from compiled `dist/main.js` (watch mode is broken).
- **web** → `apps/web/app/layout.tsx` (+ `app/providers.tsx`) — `next dev` on `:3001`.
- **mobile** → `apps/mobile/app/_layout.tsx` — `expo start`. Deep-link scheme `routeflow://`.

| Lockfile integrity / "npm ci installed a hole"                               | `scripts/validate-lock-edges.mjs` (`npm run validate-lock`, `--verbose`) — walks EVERY package-lock entry's deps by node_modules walk-up with root `overrides` applied; the check arborist never does. Gates on MISSING (the #488 jest-coverage-chain class), on a workspace range that a root override contradicts (npm 10's `ci` validator is override-unaware → ~97-error phantom cascade; the #488 root cause), and on SKEWs outside the `TOLERATED_SKEWS` baseline. Runs as ci.yml's **`lock-integrity` job PRE-install** (an override-break makes `npm ci` itself die on the phantom cascade, so a post-install gate could never reach that case) + **step 1 of `npm run verify`** (so the pre-push hook gates the lock). The CI job fetches semver into an ISOLATED scratch dir + `NODE_PATH` — `npm install <pkg>` at a workspaces root re-resolves the whole tree (>10min, measured); pin is asserted on load (major mismatch = exit 2) and must move together with `EXPECTED_SEMVER_MAJOR`. `--edges-only` = zero-dep reachability mode; a missing semver is exit 2, never a silent partial pass. | Lessons-register integrity / "the count merged wrong"                        | `scripts/validate-lessons.mjs` (`npm run validate-lessons`, `--verbose`) — the check a MERGE never does. `_meta.json`s `activeCount`/`archivedCount`/`nextId` are counts OF the files beside them, so a union merge of two branches that each appended an entry leaves BOTH sides individually correct and the total neither, with **no conflict marker** (entries land in different `##` sections). Observed live 2026-09-01: 28 + 2 + 2 merged to a file of 32 declaring 30. Gates on COUNT MISMATCH, DUPLICATE ID (within a file and ACROSS both — a compaction must MOVE, not copy), NEXTID (must exceed the max id in EITHER file; archived ids are retired, never reissued), DANGLING REF (a `[[L-0xx]]` naming no existing entry — this is what makes ids safely immutable), CONFLICT MARKER, and OVER CAP. ⚠️ **Caps are DATA** (`_meta.maxEntries`/`maxBytes`), not constants, so an owner ruling is a field edit. They currently contradict: at ~0.92 KB/entry the 40-entry cap implies ~37 KB against a 25 KB ceiling, so size really permits ~27 entries and the entry cap is unreachable — reported on every run. Gaps in the id sequence are NOT findings (a gap is an id reserved by an unmerged branch).
