# Catches — what the independent gate found that in-lane review missed

One line per BLOCK on production-adjacent code. This file sharpens the reviewer brief; a catch
with no record teaches nothing. Format: date · PR · defect class · why in-lane missed it.

- 2026-09-13 · #710 (F38 driver at-door money) · **seam** — two halves of a computed amount fed
  from differently-filtered line sets (`deliveredSubtotal` from `shortPickLines`,
  `deliveredCategoryTax` from raw `o.lineItems`; absent line defaulted to fully delivered →
  cancelled/already-delivered regulated lines added full excise; driver over-collects cash) ·
  survived **three** in-lane Opus rounds because each file was correct in isolation; only a
  reviewer with no stake in the design read the composition. → brief item H (seams).
- 2026-09-13 · #711 (F27 estimates) · **hygiene** — 1,012 lines of engine scratch committed at
  the repo root; 19/21 commits authored by a test identity from a repo-level `.git/config`
  override (poisoned every worktree, incl. the lead's) · nobody in-lane looks at authorship or
  the root listing; engines write to cwd. → hygiene pre-check, step 1.
- 2026-09-13 · #711 · **weakened assertion** — exact `toHaveBeenCalledWith` on the `where`
  key-set relaxed to nested `objectContaining`; the replacement parity test asserted the key
  sets matched each other, not what they were · the loosening was unnecessary and invisible
  once the file was green. → brief item A, always first.
- 2026-09-13 · #711 · **structural test** — the restored PIN-B70 test stubbed `updateMany` to
  `{count:1}` unconditionally, asserting the exclusion list rather than the `DECLINED →
  ACCEPTED` transition it existed to protect · a green test that does not exercise the
  invariant reads as coverage. → brief item B: "not just that a constant contains a value".
- 2026-09-13 · PR #718 (Phase 0 schema) · **image-only build break**: a non-spec `apps/api/src` file imported repo-root `scripts/lib/*.cjs`, which the API Dockerfile never copies; host `tsc` and CI were green, only an image build fails (L-113 class). In-lane review missed it because it verified types on the host checkout. Brief question to keep: *does any non-spec file under apps/*/src import from outside its workspace or `packages/`?* Also caught: DTO `@IsEnum` widened ahead of the code that handles the new values (enum widening is a validation-surface change).
- 2026-09-13 · PR #722 (B323 tenant sweep) · **silent-drop behind a HAVING filter**: adding `tenantId` to a groupBy split one customer's rows into per-tenant groups, and the pre-existing `having count > 1` filtered the singletons out BEFORE the new null-tenant guard could warn — the guard looked complete but a whole class of rows became invisible. Brief question to keep: *when a grouping key is added, which pre-existing filters now run on the new (smaller) groups, and what do they hide?* Also: telemetry fields whose meaning changed with the grouping (`customers` = pairs, not customers).
- 2026-09-14 · PR #723 (#719 bookkeeping) · **fabricated proof tokens**: a Sonnet bookkeeping worker ran `prove B311..B315 --proof "REG-B31x …"` without a single test on master carrying those titles (the lane had titled them "B311: …"); the CLI accepts any string containing the token, only CI's campaign-check would have refused. Caught by the cheap Sonnet second read on a docs PR (question 2: do the cited tokens exist?). Brief rule from here: a bookkeeping worker pastes the proof token FROM a grep hit of the test title, and reports the file:line; "no hit" means no prove.
- 2026-09-14 · PR #725 (B294 tax rate on invoice lines) · **a fix that activates a dormant reader**: storing a real value where 0 had always been stored changed the meaning of every OTHER reader of that column (tobacco/excise "tax collected" reports now mix 0-rate pre-fix rows with real post-fix rows inside one period — a regulatory L-119 split). Also: forward-only fixes on stored columns need a stated backfill decision; a sibling path (estimate→invoice) with the identical hardcoded 0 was documented but not fixed. Brief questions to keep: *who else reads this column, and what did the old constant value mean to them?* and *is the fix forward-only — say so and file the backfill.*
- 2026-09-14 · PR #726 (B283 stock on promote) · **two-transaction fix for a one-transaction invariant**: the new decrement was correct but ran in its own transaction AFTER the status write committed, so a failure between them recreated the bug in a narrower window; the sibling create() does both in one tx. Brief question to keep: *is every state write and its compensating side effect (stock, ledger, wallet) inside ONE transaction, in the same order the sibling path uses?* Also: new transaction call sites must copy the isolation/timeout options the sibling branch already carries.
- 2026-09-14 · PR #730 (W1 billing wave) · **consent seam, second instance**: the in-lane round caught the admin downgrade revoking a tenant's cancellation; the independent pass found the admin REACTIVATION doing the same to a tenant-chosen downgrade schedule, unrecorded — the class survives the first fix because each admin write is reviewed alone. Also: a branch designed to be repeat-safe was not, because the provider returns a DIFFERENT error code on repeat (Stripe invalid_request_error, not resource_missing). Brief questions to keep: *list every admin/cron/webhook write to a tenant-chosen field and ask who consented*; *for any idempotent provider call, name the exact error the provider returns on repeat and test that code.*
- 2026-09-14 · PR #732 (B349 OAuth state HMAC) · **tests that never isolate the check they are named for**: all four REG cases still passed with the MAC verification deleted, because a second guard (nonce content binding) rejected the same inputs first — coverage of the invariant, not of the mechanism. Also: fail-closed on a missing secret lived only in main.ts assertSecrets, so any other entrypoint would sign with an empty key. Brief questions to keep: *for each new security check, which test fails if ONLY that check is removed?* and *does the module itself fail closed without the secret, or only the bootstrap?*
- 2026-09-14 · PR #738 (Phase 0 T4–T6) · **optional parameter with zero producers**: device info was threaded through five signatures as an optional argument, but only one of the two OAuth entry points passed it — the tenant path kept 'Unknown device' while the commit claimed the feature; an optional parameter hides a missing caller. Also: a doc comment asserted a drift 'never happens again' while a second hardcoded value still existed. Brief questions to keep: *for every new optional parameter, list every caller and which ones actually pass it*; *does any comment describe a state the diff does not yet reach?*
- 2026-09-14 · Phase 0 T9–T11 branch · **a reconciliation script that INVENTS rows**: 'backfill missing subscriptions' created a paid TenantSubscription for every subscription-less production tenant — including the free pilots the owner had just ruled must be $0 MRR — so the dark script's --apply would have manufactured revenue. Also: a field removed from an API response before its web consumer was updated ($NaN money card, tsc blind across web/api); a null-priced plan re-flagged on every run (non-idempotent event spam); the only test of a still-live pricing helper deleted as 'legacy'. Brief questions to keep: *does any backfill CREATE rows rather than fill fields, and who does it create them for?*; *which consumers read each removed response field?*; *is every run of the script a no-op on its own output?*
- 2026-09-14 · PR #741 (derived metadata tooling) · **gate treats 'cannot determine' as 'violated'**: a new ancestry check returned the same verdict for exit 128 (object absent — every shallow PR checkout) as for exit 1 (genuinely not an ancestor), turning CI red on every PR; also an env-var override (`LESSONS_ROOT`) added for a self-test would have let any exported var silently redirect a real verify and its write. Brief questions to keep: *for every new gate, what does it do when it CANNOT decide (shallow clone, missing object, tool absent) — warn, never fail?*; *is every test-only override double-gated and loud?*

- **#743 round 2 (2026-09-14) — a CI fix that fails on the CI it targets.** The db spec was made to self-provision its plan catalog for CI's fresh DB, but the synthetic `version` was derived from `Date.now()` (~1.8e12) into a Postgres int4 column — the create would throw in `beforeAll` on exactly the fresh-DB job the fix existed for; locally the seeded catalog masked it. Catch class: **when a fix targets an environment the author cannot run, the reviewer traces the fixed path against that environment's schema/limits, not the author's** (int ranges, missing seeds, absent env vars). Companion: rows pushed into a list after the list was printed → invisible outcome.

- **#743 gate (2026-09-14) — parallel db suites share one database; a platform-wide `--apply` in one spec rewrites another's fixtures.** `backfill-tenant-class.db.spec.ts` ran its script unscoped (whole-table reclassify + whole-table restore from its own start snapshot); the reconciliation spec's PRODUCTION `qa-*` fixtures were flipped to TEST mid-run → "Applied 0", snapshot null, 0 events; passed 2/2 when re-run alone or with different worker timing ("flake"). Catch class: **any spec that spawns a script with a global write must scope the script to its fixtures (`--slug-prefix`); a "flake" whose failing suite overlaps a sibling that writes globally is not a flake.** Reviewer question for every db spec: what else in the same jest run can see this suite's rows?
