## Objective

Rebuild the buyer portal shop (`/buyer/portal/[seller]/shop`) into the Catalogue v2 experience per `docs/design-package/project/unified/buyer-shop.html`: a category rail with per-category product counts and smart collections (Your usuals · Favorites · New · Deals), regulated categories shown locked, rich product tiles (multi-image 4:5 focal dot-pager, struck promo price with exact cent parity to the cart, live stock-state text, deal/new/behavioral chips, inline qty stepper), name/SKU/barcode search with a suggestion dropdown, and a "Best for you" sort driven by the buyer's replenishment frequency. API changes are strictly additive (new fields on existing catalog rows + one new read endpoint + one new query param). **No Prisma migration is needed** — every column used (`Product.isNew`, `isDeal`, `isFeatured`, `currentStock`, `lowStockThreshold`, `imageKeys`, `trackedCategoryId`) already exists.

## Constraints & conventions

- **Money math ONLY through `pricing.ts` helpers.** The tile's struck promo price must equal the cart's for the same product+qty **to the cent**. The cart (`apps/web/app/buyer/portal/[seller]/cart/page.tsx` lines 79–131) derives per line: base = catalog `buyerPrice` (the buyer's tier/effective price, resolved server-side) → `normalizeBoxesPieces(...)` for `qtyPieces` → `applyBestPromotion(base, promoRules, { productId, category, qtyPieces })` from `@/lib/pricing`. The tile MUST use the identical derivation (exact code given in WP5). Never add a second promo evaluator, never compute a promo server-side for the tile (that would create a second evaluation path that can drift from the cart).
- **Do NOT touch** `apps/web/lib/pricing.ts`, `apps/api/src/common/pricing.ts`, or `apps/mobile/lib/pricing.ts` — no pricing-logic change is required (the triple mirror stays byte-identical).
- **Regulated gate must not leak.** `RegulatedVisibilityService.computeGate(customerId)` (`apps/api/src/buyer/regulated-visibility.service.ts`) returns `{ hiddenIds: Set<string>, locked: [{id,name,status}] }`. `BuyerCatalogService.getCatalog` already excludes hidden `trackedCategoryId`s at query level and returns `hiddenCategories`. Every NEW read path added by this plan (counts endpoint, collection filters) must apply the same exclusion. Locked categories get a rail affordance + info panel only — never product data.
- **Buyer WEB only.** `apps/mobile` is out of scope (P5-16). Also out of scope (separate increments): Notify-me button (P5-03), the "Running low" strip (P5-07), the "next delivery Tuesday / order by 8 PM" subtitle (P5-06 delivery calendar), and "Out — back ~date" restock estimates (no data source exists).
- **No new dependencies.** Web tests are Playwright only (no web Jest — do not create `*.test.tsx` in apps/web). API tests are Jest (`apps/api/src/**/*.spec.ts`); new API service logic gets spec coverage (WP3).
- API additions must be **backward compatible**: existing response shapes only GAIN fields; `GET /buyer/products/categories` (returns `string[]`) is kept unchanged (mobile uses it). New web `BuyerProduct` fields are declared **optional** with runtime fallbacks so the page tolerates an older API.
- **Nest route-ordering trap:** static routes must be declared before `@Get("products/:id")` in `buyer.controller.ts` (same trap as `products/categories`, repo issue #194). Put the new `products/counts` route right next to the existing `products/categories` route.
- Preserve existing behaviors: buyer cart hook contract (`apps/web/lib/buyer-cart.ts` — `addItem/removeItem/updateQty/clearCart/getItemQty/itemCount/totalQty`), favorites hooks, the sticky cart bar, pagination, the grid/list view toggle, the W7b `LockedCategoriesTile` banner, and add-to-cart defaults (boxed products add 1 box = `unitsPerBox` pieces with `boxes:1, pieces:0`).
- Existing Playwright suite (`apps/web/e2e/04-buyer-portal.spec.ts`) does not exercise the shop page — no e2e updates required.
- The API `BuyerCatalogService` constructor changes (two new injections) — the existing spec `buyer-catalog.service.spec.ts` must be updated in the same change-set or `npx jest buyer-catalog` fails to compile (WP3).

**(3) Deals predicate — one shared private helper (used by both the collection filter and the counts endpoint so they cannot drift):**

```ts
  /**
   * Where-fragment matching every product that would surface as a deal: the
   * isDeal merch flag OR coverage by an active promotion's scope. An ALL-scope
   * promo makes the whole catalog a deal ({} matches everything). QTY_BREAK
   * promos count as deals even though their struck price only appears at the
   * qty threshold (the tile shows the rule as a chip).
   */
  private dealsWhere(
    promos: Array<{ scope: string; category: string | null; productIds: string[] }>,
  ): Record<string, unknown> {
    const or: Record<string, unknown>[] = [{ isDeal: true }];
    for (const p of promos) {
      if (p.scope === "ALL") return {};
      if (p.scope === "CATEGORY" && p.category) or.push({ category: p.category });
      if (p.scope === "PRODUCTS" && p.productIds.length > 0)
        or.push({ id: { in: p.productIds } });
    }
    return { OR: or };
  }
```

**(7) Counts endpoint — new service method:**

```ts
  /**
   * Category-rail data: total + per-category product counts + smart-collection
   * counts + the locked regulated categories. Every count applies the W7
   * visibility gate so a locked category's products are never countable.
   */
  async getCatalogCounts(customerId: string, buyerAccountId: string) {
    const { hiddenIds, locked } = await this.visibility.computeGate(customerId);
    const baseWhere: Record<string, unknown> = { isActive: true };
    if (hiddenIds.size > 0) baseWhere.trackedCategoryId = { notIn: [...hiddenIds] };

    const [total, byCategory, newCount, favRows, estimates, promos] = await Promise.all([
      this.prisma.forTenant().product.count({ where: baseWhere }),
      this.prisma.forTenant().product.groupBy({
        by: ["category"],
        where: { ...baseWhere, category: { not: null } },
        _count: { _all: true },
      }),
      this.prisma.forTenant().product.count({ where: { ...baseWhere, isNew: true } }),
      this.prisma.forTenant().buyerFavorite.findMany({
        where: { buyerAccountId, customerId },
        select: { productId: true },
      }),
      this.replenishment.estimates(customerId),
      this.promotions.activeForCatalog(),
    ]);

    const usualIds = estimates.filter((e) => e.orderCount >= 2).map((e) => e.productId);
    const favIds = favRows.map((f) => f.productId);
    const [usuals, favorites, deals] = await Promise.all([
      usualIds.length > 0
        ? this.prisma.forTenant().product.count({ where: { ...baseWhere, id: { in: usualIds } } })
        : Promise.resolve(0),
      favIds.length > 0
        ? this.prisma.forTenant().product.count({ where: { ...baseWhere, id: { in: favIds } } })
        : Promise.resolve(0),
      this.prisma
        .forTenant()
        .product.count({ where: { AND: [baseWhere, this.dealsWhere(promos)] } }),
    ]);

    return {
      total,
      categories: (byCategory as Array<{ category: string | null; _count: { _all: number } }>)
        .filter((c) => c.category)
        .map((c) => ({ name: c.category as string, count: c._count._all }))
        .sort((a, b) => a.name.localeCompare(b.name)),
      collections: { usuals, favorites, new: newCount, deals },
      lockedCategories: locked,
    };
  }
```

```ts
import type { BuyerProduct } from "@/lib/api/buyer";

/**
 * Tile promo/struck price. MUST equal the cart's number for the same
 * product+qty TO THE CENT — this mirrors cart/page.tsx `pricedLines` exactly:
 *   base      = catalog `buyerPrice` (tier/effective price, server-resolved)
 *   qtyPieces = normalizeBoxesPieces(cart line when in cart, else the default

 * `rules` must come from `toPromotionRules(useBuyerPromotions().data)`.
 * result.unitPrice = net selling-unit price; result.originalPrice = struck
 * pre-promo price (null => no strikethrough).
 */
export function deriveTilePrice(
  product: Pick<BuyerProduct, "id" | "buyerPrice" | "category" | "unitsPerBox">,
  promoRules: PromotionRule[],
  cartItem: CartItem | undefined,
): PromoResult {
  const unitsPerBox = cartItem?.unitsPerBox ?? product.unitsPerBox ?? null;
  const qtyPieces = normalizeBoxesPieces({
    boxes: cartItem?.boxes ?? null,
    pieces: cartItem?.pieces ?? null,
    qty: cartItem?.qty ?? (product.unitsPerBox ? product.unitsPerBox : 1),
    unitsPerBox,
  }).qty;
  return applyBestPromotion(product.buyerPrice, promoRules, {
    productId: product.id,
    category: product.category ?? null,
    qtyPieces,
  });
}
```

## Acceptance criteria

1. **Rail counts:** `GET /api/v1/buyer/products/counts` returns `{ total, categories: [{name, count}], collections: { usuals, favorites, new, deals }, lockedCategories }`; the rail renders All + Your usuals + Favorites + New this month + Deals + one row per category with its count; the sum of category counts <= total (uncategorized products count toward total only).
2. **Gate never leaks:** with a tenant that has a `requiresLicense` tracked category and an unverified buyer — (a) no product of that category appears in `GET /buyer/products` for ANY search/collection/sort/page combination, (b) that category's products are excluded from every number in `/buyer/products/counts`, (c) the category appears in `lockedCategories`/rail as locked with a lock icon and no count, (d) clicking it shows the locked panel with a link to `/buyer/portal/[seller]/licenses` and issues no product request, (e) the `LockedCategoriesTile` banner still renders above the grid.
3. **Smart collections filter server-side:** selecting Your usuals / Favorites / New / Deals issues `GET /buyer/products?...&collection=<x>` and the returned `meta.total` matches the rail count for that collection (same gate, same predicate — deals uses the one shared `dealsWhere`).
4. **Tile struck price == cart struck price for the same product+qty (cent parity):** for a product covered by an active PERCENT or FIXED promo, the tile shows net + struck original; add it to the cart and open the cart page — net, struck original, and implied savings match the tile **to the cent**. Both surfaces provably share `toPromotionRules` (cart line 83 memo now calls it) and evaluate via the same `applyBestPromotion` with base = the same catalog `buyerPrice`.
5. **QTY_BREAK parity:** for a qty-break promo (`minQty` pieces), a tile not in cart (default qty = 1 box below threshold) shows NO struck price; once the cart quantity for that product reaches >= `minQty` pieces, the tile (reading the cart line qty) and the cart both show the identical struck/net pair.
6. **Stock-state text:** tiles show exactly one of "In stock" (green) / "Only N left" (amber, N = integer >= 1, only when the API sent `stockStatus: "LOW"`) / "Out of stock" (red, Add disabled). `stockLeft` is null in the API response whenever status is not LOW.
7. **Dot pager:** a product with >= 2 images renders a 4:5 image with one dot per image (max 4), clicking a dot or the image switches the rendered image, and each image uses `object-position` from `objectPositionForUrl` (focal-aware). A product with 0–1 images renders no dots.
8. **Chips:** deal tiles show "Deal" (with -X% when a promo strike is active), `isNew` products show "New", a repeat-ordered product shows a behavioral label derived from replenishment (`"You order weekly"` for cadence 5–9d, or `"Bought Nx"`), and only one top-left flag renders (priority Deal > New > Running low > Featured).

## Risks & rollback

1. **Pricing cent-parity drift (top risk).** The tile and cart evaluate promos independently; any divergence in base price, rule mapping, or qtyPieces produces a tile price that differs from what checkout bills. Mitigations baked in: both read `buyerPrice` from the same `/buyer/products` endpoint; both map rules via the single `toPromotionRules`; both call the same `applyBestPromotion`; the tile reads the LIVE cart line qty so QTY_BREAK states agree; `deriveTilePrice` carries a MUST-match-cart doc comment. Reviewer: diff `deriveTilePrice` against `cart/page.tsx pricedLines` field-by-field (base, unitsPerBox precedence `cartItem ?? product`, boxes/pieces/qty passed to `normalizeBoxesPieces`).
2. **Regulated-gate leak.** New read surfaces (counts, collections, imageUrls) could bypass the W7 gate. Mitigations: counts derive every number from `baseWhere` carrying `trackedCategoryId notIn hidden`; collection filters are extra ANDs on top of the existing `excludeTrackedCategoryIds` exclusion (never a replacement); the locked rail entry renders from `computeGate().locked` metadata only. Reviewer: verify no new Prisma query in `buyer-catalog.service.ts` misses the exclusion, and that `GET /buyer/replenishment` data is only used to ANNOTATE products already returned by the gated catalog (the estimates list itself is a pre-existing P5-05 surface).
3. **Constructor change breaks existing specs/module wiring.** `BuyerCatalogService` gains two injections; `buyer.module.ts` already provides `ReplenishmentService` and imports `PromotionsModule`, so no module edit is needed — but the spec module (WP3) MUST add the two mock providers or `jest buyer-catalog` fails to compile.
4. **`sort=best` fetch-all cost.** Mirrors the existing price-sort pattern (limit=0, hard-capped at 10,000 rows in `products.service.findAll`) and additionally presigns up to 4 image URLs per row. Presigning is local HMAC (no network), but a multi-thousand-product tenant pays CPU per request. Acceptable for v1; if it shows, cap `imageUrls` presigning to the current page only (follow-up).
5. **Route-order regression.** `products/counts` declared after `products/:id` would 404 as a product lookup. The plan pins its position next to `products/categories`; reviewer should confirm declaration order in `buyer.controller.ts`.
6. **Older-API tolerance.** If web deploys before API, new fields are absent — web types are optional and the tile falls back (`thumbnailUrl` single image, "In stock" default, no chips). No crash path.
7. **Rollback:** every change is additive and confined to the files listed; revert the branch (`git revert` the merge or redeploy master) restores shop v1 — no migration, no data shape change, nothing to unwind in the DB.
