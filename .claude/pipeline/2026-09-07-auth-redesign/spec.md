## Lifecycle / states sweep (all inherited, must remain)

Loading (`Loader2` spinners, disabled submit), inline zod errors, API error banner, 429 countdown
(`/login`), buyer/operator presence banners with their exact copy and links, availability
spinner/check/X (`/signup`), sent state (`Check your inbox` + `If that address is registered…`),
invalid/missing token (`invalid or incomplete`, link `Request a new reset link`), done states, no-token
verify, verified, merge loading/success/error, invite loading/invalid/accepted, unauthorized
(`/buyer/change-password` redirects to `/buyer/login`). Concurrency, offline, too-much-data: not applicable
to these forms.

## Non-goals

Normalising hand-rolled inputs (signup, buyer register, invite) onto the shared primitives (a11y gaps stay
as today — residual row); deduplicating the two inline Google sign-in implementations; the buyer manifest
`themeColor`; the platform-admin surfaces (`/admin-login`, `(auth)/admin`, `(auth)/platform`,
`auth/callback`); the session-expiry re-auth dialog; dark mode; any middleware/proxy or route change
(`/login` stays outside `MARKETING_AUTH_PATHS`); copy changes to labels, buttons or links; changing what
the buyer portal itself looks like after sign-in.

## Deploy day / entitlement

Pure UI; no data, no migration, no gate, no env var. Rollback = revert the PR. Phones keep being proxied to
the mobile-web build on `/login`, so the mobile app's users never see these pages.
