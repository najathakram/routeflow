## What "removed" means (applies to every test)

`CustomersService.deleteCustomer`'s soft branch (`customers.service.ts` ~2039-2049) writes only
`Customer.deletedAt = now` and `User.status = INACTIVE`. `restoreCustomer` (~1965-1984) writes `deletedAt = null`. So
"removed" is `customer.deletedAt !== null` and "restored" is `customer.deletedAt === null`. The fix is stateless (a filter
or check on `deletedAt`), so each restore pin is the same fixture with `deletedAt` set back to `null`.

## Why the fakes honor `where` (L-081)

Three of the five fixes are `where`-clause filters (both crons, the guard, getSellers). A mock that injects a fixed result
(`findMany.mockResolvedValue([...])`) cannot see a where-only fix, so the REG test would stay red after a correct fix (L-081).
Each new test therefore stubs the one Prisma read with `mockImplementation` over a two-row fixture and applies the `where`
the service actually sends, through the small strict evaluator `matchesWhere` (exact code in build-plan.md, "Shared test
code"). It throws on filter shapes it does not model, so a differently shaped fix fails loudly rather than passing
vacuously. `InvoicesService.create()` is fixed by a row check (`customer.deletedAt` on the row it just read), so its
tests use a plain `mockResolvedValue` fixture.
