# Test plan — Registry guards (split from registry-views: R9 `sync --check`, R10 `move --tier`)

Every T# is a NEW case appended at the END of `cmds["self-test"]` in `scripts/campaign/bugs.mjs` (the registry's own harness, ~lines 2827–6831): `check(name, got, want)` JSON-compares and counts failures; fixtures are built with `mkdtempSync(join(tmpdir(), "bugs-self-test-"))`, `process.env.BUGS_ROOT = tmp` (path helpers are lazy getters), every env var saved and restored in `finally`, `rmSync(tmp, { recursive: true, force: true })`. **Every new assertion drives the REAL command through `runCli([...args], root)` (child process → `{ code, out }`)** — never an in-process `cmds.x()` call for these cases, because `fail()` exits the process and the red gate must see assertion failures (`  FAIL name / got / want`), not a crash. Read the existing `render` case (~2998–3040) and any `runCli` case for the idiom. The red-gate command is `node scripts/campaign/bugs.mjs self-test` (expect: exit 1 with the new cases FAILING on their own expected values while the existing 265 checks stay green).

Bugs are created with the REAL command: `runCli(["file", "Fixture", "--location", "apps/api/src/x.ts", "--severity", "high", "--batch", "F05", "--tier", "T1"], root)` (ids B1, B2, … in creation order). A non-queued state is set by rewriting the shard line's `"state"` in node (read `<root>/status/F05.jsonl`, `JSON.parse` each line, set `state`, write back with `\n`), then `runCli(["sync", "--quiet"], root)` mirrors it.

## Red-gate contract
