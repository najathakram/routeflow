## Binding rules (from CLAUDE.md, blueprint.json, DECIDE-27, the 2026-09-06 evaluation)

- No Plane uuids, keys or slugs in tracked files. Projects resolve by identifier (`BUGS`, `ROAD`, …), states/labels/types by name, at runtime. Ops files with identifiers (`ROAD-15`) are fine; uuids are not.
- Registry = proof. Plane never changes a registry state. The only Plane → registry path is intake (R6).
- Never delete or archive anything in Plane from the sync (plane-apply may archive an item the ops file names explicitly).
- Every outbound string (name, description_html, comment_html, link url) passes the denylist (R2). Never print matched text.
- `PLANE_API_KEY` from env only; never printed, never logged, never written. Auth header `X-API-Key` (REST). Base `PLANE_BASE_URL` (default `https://api.plane.so`), slug `PLANE_WORKSPACE_SLUG` (default `routeflow`) — the v1 conventions.
- Rate limit ≤ 50 req/min via the shared client; retries on 429/5xx honour `X-RateLimit-Reset` (v1 behaviour kept).
- Nothing here blocks a turn: Gate 5 stays non-blocking; every script exits 0 when the key is missing (`<tool>: skipped (no PLANE_API_KEY)`), except `plane-apply`, whose whole purpose is to write (exit 2 when the key is missing).
- No PQL (may be Pro-gated on the API); plain list endpoints + client-side filters only. No custom properties (per-item call cost).

## Lifecycle sweep (core object = one BUGS work item mirrored from a registry row)

create (sync, adoption) · read (triage, check) · list/filter (triage) · edit (sync patches state/priority/name/description diffs only) · delete — never · undo — adoption reversible by PATCH `external_id: null` (documented, not scripted) · permissions — one seat (`ClaudeLead`), key machine-bound · audit — write ledger + Plane activity · notification — comment-on-close · export — n/a · states: empty registry (0 diffs) · no key (skipped) · partial Plane page (paginate) · network error (exit 0, `partial`) · rate limited (sleep to reset) · concurrent run (ledger append is atomic per line; the state cache is rewritten whole — last writer wins, safe because entries only ever accumulate) · too much data (`--max-writes` defers) · stale cache (falls back to listing comments).

## Non-goals

Webhooks (no addressable receiver; 4xx = permanent drop). Plane → registry state changes. Custom properties. PQL. Project Updates / Initiatives (features off). Cycle/module automation for ROAD (manual via plane-apply). Any change to `bugs.mjs` semantics. Global `~/.claude` command edits (done outside this PR by the Lead).

## Deploy-day

First run after merge is a bulk: ≈ 160 adoptions + 122 creates + ≤ 4 comments/links ≈ 290 writes ≈ 6 min under the rate limiter → run `npm run plane:sync -- --max-writes 400` once, with the owner watching; Gate 5's 25-write cap keeps hooks from doing it by accident. No prod data, no migration. Rollback: revert the PR; Plane keeps the stamped `external_id`s (harmless, and the next run reuses them).
