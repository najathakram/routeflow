# bugs.mjs self-test · pid-reuse fixture flake on Linux runners — ruling (Fable, 2026-09-06)

Evidence: `reader.md` (CI run 34019219777 log; fixture source lines 5756–5854; lock primitives). Verdict:
**not timing jitter — a value collision.** `bootStamp() = Date.now() − os.uptime()*1000` with
`BOOT_STAMP_SLOP_MS = 5000`; the pid-reuse fixture forges `owner.bootAt = Date.now() − LOCK_ABANDON_MS*10`
(20 minutes ago). On a runner whose OS uptime is ≈ 20 minutes when the self-test runs (a cold `npm ci` +
turbo verify takes about that long), `|forged − real| ≤ 5 s`, the impostor pid (a live child) is judged the
legitimate holder, the waiter spins its full `LOCK_SPIN_MS` and gives up (exit 1) — checks (2)(3)(4) are
consequences of that one give-up because the fixtures share `lockDir` state. Windows dev boxes have days of
uptime, so the collision never shows there. The re-run was green because its uptime differed.
