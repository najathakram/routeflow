## 1. Strategy for this change

New surface (a CRM connector: schema, an external API client, a polling/matching pipeline, a
settings tab) built test-first against hand-built module skeletons. Money is not touched; dates
(cutoff, backoff scheduling) and permissions (tenant scoping, add-on gate, JWT/role guards) are,
so those get concrete example-based assertions rather than integration wiring, per the ruling's
anti-vacuity design (everything external — Prisma, `fetch`, email, gateway, audit — is a
hand-built `jest.fn()` mock; nothing hits a real DB, HTTP endpoint, or socket).

| Level       | Used here? | Why / why not                                                                                                                                                                                           |
| ----------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| unit        | yes        | pure identity helpers, the GHL HTTP client, poll/match/write-back services, controller — all mockable at the module boundary                                                                            |
| property    | no         | dates/permissions are touched but the ruling authored concrete example-based oracles (specific timestamps, specific role/guard checks), not generator-based invariants; no `fast-check` usage specified |
| contract    | no         | GHL's wire shape is fixed and out of RouteFlow's control (§GHL in spec.md); the client's hand-written type guards are exercised by the same unit tests, not a separate contract suite                   |
| integration | no         | Prisma and `fetch` are mocked at the boundary in every package — a real DB/HTTP integration lane is out of scope this run (`local:validate` / the sandbox check script, R33, cover that manually)       |
| e2e         | no         | `uiVerify` is omitted this run (ruling §E) — the settings tab needs a live GHL location to reach most states; RTL covers the states instead                                                             |
| manual      | yes        | `apps/api/scripts/crm-gohighlevel-check.mjs` (R33) against a GHL sandbox; a browser pass against the pilot tenant before enabling the add-on                                                            |

**Rule applied:** prefer the lowest level that can fail for the right reason.

**Deliberately NOT tested, and why:**

- GHL's own API behavior (rate limits, exact response shapes beyond the fixed contract) — third-party, covered by the hand-written type guards + the sandbox check script (R33).
- Real Postgres unique-constraint enforcement for `CrmHandoff`'s `(tenantId, provider, opportunityId)` index — the `P2002` path is exercised via a mocked rejection (T18); the index itself is proven by the migration + `local:drift`, not Jest.
- Cron scheduling itself (`@LeaderCron` firing on `*/3 * * * *`) — `cron-lock.spec.ts` already covers `LeaderCron`'s locking mechanism; this plan tests `pollAll`/`pollTenant` as plain async functions.

**Risk driving depth:** HIGH-risk files per the ruling (`apps/api/src/crm/**`, the Prisma schema,
the addon-gate registry, the gateway) touch secrets (the PIT token), tenancy (customer matching
must never cross tenants), and external writes (creating RouteFlow customers, writing back to a
client's live GHL account) — a wrong match or a leaked token both fail visibly and expensively,
so every match branch, every terminal handoff status, and the token's non-exposure each get a
dedicated oracle rather than being folded into a broader test.

**Characterization tests needed first?** No — this is new surface, not a refactor.

## 2. Test packages (TP1–TP7)

_Authored before any implementation code; each package also creates the module files it imports
as skeletons._

**Skeleton rule (verbatim from the ruling, so suites load and every test fails on its own
value):** each test package also creates the module files it imports as _skeletons_ — exported
classes/functions with the agreed signatures whose bodies are `return undefined as never;` (no
logic, no TODO comments), and `apps/api/src/crm/crm.types.ts` with the plain-string unions
`CrmHandoffStatus`, `CrmConnectionStatus`, `CrmTriggerMode` (string literals, NOT
`@prisma/client` — those enums do not exist until WP1). Tests never import `@prisma/client` CRM
enums; Prisma access is through hand-built `jest.fn()` model mocks
(`{crmConnection:{findUnique,findMany,update,upsert}, crmHandoff:{findUnique,create,update,findMany,count}, customer:{findFirst},
user:{findFirst,findMany}, importExternalRef:{...}}`) passed where `PrismaService` is injected,
plus `forTenant: () => models`. HTTP is mocked with `global.fetch = jest.fn()` (restore in
`afterEach`).

### 3.1 Expanded cases

**T16 — ignoreCutoff exception**

- **Given:** the exact stale opportunity from T15 (would be skipped under the default cutoff).
- **When:** `pollTenant(tenantId, { ignoreCutoff: true })` is called (the path used by
  "Import existing", R23).
- **Then:** `gohighlevel-handoff.service`'s `handle` IS called for that opportunity.
- **Oracle:** spec R10's exception clause, worded exactly as "unless the poll was invoked with
  `ignoreCutoff=true`".
- **Fails today because:** skeleton `pollTenant` ignores its `opts` argument entirely (returns
  `undefined as never`).

**T19 — auth failure notifies once per transition**

- **Given:** `attentionNotifiedAt` is `null` on the connection; two active OPERATOR/TENANT_ADMIN
  users exist for the tenant; the GHL client throws `CrmAuthError` on the first call inside
  `pollTenant`.
- **When:** `pollTenant(tenantId)` runs twice in a row (simulating two cron ticks) without the
  connection being re-tested in between.
- **Then:** `EmailService.send` is called exactly ONCE across both invocations (guarded by
  `attentionNotifiedAt` being set after the first).
- **Oracle:** spec R12: "once per transition (`attentionNotifiedAt` null → set)".
- **Fails today because:** skeleton never calls `EmailService.send`.

**T31 — tag idempotency + notification/audit**

- **Given:** `listTags()` returns `[{name:"GoHighLevel", id:"tag-1"}]` (missing "Needs
  onboarding"); a no-match contact.
- **When:** `handle(connection, opportunity, opts)` runs the CREATED path.
- **Then:** `createTag` is called exactly once, for `"Needs onboarding"` only; `assignTag` is
  called for both tag ids; `ExternalRefService.record` is called once;
  `gateway.emitCrmHandoff` is called once with the exact payload shape; `audit.log` is called
  once with `action:"crm.handoff.created"`. A second scenario (LINKED path, both tags already
  exist) asserts `assignTag` is called only for `"GoHighLevel"`.
- **Oracle:** spec R18 (tag idempotency) + R24 (notification/audit), combined into one test per
  ruling §A's oracle for TP4.
- **Fails today because:** skeleton `handle` calls none of these collaborators.

**T37 — backoff formula at three points**

- **Given:** a fixed `now = new Date("2026-09-11T00:00:00Z")`.
- **When:** `nextAttemptAt(1, now)`, `nextAttemptAt(3, now)`, `nextAttemptAt(5, now)`.
- **Then:** results equal `now + 1min`, `now + 15min`, `now + 240min` — i.e. the backoff table
  `[1, 5, 15, 60, 240]` minutes indexed by `attempts` (1-based, capped at 5).
- **Oracle:** spec R20's literal minute table; independently computable without reading the
  implementation.
- **Fails today because:** skeleton `nextAttemptAt` returns `undefined as never`.
