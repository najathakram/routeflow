## Non-goals

Atlas (PR-5). The `prisma/schema/` folder split (PR-15). Any new migration (none is needed —
prod matches). Keeping a kill-switch. Touching anything under `apps/api/prisma/**`. Running
`migrate deploy`, `db push`, or `migrate reset` anywhere except the CI fresh service (existing
step). Any other worktree.

## Deploy day

No user-visible change. Prod schema already equals the datamodel, so the first boot without DDL
differs only by the absence of two no-op blocks. No backfill, no entitlement gate. After deploy the
rebuild routine for schema PRs runs `railway run --service postgres node
apps/api/scripts/schema-drift.mjs` and requires exit 0.

## Rollback

Revert the PR (the boot DDL code returns, still no-op). A future column gap is fixed by a real
migration through `prod-migrate.mjs`, never by boot DDL.

## Lesson L-052 (draft — refine with the run's own surprise, keep ≤ 1,000 bytes)

- **Symptom:** the documented boot-time DDL (`main.ts`) had an undocumented twin
  (`platform-config.service.ts` creating two tables and an index on every boot, ungated).
- **Root cause:** "retire the DDL" was scoped to the site the docs named, not to every raw-DDL
  call site.
- **Lesson:** retiring a runtime schema writer means grepping every `$executeRaw*` DDL site,
  proving the live DB already matches the datamodel (`migrate diff … --exit-code` → 0) before
  deleting, and deleting — a default-off flag leaves the contradiction in place.
- **Guard:** `apps/api/src/common/no-runtime-ddl.spec.ts` (static tripwire) + the drift gate in
  `db-migrations.yml` and `prod-migrate.mjs`.
