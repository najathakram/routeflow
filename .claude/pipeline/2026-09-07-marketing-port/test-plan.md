value before implementation (`R#` ↔ `T#`). Tokens in titles: `R-MKT` (pre-deploy unit/static rows that are RED before the

## Harness notes

- `apps/web` Jest is `jest-environment-jsdom` with RTL (`settings-users.test.tsx` precedent); static scans read files
  with `fs` relative to `apps/web`.
- **Test discovery**: `apps/web/jest.config.js` scopes `roots` to `app/`, `components/`, `lib/`, `hooks/`. A test file at
  the workspace root is NEVER collected — that is why the middleware spec lives at
  `apps/web/app/(marketing)/middleware.marketing.test.ts` and imports `../../middleware`.
- **`next/server` under Jest** touches the Fetch API globals (`Request`, `Response`, `Headers`) at import time, which the
  default jsdom environment does not define (`ReferenceError: Request is not defined`). The middleware spec therefore opens
  with a `/** @jest-environment node */` docblock. Verified: 10 assertion failures + 3 pins, no import-time error.
- `next/image` in RTL: the existing jest config maps `next/image`? If not, mock it to a plain `img` in the test file.
- `next/font/local` throws under Jest: the root layout is not rendered in any unit test; the brand component imports
  no font.
- Playwright: the `marketing` project has no `storageState` (signed-out) and `dependencies: []`; the mobile flow uses
  `devices["iPhone 13"]` inside the spec via `test.use`. Never run Playwright locally.
- Regression pins outside the red gate: CC-11…CC-15 in `05-cross-cutting.spec.ts` (untouched), and every `MKT-PIN` row —
  all of T7, the three T11 unchanged-path rows, and the T5 standing guards / size ceilings listed in the T5 row above.
