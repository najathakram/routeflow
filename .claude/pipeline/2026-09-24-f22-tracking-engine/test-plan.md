## 1. Strategy for this change

This is internal tooling: one existing renderer extended (`render.mjs`: stamps, `lag.json`,
`--status`, warnings), two new standalone CLIs (`from-git.mjs`, `publish.mjs`), and wiring
(package.json `verify`/scripts, a second `SessionStart` element, a husky `post-merge`, the PR
template, the README). Every surface is a terminal line, a file in a gitignored render dir, or a
Plane request. The proof is therefore: (a) **in-process unit checks** on the pure functions the
scripts export under the repo's own `main()` guard (`import.meta.url === pathToFileURL(process.argv[1]).href`,
`scripts/campaign/plane-sync.mjs:1247`) — LAG math, hashing, trailer parsing, verdicts, publish
plans, byte caps — with a pinned clock; (b) **spawned-child CLI checks** for exit codes, exact
output lines and "nothing written" contracts, against throwaway register dirs, a throwaway git
repo and the existing fake Plane server; (c) **static contract checks** over `package.json`,
`.claude/settings.json`, the hook file, the template and the README; and (d) two
**environment-gated live checks** (F-3) plus two **manual** checks the owner runs on the PC
(R15 hourly task, R16 local pull). Test runner: the repo's standalone `*.self-test.mjs`
convention — plain Node, `  ok  ` / `  FAIL` lines, `process.exit(failures ? 1 : 0)`; no Jest,
no `node:test`, no Vitest (CLAUDE.md do-not-introduce; `plane-docs.self-test.mjs` header).

| Level       | Used here?  | Why / why not                                                                                                                                                                                                    |
| ----------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| unit        | yes         | `computeLag`, `registersHash`, `statusReport`, `parseTrailers`, `probeVerdict`, `buildPublishPlan`, `truncateBody` are pure given a pinned `now` — they fail for exactly one reason each                         |
| property    | yes (table) | dates are touched (LAG is date-relative, UTC day boundary) — a hand-rolled table of boundary cases (§5), no `fast-check` (not in the repo: zero hits in `package.json`, `apps/api`, `packages/pricing`)          |
| contract    | yes         | `package.json` `verify`, `.claude/settings.json` hooks, `.husky/post-merge`, the PR template, the README — the wire shape IS the requirement (R1, R4, R9, R16, R18, R19)                                         |
| integration | yes         | every CLI runs as a real spawned child: exit codes, exact lines, zero-writes proofs, the request sequence against `plane-fake-server.mjs`, the git fixture repo                                                  |
| e2e         | no          | no browser, no UI surface                                                                                                                                                                                        |
| manual      | yes         | R15 (machine-local hourly task on the PC — per-machine state outside the repo) and R16's live pull; plus the env-gated live probe when the PC runs it (T20/T24 automate the assertion, a human supplies the key) |

**Rule applied:** lowest level that can fail for the right reason — pure functions in-process,
exit-code/line contracts by spawn, file shapes statically.

**Deliberately NOT tested, and why:**

- `plane-client.mjs`'s retry/rate-window/ledger internals — F-09's own self-tests own them
  (`plane-sync.self-test.mjs` T4/T11 family); F-22 only proves it _calls_ the client (ledger
  line count, request sequence).
- `plane-sync.mjs --if-digest-changed` and `plane-triage.mjs --brief` behaviour — F-09's; the
  composite proves invocation order, argv and exit propagation with **stub** children (T27).
- The rendered HTML's markup/CSS — unchanged from today's renderer beyond the footer clock; a11y
  of the pages is out of scope (spec §5).
- Claude Code's hook runtime semantics (whether two `SessionStart` elements run independently —
  D-A5) — cannot be exercised from a self-test; compensating control: the status command's own
  exit-0 / no-network contract (T6, T9) and the owner's first session after merge.
- Plane's real Pages payload shape — unknowable without the key (D-A1); T23 pins _this plan's_
  payload as the oracle so a correction from the live probe is a one-function, one-oracle edit.

**Risk driving depth:** LOW everywhere — no money, tenancy, auth, PII or app code. The three
things that could still hurt and therefore get negative tests: a rendered byte carrying a
denylisted token reaching Plane (T25), any tool committing/pushing or editing a judgement field
in the registers (T15, T28), and network or `gh` inside `verify`/hooks/status (T9, T16, T29,
T31). Depth is set by those, not by line count.

**Characterization tests needed first?** One: T1's "real registers → exit 0" and the exact
`validate()` error strings are today's behaviour of `render.mjs`, captured before the file is
extended so the extension is measured against it. Everything else is new surface.

## 11. Regression watch

- **Runs on every push (inside `npm run verify`):** `render.mjs --validate` and the four
  self-tests (T1–T19, T21–T23, T25–T33, T36) — all local, no network, budgeted (F-2); T20/T24
  print `skip` there by design.
- **Runs on demand / on the PC:** T20 and T24 with `ROADMAP_LIVE_PROBE=1` — once after merge
  (the manual step that retires D-A1), and whenever Plane's API changes. T34/T35 by hand.
- **How this regresses unnoticed in six months, and the check that catches it:** (a) someone
  "tidies" `.claude/settings.json` and drops the second element → T30; (b) a future script adds
  `roadmap:publish` to `verify` for convenience → T29; (c) the client's payload shape drifts
  (`description_html` renamed) → T21 request-body assertion; (d) a register gains a field the
  status line miscounts → T4's counts line on fixture A; (e) the hourly job silently dies on
  the PC → not a test: the next session's `Roadmap publish: STALE … last published <when>` line
  (spec §5 observability) and `runs.jsonl`.
- A green replay from a cache is not evidence: the self-tests are plain `node` invocations
  in a `&&` chain — nothing caches them; `verify-turbo.mjs`'s "executed" report covers the
  turbo-run tasks, which this change does not touch.
