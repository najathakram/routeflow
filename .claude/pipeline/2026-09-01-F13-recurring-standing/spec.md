## 1. Core capability, in one sentence (G2·Q1)

> A recurring invoice fires once per cycle and tells the operator when it did not; a standing
> order bills the customer the price they would pay at checkout; and both templates can be
> edited in place instead of deleted and rebuilt.

## 7. Deploy day (G2·Q7)

- **Existing users:** no visible change until a cycle runs. The first post-deploy midnight
  fires every MONTHLY template that is _due_ (`nextRunAt <= now`, exactly as today) **once
  more**, then advances it correctly — so the nightly spam ends with one final run; that run's
  invoice is one more candidate for the owner's duplicate review (D4). Template orders
  generated after deploy carry `priceType SPECIAL/PROMO/MANUAL` where applicable — the order
  page already renders those (they are the interactive path's values).
- **Existing data:** `lastRunStatus`/`lastError` are `null` on every row → no pill, date only.
  Old order lines keep `STANDARD`/list — the D4 report identifies them (R29).
- **Backfill:** none required. D4: report-only checks in `scripts/data-integrity-report.mjs`,
  run read-only on prod by the lead post-deploy (build plan close-out).
- **Migration:** none — F01's migration already added the columns; `schema.prisma` is
  unchanged by this batch (no `prisma generate` needed in the worktree — L-011).
- **Gates / entitlements:** none. No flag, plan or addon reads or writes are added.

## 8. Rollback (G2·Q9)

- **Kill switch:** none (no flag). Pausing a template (`DELETE :id`) stops its cron.
- **Code rollback:** safe to revert the squash commit. Old code ignores `lastRunStatus`/
  `lastError` and reads `priceType SPECIAL/PROMO` fine (existing enum values).
- **Data rollback:** nothing to reverse — outcome columns are informational; template orders
  priced by this change are correct prices.
- **Blast radius:** money — a wrong resolver input (tier, promo set, denomination) misprices
  every template order for every tenant; a wrong rollback condition could re-bill a cycle.
  Both are pinned by REG-B48 / REG-B106 tests with hand-derived oracles and mutation probes.
- **Detection:** `scripts/data-integrity-report.mjs` (`recurring-duplicate-fire`,
  `template-order-list-price-vs-tier`, `f13-gate-state`) read-only on prod; the deploy-signal
  e2e run (spec proposed 29) for the web surfaces.
