## 1. Strategy for this change

Five bug fixes across two API services, three web surfaces and one mobile line. The two
Criticals are pure server logic (a date function and a pricing path), so the proof lives in
jest unit specs with hand-derived oracles — the pricing tests run the REAL shared resolver
(`OrdersService.prototype.resolveBuyerLinePrice`, which uses no `this`) and the REAL
`computeLineSubtotal`, mocking only the database and the promotion/history loaders, so the
money assertions are arithmetic, not mirrors of a mock. The failure-state fix (B106) is proven
by call-shape and call-ORDER oracles on the Prisma mock. The web bugs (B09, B92) are
user-visible rendered behavior with no web unit runner (campaign decision D1), so they are
T2 Playwright specs that run only against the deployed build and ride in a work package, never
in the red gate. Two DTO specs use the repo's `ValidationPipe` harness precedent
(`apps/api/src/route-optimization/dto/apply-route-variant.dto.spec.ts`).

| Level       | Used?             | Why                                                                                                                                                                        |
| ----------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| unit        | yes               | `calcNextRunAt` (dates), `createOrderFromTemplate` (money), `generateInvoiceFromTemplate` (state writes), `update()` item replacement, DTO validation                      |
| property    | no — hand table   | the date invariant is covered by a 12-cycle chain (T6) and the clamp table (T2); `fast-check` is not in the repo and one chain is a stronger reviewer-readable oracle here |
| contract    | yes (DTO)         | T23/T24/T29/T30 assert the wire contract the web edit surfaces depend on                                                                                                   |
| integration | yes (mock-Prisma) | the claim/rollback/success writes and the transaction wrapping                                                                                                             |
| e2e         | yes (deployed)    | R22, R26, R27, R16-SUCCESS — the only oracle for rendered web behavior (D1)                                                                                                |
| manual      | no                | the FAILED-pill render is reviewed by lens, not manually verified — recorded in §3                                                                                         |

**Deliberately NOT tested:** `getTierPrice`, `applyBestPromotion`, `computeLineSubtotal`
internals (already pinned by `apps/api/src/common/pricing.spec.ts` and `orders.service.spec.ts`);
`ValidationPipe` itself; the `Pill` component; the cron's tenant-ALS loop (unchanged).

**Risk driving depth:** money (every template order for every tenant) and billing cadence
(a wrong month advance either re-spams or skips a month). Depth: hand-derived money values to
the cent, the BOGO free-unit table, a boxed line, and a 12-month chain.

**Characterization tests first?** Yes, three pins BEFORE the change lands, all outside the red
gate: T8 (WEEKLY/BIWEEKLY unchanged), T16's price/subtotal half (tier-1 list price unchanged)
and T2 (the dom-31 clamp, which already holds).
