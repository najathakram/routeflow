## Deploy-day / entitlement answer

- **No migration.** F01's `settlementNote`/`settlementVariance` columns are already applied to
  prod (`20260908000000_campaign_schema_foundation`); F05 only wires them.
- **Addon gates unchanged.** `RouteRunsController` is class-gated (`JwtAuthGuard` + `AddonGuard`
  `recurring_routes|order_delivery|developer_mode`) — the new settlement endpoint inherits it;
  at-door money stays behind `DriverPaymentsGuard` (`driver_payments` addon, grant path exists —
  the #475 trap is answered: no new entitlement key is introduced).
- **Client skew (the one real deploy-day risk):** clients run the mobile WEB bundle (B202), which
  updates with the deploy; an already-open pre-F05 tab that collected cash closes its run via
  notes-append + COMPLETED and will now hit R7's 400 (its note went to `notes`, not
  `settlementNote`). Accepted: the 400 message is actionable ("record the run settlement"), a
  reload gets the new bundle, and an operator can settle any run via the new endpoint. No
  notes-marker bridge — it would permanently weaken the gate for a minutes-long skew window.
- **Old idempotency-cached responses** lack `excess`/`advancePaymentId`; clients treat them as
  optional. Old clients not sending `productId` remain valid (field optional).

## Non-goals (fenced)

- `orders.service.ts` — F06/F07's lane. `invoices.service.ts` outside `:4491-4657` (the manual
  allocations flow, `updatePayment`, `reconcileOrderDeliveredInvoices` internals stay put).
- `getRunPackingList`'s fallback shape (different, narrower — not G7).
- The `payment.tsx:254` collected cap semantics (change-giving stays; only its basis is fixed).
- No persistence added to `runSettlementStore` — the server is the durable truth now; the store
  remains an ephemeral per-device echo by design.
- No `PATCH :id` DTO retrofit (shipped mobile builds still PATCH `notes` through it mid-skew).
- No web settlement WRITE UI; no driver-ownership fix for `updateRunStatus` (pre-existing gap,
  out of scope — do not replicate it in `settleRun`, which DOES check ownership).
- No new schema, no new addon keys, no pricing-mirror edits (P5 only consumes
  `computeLineSubtotal`).
