## Deploy-day / entitlement-trap answer

No new gate keys, no addon, no entitlement — nothing here can 403 a tenant on deploy day. Two
ordering constraints only: (1) the RLS migration applies before this PR's app deploy, after a
fresh backup and the R10 pre-flight; (2) F01's migration must already be applied (serial
migration flights). Rollback story: every behavior change is server-side guard logic — reverting
the PR restores prior behavior; the RLS migration is idempotent and, being a backstop behind
`tenantTransaction`, does not change what correct code sees.
